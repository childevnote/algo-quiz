# 입국심사

- 문제: [입국심사](https://school.programmers.co.kr/learn/courses/30/lessons/43238)
- 레벨: Lv.3
- 카테고리: 이분탐색
- 날짜: 2026-11-13

## 문제 핵심 요약

n명이 입국심사를 받는다. 심사관마다 한 명을 심사하는 데 걸리는 시간이 다르며, 한 심사대는 동시에 한 명만 심사할 수 있다. 비어 있는 심사대가 있으면 바로 심사받을 수도 있고, 더 빨리 끝나는 심사대를 기다렸다가 갈 수도 있다. 모든 사람이 심사를 마치는 데 걸리는 최소 시간을 구한다.

핵심 제한사항:

- 입국심사 대기 인원 n은 1명 이상 1,000,000,000명 이하이다.
- 심사관 한 명당 심사 시간은 1분 이상 1,000,000,000분 이하이다.
- 심사관은 1명 이상 100,000명 이하이다.

입출력 예:

| n | times | return |
| --- | --- | --- |
| 6 | [7, 10] | 28 |

입출력 예 설명:

- 7분이 되었을 때 첫 번째 심사대가 비어 3번째 사람이 심사를 받는다.
- 10분이 되었을 때 두 번째 심사대가 비어 4번째 사람이 심사를 받는다.
- 14분이 되었을 때 첫 번째 심사대가 비어 5번째 사람이 심사를 받는다.
- 20분이 되었을 때 두 번째 심사대가 비지만, 6번째 사람이 1분을 더 기다려 첫 번째 심사대에서 심사를 받으면 28분에 모든 심사가 끝난다.

## 문제 분석 및 핵심 로직

이 문제는 "최소 시간"을 직접 구하는 것이 아니라, "T분 안에 n명을 모두 심사할 수 있는가?"라는 판정 문제로 바꾸는 것이 핵심이다. T분이 주어지면 각 심사관이 그 시간 안에 처리할 수 있는 사람 수는 `T / 심사 시간`의 몫이다. 심사관마다 이 값을 구해 모두 더하면 T분 동안 심사할 수 있는 총인원이 나온다. 총인원이 n명 이상이면 T분으로 충분하고, n명보다 적으면 T분으로는 부족하다.

판정 결과는 단조성을 가진다. 어떤 T분으로 충분하다면, 그보다 긴 시간으로도 당연히 충분하다. 반대로 어떤 T분으로 부족하다면, 그보다 짧은 시간으로도 부족하다. "충분함"과 "부족함"의 경계가 하나만 존재하므로, 답이 될 수 있는 시간 구간에 이진 탐색을 적용할 수 있다. 답의 하한은 1분, 상한은 가장 느린 심사관 혼자 n명을 모두 심사하는 시간, 즉 `max(times) * n`분이다.

1. 답이 될 수 있는 구간 `[1, max(times) * n]`을 잡는다.
2. 구간 가운데 시간 `mid`에 대해, `mid`분 안에 심사할 수 있는 총인원을 계산한다. 심사관마다 `mid // 심사 시간`을 더하고, 합이 n에 도달하면 더 더하지 않고 멈춘다. 이 조기 종료는 큰 n에서 불필요한 덧셈을 줄인다.
3. 총인원이 n 이상이면 `mid`분으로 충분하므로 상한을 `mid`로 내린다. n보다 적으면 `mid`분으로는 부족하므로 하한을 `mid + 1`로 올린다.
4. 하한과 상한이 만나면 그 값이 모든 사람을 심사할 수 있는 최소 시간이다.

예제 `n=6, times=[7, 10]`을 확인하면, 28분 동안 첫 번째 심사관은 4명, 두 번째 심사관은 2명을 처리해 총 6명이 되고, 27분 동안은 3명과 2명으로 총 5명에 그치므로 답은 28이다.

## 개념별 심층 설명

### 1. 시뮬레이션으로 풀면 왜 안 되는가

초심자 방식은 심사관마다 "다음에 비는 시각"을 유지하며 사람을 한 명씩 배정하는 시뮬레이션이다. 매번 가장 빨리 비는 심사대를 찾아 다음 사람을 배정하고, 그 심사대의 다음 빈 시각을 갱신한다. 이 방식은 n이 작을 때는 직관적이고 정확하다. 그러나 n이 최대 10억 명까지 커지면 사람을 한 명씩 배정하는 횟수 자체가 10억 번이 되어 시간 안에 끝나지 않는다. 심사관이 10만 명이면 매번 가장 빨리 비는 심사대를 찾는 비용까지 더해진다.

이 문제에서 요구하는 것은 "누가 어느 심사대에 가는지"가 아니라 "모두 마치는 데 걸리는 최소 시간" 하나뿐이다. 배정 과정을 전부 흉내 낼 필요가 없다. 특정 시간 T가 주어졌을 때 "T분 안에 n명을 처리할 수 있는가"만 판단하면 되고, 이 판단은 심사관마다 나눗셈 한 번씩으로 끝나므로 심사관 수만큼의 연산이면 충분하다.

### 2. 판정 문제로 바꾸는 사고: "얼마나 걸리나"를 "T분이면 되나"로

최솟값을 직접 계산하기 어려울 때, 그 값이 어떤 조건을 만족하는지를 묻는 판정 문제로 바꾸는 것이 파라메트릭 서치의 출발점이다. 여기서는 답을 모른 채로 "T분 안에 n명을 심사할 수 있는가"를 묻는다. 이 질문에는 답이 있다. T분이 길수록 각 심사관이 처리하는 사람 수는 늘어나거나 그대로이므로, 심사할 수 있는 총인원은 T에 대해 단조 증가한다. 따라서 "충분하다"는 답이 나오는 T들의 집합은 어떤 경계값 이상에서만 나타나고, 그 경계값이 바로 구하려는 최소 시간이다.

단조성이 성립하는 이유는 각 심사관의 처리 인원 `T / 심사 시간`이 T가 커질수록 감소하지 않기 때문이다. 합 역시 감소하지 않으므로, 한 번 "충분하다"가 되면 더 긴 시간에서도 "충분하다"는 유지된다. 경계가 하나뿐이라는 확신이 서면, 그 경계를 찾는 데는 이진 탐색이 가장 빠르다.

### 3. 이진 탐색 구간과 오버플로: 상한과 자료형

상한은 가장 느린 심사관이 혼자 n명을 모두 처리하는 시간, `max(times) * n`이다. 가장 빠른 심사관이 도와주면 이 시간보다 빨리 끝나므로, 답은 반드시 이 상한 안에 들어간다. 하한은 1분이다. n이 10억, 심사 시간이 10억 분이면 상한은 10^18분이 된다. 이진 탐색은 구간을 절반씩 줄이므로 log2(10^18) ≈ 60번의 판정으로 끝나고, 판정 한 번은 심사관 수만큼의 나눗셈이므로 전체 연산량은 심사관 수의 60배 수준이다.

10^18이라는 수는 32비트 정수 범위(약 21억)를 훌쩍 넘는다. Java에서는 `max(times) * n`을 int로 계산하면 오버플로가 나므로 long으로 계산해야 하고, 판정에서 세는 인원수도 n이 최대 10억이라 int에 들어가지만 중간 합이 커질 수 있어 long을 쓰는 것이 안전하다. Python은 임의 정밀도 정수라 이 걱정이 없지만, Java에서는 이 문제의 상한과 누적 합을 long으로 두는 것이 풀이의 일부이다. 또한 판정 합이 n에 도달하면 바로 멈추는 조기 종료는, 합이 10^18 수준까지 커지는 것을 막아 오버플로 위험을 줄이는 역할도 한다.

## 최종 솔루션 코드

### Python

```python
def solution(n, times):
    # 1) 답의 범위를 잡는다: 최소 1분, 최대 (가장 느린 심사관) * n분
    lo, hi = 1, max(times) * n
    # 2) 이진 탐색: T분 안에 n명을 모두 심사할 수 있으면 hi를, 아니면 lo를 좁힌다
    while lo < hi:
        mid = (lo + hi) // 2
        # 3) T분 동안 각 심사관이 처리할 수 있는 사람 수의 합 (n에 도달하면 조기 종료)
        count = 0
        for t in times:
            count += mid // t
            if count >= n:
                break
        if count >= n:
            hi = mid
        else:
            lo = mid + 1
    return lo
```

### Java

```java
class Solution {
    public long solution(int n, int[] times) {
        // 1) 답의 범위를 잡는다: 최소 1분, 최대 (가장 느린 심사관) * n분
        long lo = 1;
        long hi = (long) max(times) * n;
        // 2) 이진 탐색: T분 안에 n명을 모두 심사할 수 있으면 hi를, 아니면 lo를 좁힌다
        while (lo < hi) {
            long mid = (lo + hi) / 2;
            // 3) T분 동안 각 심사관이 처리할 수 있는 사람 수의 합 (n에 도달하면 조기 종료)
            long count = 0;
            for (int t : times) {
                count += mid / t;
                if (count >= n) break;
            }
            if (count >= n) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private static int max(int[] times) {
        int m = times[0];
        for (int t : times) {
            if (t > m) m = t;
        }
        return m;
    }
}
```

## 성능 측정

로컬 실측 (2026-11-13):

- 예제 케이스 (`n=6, times=[7, 10]`): Python 0.011 ms, Java 0.094 ms.
- 스케일 케이스 (`n=1,000,000,000`, 심사관 100,000명, 심사 시간 1~1,000,000,000 무작위): Python 367.6 ms, 피크 메모리 14.4 MiB; Java 31.5 ms, 힙 사용 약 2 MiB. (Python과 Java는 난수 생성 방식이 달라 입력이 다르므로, 두 수치는 같은 입력에 대한 비교가 아니다.)

시간 복잡도: 이진 탐색 반복 횟수는 log2(max(times) * n) ≈ 최대 60회, 판정 한 번은 심사관 수만큼의 나눗셈이므로 O(len(times) * log(max(times) * n))이다. 심사관이 100,000명이면 약 600만 번의 나눗셈으로 끝난다.

공간 복잡도: 입력 외에 추가 배열을 쓰지 않으므로 O(1)이다.

## 요약

- "최소 시간"을 직접 구하지 않고 "T분 안에 n명을 심사할 수 있는가"라는 판정 문제로 바꾼다.
- 판정 결과가 단조성을 가지므로, 답의 구간에 이진 탐색(파라메트릭 서치)을 적용한다.
- 답의 상한은 `max(times) * n`, 판정은 심사관마다 `T / 심사 시간`을 더해 n과 비교한다.
- Java에서는 상한이 10^18까지 커지므로 long을 쓰고, 판정 합은 n에 도달하면 조기 종료한다.
