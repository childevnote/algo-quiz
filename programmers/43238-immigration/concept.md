# 개념 정리: 파라메트릭 서치 (이진 탐색으로 답 찾기)

## 1. 파라메트릭 서치란

파라메트릭 서치는 답을 직접 구하기 어려울 때, 답의 후보값을 변수로 두고 "이 값이면 조건을 만족하는가?"라는 판정 문제로 바꿔 푸는 방법이다. 판정 결과가 단조성을 가지면, 즉 어떤 경계값을 기준으로 한쪽에서는 항상 "예", 다른 쪽에서는 항상 "아니오"가 나오면, 그 경계를 이진 탐색으로 찾을 수 있다. 답을 직접 계산하는 대신 "되는지 안 되는지"를 반복해서 묻는 것이 핵심이다.

예를 들어, "길이 L인 막대를 최소 몇 개로 자를 수 있는가" 같은 문제에서 L을 직접 구하기보다, "L을 10으로 자르면 되나, 20으로 자르면 되나"를 묻는 식이다. L이 커질수록 조건을 만족하기 쉬워지므로, 만족하는 가장 작은 L이 답이 된다.

## 2. 단조성이 필요한 이유

이진 탐색은 "중간값보다 답이 크다/작다"를 확신할 수 있을 때만 구간을 절반으로 줄일 수 있다. 판정 결과가 단조성을 가지지 않으면, 중간값에서 "예"가 나왔다고 해서 답이 그보다 작다고 단정할 수 없다. 판정 함수가 단조 증가라면 "예"가 나오는 구간은 경계값 이상에서만 나타나고, 단조 감소라면 경계값 이하에서만 나타난다. 따라서 파라메트릭 서치를 적용하기 전에, 판정 결과가 단조성을 가지는지 먼저 확인해야 한다.

일반적인 실수는 판정 조건을 "정확히 n개"처럼 등식으로 두는 것이다. 등식은 단조성을 가지지 않는다. "n개 이상"처럼 부등식으로 두어야 한쪽 방향으로만 답이 모인다.

## 3. 이진 탐색의 구간 설정

파라메트릭 서치에서는 답이 반드시 들어가는 구간을 잡는 것이 먼저이다. 하한은 답보다 작거나 같은 값, 상한은 답보다 크거나 같은 값이어야 한다. 상한을 너무 작게 잡으면 답이 구간 밖에 있어 이진 탐색이 잘못된 값을 내놓는다. 상한을 넉넉하게 잡는 것은 이진 탐색 횟수를 로그 수준으로만 늘릴 뿐이므로, 확실한 상한을 쓰는 것이 안전하다.

예를 들어, "n개의 물건을 처리하는 최소 시간"을 구할 때, 가장 느린 처리 장치가 혼자 n개를 모두 처리하는 시간을 상한으로 잡으면 답은 반드시 그 안에 들어간다. 실제 답은 그보다 빠를 수 있지만, 이진 탐색이 구간을 좁혀 가며 정확한 경계를 찾아낸다.

```python
lo, hi = 1, max_time * n  # 답은 반드시 이 구간 안에 있다
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid):
        hi = mid
    else:
        lo = mid + 1
```

## 4. 판정 함수의 조기 종료

판정 함수는 "조건을 만족하는가"만 알면 되므로, 답이 확정되는 순간 바로 멈추는 것이 좋다. 예를 들어 합이 n 이상인지를 묻는 판정에서는 합이 n에 도달하는 순간 더 더할 필요가 없다. 조기 종료는 전체 연산량을 줄일 뿐 아니라, 누적 합이 커져서 자료형 범위를 넘는 것을 막는 역할도 한다.

판정 함수의 시간 복잡도가 전체 풀이의 시간 복잡도를 결정한다. 이진 탐색은 로그 횟수만큼 판정을 반복하므로, 판정이 O(m)이면 전체는 O(m log 범위)이다. 판정이 무거우면 파라메트릭 서치의 이점이 사라지므로, 판정은 가능한 한 가볍게 만드는 것이 중요하다.

## 5. 오버플로 주의

파라메트릭 서치의 상한은 문제의 최댓값을 곱한 형태가 많아, 32비트 정수 범위를 넘는 경우가 흔하다. 예를 들어 상한이 10^18까지 커지면 Java의 int(약 21억)로는 표현할 수 없으므로 long을 써야 한다. 판정 과정에서 더해지는 값도 중간에 커질 수 있어, 누적 합 역시 범위가 넉넉한 자료형으로 두는 것이 안전하다. Python은 임의 정밀도 정수라 이 걱정이 없지만, Java나 C++에서는 상한 계산부터 long으로 하는 습관이 필요하다.
