## 문제 분석 및 핵심 로직

세 사람이 각각 정해진 패턴으로 답안을 찍는다. 1번은 주기 5(`1,2,3,4,5`), 2번은 주기 8, 3번은 주기 10으로 답이 순환한다. 시험 문제는 최대 10,000개라 패턴을 실제로 늘려 대입할 수도 있지만, 핵심은 "i번째 문제에서 각 사람의 답 = 패턴[i % 주기]"라는 점이다. 모든 문제를 한 번씩만 순회하며 정답과 비교하면 가장 많이 맞힌 사람을 바로 알 수 있으므로, 완전탐색임에도 선형 시간에 끝난다.

## 개념별 심층 설명

### 초심자 방식: 패턴을 길게 늘려서 비교하기

답안 길이에 맞춰 각 사람의 패턴을 실제로 복제해 길이를 맞춘 뒤, 세 배열을 정답과 자리마다 비교한다.

- **동작 원리**: `patterns[j]`를 `ceil(n / 주기)`만큼 반복하고 앞 n개만 잘라 답안 배열과 `==` 비교.
- **왜 별로인가**: 길이 n 배열을 세 개나 만들고, 슬라이싱·zip 등 중간 연산이 늘어난다. n이 10,000으로 작아 통과는 되지만, 문제 조건이 커지면 메모리 낭비가 그대로 드러난다. 결국 주기성이라는 구조를 활용하지 못한 풀이이기도 하다.

### 개선 방식: 나머지 연산으로 순환 인덱싱

- **동작 원리**: i번째 문제에서 j번 사람의 답은 `pattern[j][i % len(pattern[j])]`다. 배열을 늘리지 않고, 정답을 순회하며 세 사람 점수를 누적한다.
- **왜 좋은가**: 추가 배열 없이 O(1) 보조 공간으로 끝나고, 코드도 더 짧다. 주기성을 수학적으로 직접 표현하는 방식이다.
- **시간복잡도**: O(n) — n개 문제를 세 사람이 각각 한 번씩 본다(상수 3).
- **공간복잡도**: O(1) — 패턴 세 개는 고정 크기, 점수 배열도 크기 3.

동점 처리는 "최고점을 세 명 모두와 비교해, 동점자 전원을 번호 오름차순으로 반환"하면 된다. 번호가 이미 1, 2, 3 순서대로 검사되므로 정렬을 따로 할 필요가 없다.

## 최종 솔루션 코드

### Python

```python
def solution(answers):
    # ① 각 수포자의 찍기 패턴 (반복 주기)
    patterns = [
        [1, 2, 3, 4, 5],                  # 1번: 길이 5
        [2, 1, 2, 3, 2, 4, 2, 5],         # 2번: 길이 8
        [3, 3, 1, 1, 2, 2, 4, 4, 5, 5],   # 3번: 길이 10
    ]

    # ② 각 패턴을 answers 길이에 맞춰 순환하며 맞힌 개수 세기
    scores = []
    for p in patterns:
        m = len(p)
        score = sum(1 for i, a in enumerate(answers) if a == p[i % m])
        scores.append(score)

    # ③ 최고점과 동점자를 찾아 오름차순 반환
    best = max(scores) if scores else 0
    return [i + 1 for i, s in enumerate(scores) if s == best]
```

### Java

```java
public int[] solution(int[] answers) {
    // ① 각 수포자의 찍기 패턴 (반복 주기)
    int[][] patterns = {
        {1, 2, 3, 4, 5},
        {2, 1, 2, 3, 2, 4, 2, 5},
        {3, 3, 1, 1, 2, 2, 4, 4, 5, 5},
    };

    // ② 각 패턴을 answers 길이에 맞춰 순환하며 맞힌 개수 세기
    int[] scores = new int[3];
    for (int j = 0; j < 3; j++) {
        int m = patterns[j].length;
        for (int i = 0; i < answers.length; i++) {
            if (answers[i] == patterns[j][i % m]) {
                scores[j]++;
            }
        }
    }

    // ③ 최고점과 동점자를 찾아 오름차순 반환
    int best = Math.max(scores[0], Math.max(scores[1], scores[2]));
    List<Integer> winners = new ArrayList<>();
    for (int j = 0; j < 3; j++) {
        if (scores[j] == best) winners.add(j + 1);
    }
    return winners.stream().mapToInt(Integer::intValue).toArray();
}
```

## 성능 측정 (로컬 실측, 2026-10-16)

| 케이스 | Python | Java |
|---|---|---|
| 입출력 예 1회 | 0.0035 ms | 0.0038 ms |
| n=100,000 무작위 답안 | 133.78 ms | 2.98 ms |
| n=100,000 추가 메모리 | ~1.0 KiB | ~123 KiB (JVM 초기 히프 측정 포함) |

- **시간복잡도**: O(n)
- **공간복잡도**: O(1)
- 최대 제한 n=10,000 기준 두 언어 모두 수 ms 이내로 여유 있게 통과한다. Java가 빠른 이유는 단순 루프 위주 코드에서 JIT의 효과가 그대로 드러났기 때문이며, 알고리즘 자체는 동일하다.

## 요약

- **막혔던 점**: 없음. 패턴 길이(5, 8, 10)를 문제 설명에서 그대로 옮기면 바로 풀리는 구조다.
- **핵심 포인트**: 주기적 패턴은 배열을 늘리지 말고 `i % 주기`로 직접 인덱싱한다.
- **개선**: 초심자 방식(패턴 복제 후 비교) → 나머지 연산 순환 인덱싱으로 O(1) 보조 공간 풀이.
