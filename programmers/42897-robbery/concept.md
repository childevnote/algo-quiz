# 개념 정리

## 1. 동적 프로그래밍 (Dynamic Programming)

동적 프로그래밍은 큰 문제를 작은 문제로 나누고, 작은 문제의 답을 재사용해 전체 답을 구하는 방법이다. 두 가지 조건이 필요하다. 첫째, 최적 부분 구조 — 전체 문제의 최적 해가 부분 문제의 최적 해로 이루어져야 한다. 둘째, 중복 부분 문제 — 같은 부분 문제가 여러 번 등장해 답을 저장해 두면 다시 계산하지 않아도 되어야 한다.

대표적인 예가 피보나치 수열이다. `F(n) = F(n-1) + F(n-2)`라는 점화식이 있고, `F(n)`을 구하는 과정에서 `F(n-2)`가 두 번, `F(n-3)`이 세 번 등장한다. 그대로 재귀하면 호출 횟수가 지수적으로 늘어나지만, 작은 값부터 순서대로 계산해 저장하면 각 값을 한 번씩만 구한다.

```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

피보나치처럼 점화식이 앞의 몇 개 값만 참조할 때는 배열 전체를 저장할 필요가 없다. 필요한 값만 변수에 들고 다니면 공간 복잡도를 O(1)까지 줄일 수 있다. 이를 공간 최적화, 또는 롤링 변수 기법이라고 한다.

## 2. 점화식 세우기 — 현재 선택이 과거에 미치는 영향

DP 문제의 출발점은 "지금 이 위치에서 내릴 수 있는 선택"을 나열하고, 각 선택이 어떤 과거 상태와 연결되는지 적는 것이다. 선택이 두 가지뿐인 경우가 많다. 하나는 현재 원소를 포함하는 선택이고, 다른 하나는 건너뛰는 선택이다.

현재 원소를 포함하면, 그 원소와 충돌하는 바로 앞 원소는 포함할 수 없으므로 두 단계 전의 최적 해에 현재 값을 더한 것이 된다. 건너뛰면 현재 원소가 답에 기여하지 않으므로 한 단계 전의 최적 해가 그대로 유지된다. 둘 중 큰 쪽이 현재까지의 최적 해다.

이 사고방식은 집합 선택 문제 전반에 통한다. 예를 들어 일정을 잡을 때 겹치지 않는 회의의 최대 개수를 구하거나, 계단을 오를 때 한 번에 1칸 또는 2칸씩 올라가는 방법의 수를 구할 때도 같은 틀을 쓴다. 계단 오르기는 점화식이 `ways(n) = ways(n-1) + ways(n-2)`로 피보나치와 같은 형태가 된다.

```python
def climb_stairs(n):
    a, b = 1, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b
```

## 3. 원형 배열의 경우 나누기 — 양쪽 끝이 충돌할 때

배열이 직선이 아니라 원형이면 첫 원소와 마지막 원소가 서로 영향을 준다. 둘을 동시에 선택할 수 없다는 제약 하나가 추가되는 셈이다. 이런 문제는 최적 해가 첫 원소를 포함하는지 여부로 경우를 나누면 직선 문제로 되돌릴 수 있다.

첫 원소를 포함하는 경우, 마지막 원소는 선택에서 제외되므로 고려 구간은 첫 원소부터 마지막에서 두 번째 원소까지가 된다. 첫 원소를 포함하지 않는 경우, 마지막 원소까지 자유롭게 볼 수 있으므로 구간은 두 번째 원소부터 마지막 원소까지가 된다. 최적 해는 반드시 두 경우 중 하나에 속하므로, 두 구간을 각각 직선 문제로 풀어 큰 쪽을 택하면 된다.

이 기법의 핵심은 경우 나눔이 완전하다는 점이다. "첫 원소를 포함한다"와 "포함하지 않는다"는 서로 겹치지 않고 모든 가능성을 덮는다. 경우를 나누는 비용은 직선 문제를 두 번 푸는 것뿐이라, 시간 복잡도는 상수 배만 늘어난다.
