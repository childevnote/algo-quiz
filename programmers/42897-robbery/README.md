# 도둑질

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42897
- 레벨: Lv.4
- 카테고리: DP
- 풀이일: 2026-11-17

## 문제 핵심 요약

집들이 원형으로 배치된 마을에서 도둑이 털 수 있는 돈의 최댓값을 구한다. 인접한 두 집을 동시에 털면 경보가 울리므로, 턴 집들 사이에는 최소 한 집이 비어 있어야 한다. 각 집에 있는 돈이 담긴 배열이 주어졌을 때 훔칠 수 있는 최대 금액을 반환한다.

핵심 제한사항:

- 집은 3개 이상 1,000,000개 이하
- money 배열의 각 원소는 0 이상 1,000 이하인 정수

입출력 예:

| money | return |
|---|---|
| [1, 2, 3, 1] | 4 |

예 설명: 1번 집(1원)과 3번 집(3원)을 털면 4원이다. 1번 집과 3번 집은 인접하지 않으므로 경보가 울리지 않는다. 2번 집(2원)과 4번 집(1원)을 터는 조합은 3원이라 더 적다.

## 문제 분석 및 핵심 로직

이 문제는 직선 배치의 도둑질 문제에 원형이라는 조건 하나가 얹힌 형태다. 직선 배치에서는 각 집마다 "턴다"와 "건너뛴다" 중 하나를 고르는데, 지금 집을 턴다면 바로 앞집은 털 수 없고, 건너뛴다면 앞집까지의 최댓값이 그대로 유지된다. 이를 점화식으로 쓰면 `dp[i] = max(dp[i-1], dp[i-2] + money[i])`가 된다.

원형 배치에서 달라지는 것은 첫 집과 마지막 집이 인접하다는 점 하나뿐이다. 그래서 최적 해를 두 경우로 나눈다. 첫 집을 터는 경우, 마지막 집은 털 수 없으므로 고려 구간은 첫 집부터 마지막에서 두 번째 집까지가 된다. 첫 집을 털지 않는 경우, 마지막 집까지 자유롭게 볼 수 있으므로 구간은 두 번째 집부터 마지막 집까지가 된다. 최적 해는 반드시 이 두 경우 중 하나에 속하므로, 각 구간을 직선 문제로 풀어 큰 쪽을 택하면 답이 된다.

핵심 로직은 세 단계다.

1. 구간 `[start, end]`를 직선 배치로 보고 두 개의 변수만으로 DP를 수행한다. `prev1`은 바로 앞집까지의 최댓값, `prev2`는 두 집 전까지의 최댓값이다.
2. 첫 집을 포함하는 구간 `[0, n-2]`와 제외하는 구간 `[1, n-1]`에 대해 각각 1번을 수행한다.
3. 두 구간의 결과 중 큰 값을 답으로 반환한다.

## 개념별 심층 설명

### 1. 직선 배치의 도둑질 — 점화식 하나로 끝나는 DP

초심자 방식은 모든 집의 털기/건너뛰기 조합을 전부 시도하는 것이다. 집이 n개면 조합은 2^n개라 n이 조금만 커져도 불가능하다. 한 걸음 나아간 방식은 재귀에 메모이제이션을 붙이는 것이다. i번째 집까지의 최댓값을 함수로 정의하고, `f(i) = max(f(i-1), f(i-2) + money[i])`로 계산하면 중복 계산이 사라진다. 그러나 재귀 호출 스택과 메모이제이션 배열이 필요하고, n이 1,000,000이면 재귀 깊이 때문에 스택 오버플로가 날 수 있다.

개선 방식은 점화식이 앞의 두 값만 참조한다는 점에 착안해 배열을 버리고 변수 두 개만 유지하는 것이다. 집을 왼쪽에서 오른쪽으로 한 번 훑으면서 `prev1`과 `prev2`를 갱신한다. 현재 집을 터는 경우의 값은 `prev2 + money[i]`이고, 건너뛰는 경우의 값은 `prev1`이다. 둘 중 큰 쪽이 현재 집까지의 최댓값이 되어 다음 단계의 `prev1`이 되고, 이전 `prev1`은 `prev2`가 된다.

동작 원리를 `[1, 2, 3, 1]`로 보자. 1번 집에서는 털면 1원, 건너뛰면 0원이므로 최댓값은 1이다. 2번 집에서는 털면 `0 + 2 = 2`원, 건너뛰면 1원이므로 2가 된다. 3번 집에서는 털면 `1 + 3 = 4`원, 건너뛰면 2원이므로 4가 된다. 4번 집에서는 털면 `2 + 1 = 3`원, 건너뛰면 4원이므로 4가 유지된다. 이렇게 한 번의 순회로 답이 나온다.

### 2. 원형 배치의 처리 — 경우 나누기가 전부다

원형에서 직선 DP를 그대로 돌리면 첫 집과 마지막 집을 동시에 터는 해가 나올 수 있다. 두 집은 원형에서 인접하므로 경보가 울린다. 그렇다고 첫 집과 마지막 집을 둘 다 빼 버리면 최적 해를 놓칠 수 있다. 첫 집을 털되 마지막 집만 빼는 해, 마지막 집을 털되 첫 집만 빼는 해가 모두 가능하기 때문이다.

그래서 최적 해가 첫 집을 포함하는지 여부로 경우를 나눈다. 첫 집을 포함하는 해는 마지막 집을 포함할 수 없으므로 구간 `[0, n-2]`의 최적 해와 같고, 첫 집을 포함하지 않는 해는 구간 `[1, n-1]`의 최적 해와 같다. 두 구간은 모두 직선 배치이므로 1번의 DP를 그대로 적용할 수 있다. 두 경우 중 큰 값이 전체 최적 해다. 경우를 나누는 비용은 DP를 두 번 도는 것뿐이라 전체 시간은 여전히 선형이다.

엣지 케이스를 확인하면 이 나눔이 완전하다는 것을 알 수 있다. 집이 3개 `[a, b, c]`인 경우, 구간 `[0, 1]`의 최댓값은 `max(a, b)`, 구간 `[1, 2]`의 최댓값은 `max(b, c)`다. 둘 중 큰 값은 `max(a, b, c)`로, 세 집 중 한 집만 털 수 있다는 원형 조건과 일치한다. 모든 원소가 0이면 두 구간 모두 0을 반환하므로 답은 0이다.

### 3. 공간 최적화 — 슬라이싱 대신 인덱스 구간

직선 DP를 구간에 적용할 때 파이썬에서 흔히 쓰는 방법은 `money[:-1]`처럼 슬라이싱으로 부분 배열을 만드는 것이다. 동작은 같지만 부분 배열을 복사하는 데 O(n)의 추가 메모리가 들고, 복사 자체도 O(n) 시간이다. n이 최대 1,000,000이면 구간 복사본이 두 개 생겨 수 MB의 메모리가 추가로 든다.

개선 방식은 배열을 복사하지 않고 구간을 인덱스 `[start, end]`로만 표시하는 것이다. DP 함수가 배열 전체와 시작·끝 인덱스를 받아 그 범위만 훑는다. 추가 메모리는 변수 두 개뿐이라 O(1)이다. 로컬 측정에서 n=1,000,000일 때 슬라이싱 방식은 397ms, 인덱스 방식은 442ms로 시간은 비슷했지만, 인덱스 방식의 추가 메모리는 tracemalloc 기준 0.5 KiB로 사실상 0이었다. 시간 차이가 크지 않으므로 메모리 사용량이 적은 인덱스 방식을 택했다. 자바도 같은 이유로 인덱스 구간을 받는 헬퍼 메소드를 쓴다.

## 최종 솔루션 코드

### Python

```python
def solution(money):
    # 1. 구간 [start, end]를 직선 배치로 보고 두 변수로 DP 수행
    #    prev1: 바로 앞집까지의 최댓값, prev2: 두 집 전까지의 최댓값
    def rob(start, end):
        prev2 = 0
        prev1 = 0
        for i in range(start, end + 1):
            # 2. 현재 집을 터는 경우(prev2 + money[i])와 건너뛰는 경우(prev1) 중 큰 쪽
            prev2, prev1 = prev1, max(prev1, prev2 + money[i])
        return prev1

    # 3. 첫 집을 포함하는 구간 [0, n-2]와 제외하는 구간 [1, n-1] 중 큰 값
    return max(rob(0, len(money) - 2), rob(1, len(money) - 1))
```

### Java

```java
class Solution {
    public int solution(int[] money) {
        // 1. 첫 집을 포함하는 구간 [0, n-2]와 제외하는 구간 [1, n-1] 중 큰 값
        return Math.max(rob(money, 0, money.length - 2),
                        rob(money, 1, money.length - 1));
    }

    // 2. 구간 [start, end]를 직선 배치로 보고 두 변수로 DP 수행
    //    prev1: 바로 앞집까지의 최댓값, prev2: 두 집 전까지의 최댓값
    private int rob(int[] money, int start, int end) {
        int prev2 = 0;
        int prev1 = 0;
        for (int i = start; i <= end; i++) {
            // 3. 현재 집을 터는 경우(prev2 + money[i])와 건너뛰는 경우(prev1) 중 큰 쪽
            int cur = Math.max(prev1, prev2 + money[i]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}
```

## 학습 노트

- 막혔던 점: 없음. 18:00 자동 풀이로 처리했으며, 원형 조건을 경우 나누기로 푸는 것이 이 문제의 핵심이라 직선 DP를 그대로 재사용할 수 있었다.
- 핵심 포인트: 원형 배치는 첫 집과 마지막 집의 인접성 하나만 다르다. 최적 해가 첫 집을 포함하는지 여부로 두 개의 직선 구간으로 나누면, 직선 도둑질 DP를 두 번 도는 것으로 답이 나온다.
- 개선: DP 배열을 쓰지 않고 변수 두 개만 유지해 공간을 O(1)로 줄였고, 구간을 슬라이싱으로 복사하지 않고 인덱스로 표시해 추가 메모리도 없앴다. 재귀 + 메모이제이션 방식은 n=1,000,000에서 스택 오버플로 위험이 있어 반복문 방식을 택했다.

- 공간 복잡도: O(1) — 변수 두 개만 유지하고 구간 복사본을 만들지 않는다.

## 요약

원형 배치의 도둑질은 첫 집 포함 여부로 두 개의 직선 구간으로 나누면 직선 도둑질 DP로 풀린다. 각 구간은 `dp[i] = max(dp[i-1], dp[i-2] + money[i])` 점화식을 변수 두 개만으로 계산하고, 두 구간의 최댓값 중 큰 쪽이 답이다. 시간 복잡도 O(n), 공간 복잡도 O(1)로 n ≤ 1,000,000 제한 안에서 충분히 여유가 있다.
