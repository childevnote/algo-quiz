## 문제 핵심 요약

모음 다섯 글자(A, E, I, O, U)만으로 만들 수 있는 길이 5 이하의 모든 단어를 사전식으로 나열했을 때, 주어진 단어가 몇 번째인지 구하는 문제다. 단, 여기서의 사전식 순서는 일반적인 문자열 정렬과 다르다. "A" 다음이 "AA"이고, "AAAAA" 다음이 "AAAAE"이며, "AAAAU" 다음이 "AAAE"다. 즉 짧은 단어가 그 단어로 시작하는 긴 단어보다 먼저 오고, 같은 접두사를 공유하면 다음 자리 모음 순서대로 나열된다.

핵심 제한사항: 단어 길이는 1 이상 5 이하, 모음 다섯 글자로만 구성된다.

입출력 예: "AAAAE" → 6, "AAAE" → 10, "I" → 1563, "EIO" → 1189.

## 문제 분석 및 핵심 로직

이 나열 순서는 트리의 전위 순회(pre-order)와 정확히 일치한다. 루트 아래에 다섯 개의 자식(A, E, I, O, U)이 있고, 각 노드는 다시 다섯 개의 자식을 가지며, 깊이는 최대 5다. 노드 자체가 하나의 단어가 되고, 전위 순회는 노드를 방문한 뒤 자식들을 순서대로 방문한다. 그래서 "A" → "AA" → "AAA" → ... 순으로 이어지는 것이다.

핵심 아이디어는 단어를 직접 열거하지 않고, 목표 단어보다 앞에 오는 단어의 개수를 자리마다 세는 것이다. 목표 단어의 각 자리에서, 현재 모음보다 작은 모음이 몇 개인지 보고, 그 모음 아래에 달린 서브트리 전체를 한 번에 건너뛴다. 여기에 조상 단어(접두사) 개수를 더하면 목표 단어보다 앞에 있는 단어 수가 되고, 여기에 1을 더하면 순번이 된다.

구체적으로 자리 i(0부터 시작)에 모음 인덱스 v(A=0, E=1, I=2, O=3, U=4)가 있다고 하자. 이 자리에서 건너뛰는 단어는 v × (그 모음 아래 서브트리 크기)개다. 깊이 d인 노드 아래 서브트리 크기는 1 + 5 + 25 + ... + 5^(5-d)이며, 등비수열 합으로 (5^(6-d) - 1) / 4로 계산된다. 자리 i의 노드 깊이는 i+1이므로 서브트리 크기는 (5^(5-i) - 1) / 4다. 마지막으로 조상 단어는 길이 - 1개(접두사들)이고, 목표 단어 자신을 포함해 순번은 "건너뛴 단어 수 + 길이"가 된다.

"EIO"로 확인해 보자. 첫 자리 E(v=1): 깊이 1 서브트리 크기 781이므로 781개를 건너뛴다. 둘째 자리 I(v=2): 깊이 2 서브트리 크기 156이므로 312개를 건너뛴다. 셋째 자리 O(v=3): 깊이 3 서브트리 크기 31이므로 93개를 건너뛴다. 합 1186에 길이 3을 더하면 1189다.

## 개념별 심층 설명

### 초심자 방식: 모든 단어를 만들어 정렬하기

가장 먼저 떠오르는 방법은 재귀나 반복문으로 길이 5 이하의 모든 단어를 만든 뒤, 사전식 순서대로 정렬하고 목표 단어의 위치를 찾는 것이다. 전체 단어 수는 5 + 25 + 125 + 625 + 3125 = 3905개라 이 문제에서는 충분히 동작한다. 실제로 동작한다는 점에서는 틀리지 않았다.

하지만 이 방식은 단어 수에 비례하는 메모리와 정렬 비용을 쓴다. 단어 길이가 5에서 조금만 커져도 단어 수는 5의 거듭제곱으로 불어나고, 정렬까지 더해지면 금방 감당하기 어려워진다. 길이가 고정된 작은 문제에서는 괜찮지만, 구조를 세는 방식으로 바꿀 수 있는데 굳이 열거할 필요는 없다.

### 개선 방식: 순서를 세는 문제로 바꾸기

사전식 순서가 트리 전위 순회라는 점에 착안하면, 열거 없이 순번을 직접 계산할 수 있다. 각 자리마다 "나보다 작은 모음 아래에 단어가 몇 개인가"만 알면 되기 때문이다. 서브트리 크기는 등비수열 합으로 한 번에 구해지므로, 전체 계산은 단어 길이에 비례하는 다섯 번의 연산으로 끝난다. 단어 수가 3905개든 5의 거듭제곱으로 커지든, 계산량은 단어 길이에만 비례한다.

이 방식에서 놓치기 쉬운 부분은 두 가지다. 첫째, 조상 단어(접두사)도 목표 단어보다 앞에 온다는 점이다. 전위 순회는 부모를 자식보다 먼저 방문하므로, "AAAAE" 앞에 "A", "AA", "AAA", "AAAA"가 있다는 것을 빼먹으면 안 된다. 둘째, 서브트리 크기에 노드 자신을 포함해야 한다는 점이다. "A" 아래 서브트리에는 "A" 자체도 포함되므로, 크기는 781이지 780이 아니다.

### 왜 일반적인 문자열 정렬과 다른가

파이썬의 기본 문자열 정렬에서 "AA"는 "A"보다 뒤에 오지만, 이 문제의 사전에서는 "A" 다음이 "AA"다. 일반적인 정렬은 짧은 문자열이 접두사 관계일 때 먼저 오도록 하지만, 여기서도 사실 마찬가지다. 차이점은 그 다음이다. 일반 정렬에서 "AAAAU" 다음은 "AAAE"가 아니라 "AAA..." 계열이 끝난 뒤에야 오지만, 이 문제에서는 "AAAAU"의 형제들이 끝나면 바로 부모의 다음 자식인 "AAAE"로 넘어간다. 즉 접두사가 같은 단어끼리 묶이는 것이 아니라, 트리를 깊이 우선으로 탐색하는 순서다. 이 차이를 파악하지 못하면 정렬로 풀려다 예제에서 틀리게 된다.

## 최종 솔루션 코드

### Python

```python
def solution(word):
    vowels = "AEIOU"
    # 1. 자기 자신과 조상 단어 수만큼 기본 카운트 (길이만큼)
    answer = len(word)
    for i, ch in enumerate(word):
        # 2. 현재 자리보다 작은 모음 개수
        idx = vowels.index(ch)
        # 3. 그 모음 아래에 달린 서브트리 단어 수: 1 + 5 + ... + 5^(4-i)
        subtree = (5 ** (5 - i) - 1) // 4
        # 4. 건너뛴 서브트리만큼 더한다
        answer += idx * subtree
    return answer
```

### Java

```java
class Solution {
    public int solution(String word) {
        String vowels = "AEIOU";
        // 1. 자기 자신과 조상 단어 수만큼 기본 카운트 (길이만큼)
        int answer = word.length();
        for (int i = 0; i < word.length(); i++) {
            // 2. 현재 자리보다 작은 모음 개수
            int idx = vowels.indexOf(word.charAt(i));
            // 3. 그 모음 아래에 달린 서브트리 단어 수: 1 + 5 + ... + 5^(4-i)
            int subtree = (pow5(5 - i) - 1) / 4;
            // 4. 건너뛴 서브트리만큼 더한다
            answer += idx * subtree;
        }
        return answer;
    }

    private int pow5(int n) {
        int r = 1;
        for (int i = 0; i < n; i++) r *= 5;
        return r;
    }
}
```

## 성능 측정

- 예제 케이스: Python·Java 모두 4건 통과 ("AAAAE" → 6, "AAAE" → 10, "I" → 1563, "EIO" → 1189).
- 전수 대조: 깊이 우선 열거로 만든 전체 3905개 단어의 순번과 공식 계산 결과가 모두 일치했다.
- 100,000회 반복 실행: Python 약 96.1ms(회당 약 0.96us), Java 약 17.7ms(회당 약 0.18us). 단어 길이가 최대 5로 고정돼 있어, 길이가 커지는 스케일 테스트는 의미가 없어 반복 횟수로 대체했다.
- 피크 메모리(Python, tracemalloc): 약 0.3KB. 추가 자료구조를 쓰지 않는다.
- 시간 복잡도: O(L) (L은 단어 길이, 최대 5). 공간 복잡도: O(1).

## 요약

- 이 문제의 나열 순서는 트리 전위 순회다. 정렬이 아니라 탐색 순서로 이해해야 한다.
- 열거하지 말고 자리마다 건너뛰는 서브트리 크기를 세면 O(L)에 순번을 구할 수 있다.
- 조상 단어(접두사)와 서브트리 크기 계산 시 노드 자신 포함 여부를 빼먹지 않는 것이 핵심이다.
