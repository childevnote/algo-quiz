# 개념 정리: 탐욕법의 교환 논증과 투 포인터

이 파일은 문제 지문이나 문제 전용 풀이 코드를 담지 않는다. 아래 개념들은 일반적인 형태로 정리한 것이다.

## 1. 탐욕법과 교환 논증

탐욕법은 매 단계에서 당장 최선으로 보이는 선택을 하고, 그 선택이 최적해에 포함될 수 있음을 증명해야 성립한다. 증명의 전형적인 도구가 교환 논증이다.

- 최적해가 존재한다고 가정한다.
- 최적해의 첫 선택이 탐욕 선택과 다르다면, 탐욕 선택으로 교체해도 해의 품질이 나빠지지 않음을 보인다.
- 교체가 가능하면 탐욕 선택을 포함한 최적해가 존재하므로, 탐욕적으로 진행해도 최적성을 잃지 않는다.

일반적인 예시로, 제한을 만족하는 쌍을 최대한 많이 만드는 상황을 생각해 보자. 가장 제약이 강한 원소(예: 가장 큰 값)부터 처리하고, 그 짝으로는 가장 제약이 약한 원소(예: 가장 작은 값)를 고르는 선택은 교환 논증의 단골 패턴이다. 강한 원소의 짝을 약한 원소로 교체하면, 원래 짝이었던 원소는 더 가벼운 상대와 짝을 짓게 되므로 제한 조건이 깨지지 않는다.

탐욕 선택이 틀리는 경우도 있다. 예를 들어 "합이 제한을 넘지 않는 쌍을 최대한 많이"가 아니라 "쌍의 합을 최대한 크게" 만드는 문제에서는, 가장 큰 원소끼리 묶는 탐욕 선택이 최적을 보장하지 않는다. 탐욕법은 선택마다 교환 논증이 성립하는지 확인한 뒤에만 쓴다.

## 2. 투 포인터

투 포인터는 정렬된 배열의 양끝(또는 한쪽 끝에서 시작하는 두 위치)에 포인터를 두고, 조건에 따라 포인터를 안쪽으로 이동시키며 선형 시간에 답을 구하는 기법이다.

```python
# 일반적인 형태: 정렬된 배열에서 합이 target 이하인 쌍을 세는 예시
def count_pairs(arr, target):
    arr.sort()
    left, right = 0, len(arr) - 1
    count = 0
    while left < right:
        if arr[left] + arr[right] <= target:
            # arr[left]와 right 사이의 모든 원소는 arr[left]와 쌍을 이룰 수 있다
            count += right - left
            left += 1
        else:
            right -= 1
    return count
```

- 왜 정렬이 필요한가: 포인터 이동의 정당성은 순서에 의존한다. 오른쪽 포인터를 한 칸 왼쪽으로 옮기는 결정은 "현재 오른쪽 원소가 어떤 왼쪽 원소와도 조건을 만족하지 못한다"는 판단인데, 이는 배열이 정렬되어 있을 때만 성립한다. 정렬되지 않은 배열에서는 한 원소와의 실패가 다른 원소와의 실패를 함축하지 않는다.
- 시간 복잡도: 정렬 O(n log n) + 순회 O(n)이므로 전체 O(n log n)이다. 입력이 이미 정렬되어 있다면 순회만으로 O(n)에 해결된다.
- 흔한 실수: `left < right`와 `left <= right`의 조건을 헷갈리는 것이다. 쌍을 세는 문제에서는 같은 원소를 두 번 쓰지 않으므로 `left < right`가 맞고, 원소 하나를 단독으로 처리할 수 있는 문제에서는 `left <= right`까지 진행해야 마지막 원소가 누락되지 않는다.

## 3. 정렬 비용이 지배하는 문제의 성능 읽기

정렬 + 선형 순회 구조에서는 전체 시간 복잡도가 정렬의 O(n log n)으로 결정된다. 순회 부분을 아무리 최적화해도 정렬 비용 아래로는 내려가지 않으므로, 성능 개선의 여지는 정렬을 피할 수 있는지(예: 입력 범위가 작아 계수 정렬이 가능한 경우)에만 있다.

공간 측면에서는 알고리즘이 쓰는 추가 공간과 정렬 구현이 내부적으로 쓰는 임시 공간을 구분해서 읽어야 한다. 투 포인터 자체는 포인터 몇 개만 쓰므로 O(1)이지만, CPython의 Timsort는 최악 O(n)의 임시 버퍼를, Java의 원시 타입 정렬은 제자리 방식으로 O(log n) 수준의 스택을 쓴다. 실측 메모리 수치를 해석할 때는 테스트 하네스의 복사본까지 포함되어 있는지 함께 확인한다.
