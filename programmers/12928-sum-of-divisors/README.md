# 약수의 합

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12928
- 레벨: Lv.1
- 카테고리: 연습문제

## 문제 핵심 요약

정수 `n`을 입력받아 `n`의 약수를 모두 더한 값을 반환한다.

- 제한사항: `n`은 0 이상 3000 이하인 정수
- 입출력 예: `12 → 28` (1, 2, 3, 4, 6, 12의 합), `5 → 6` (1, 5의 합)

## 문제 분석 및 핵심 로직

약수를 찾는 일은 나눗셈을 확인하는 일이다. `i`가 `n`의 약수라는 말은 `n % i == 0`이라는 뜻과 같다. `12`의 약수를 찾으려면 `1`부터 `12`까지 각 수가 `12`를 나누어떨어지게 하는지 확인하면 된다.

여기서 한 가지 관찰이 있다. 약수는 짝을 이룬다. `3`이 `12`의 약수이면, 짝인 `12 / 3 = 4`도 `12`의 약수이다. `2`의 짝은 `6`, `1`의 짝은 `12`이다. 즉 약수 하나를 찾으면 짝까지 덤으로 얻는 셈이다. 짝이 만나는 지점은 제곱근이다. `i`가 `sqrt(n)`을 넘어가면 그 짝은 이미 `sqrt(n)`보다 작은 쪽에서 찾은 약수의 짝으로 등장한 적이 있다. 그래서 `1`부터 `sqrt(n)`까지만 확인하면 모든 약수를 찾을 수 있다.

단, 제곱수는 주의해야 한다. `36`의 경우 `i = 6`일 때 짝이 `36 / 6 = 6`으로 자기 자신이다. 짝을 무조건 더하면 `6`을 두 번 더하게 되므로, `i * i == n`인 경우에만 짝을 더하지 않는다.

`n = 0`은 별도로 처리한다. `0`은 어떤 수로도 나눌 수 있지만(나머지가 0), 약수의 합이라는 문제의 정의상 `0`을 반환하는 것이 자연스럽다. `0`에 대해서는 반복 범위를 정할 수 없으므로, 시작 부분에서 `0`을 반환하고 빠져나온다.

## 개념별 심층 설명

### 초심자 방식: 1부터 n까지 전부 확인하기

`1`부터 `n`까지 모든 수에 대해 `n % i == 0`인지 확인하고, 나누어떨어지는 수를 모두 더한다. 생각나는 대로 바로 옮긴 방법이라 이해하기 쉽고, 이 문제의 제한(`n ≤ 3000`)에서는 충분히 빠르게 동작한다.

이 방식의 비용은 `n`에 비례한다. `n`이 `100,000`이 되면 `100,000`번의 나눗셈이 필요하고, `n`이 10배가 되면 시간도 10배가 된다. 제한이 작아 이 문제에서는 통과하지만, 입력 범위가 커지면 그대로 쓸 수 없는 방식이다.

### 개선 방식: 약수 쌍을 이용해 제곱근까지만 확인하기

약수는 짝을 이룬다는 성질을 이용한다. `i`가 약수이면 `n // i`도 약수이다. `i`가 `sqrt(n)`을 넘어가면 `n // i`는 `sqrt(n)`보다 작아지는데, 그 값은 이미 더 작은 `i`를 확인할 때 약수로 발견된 적이 있다. 따라서 `1`부터 `sqrt(n)`까지만 확인하면 되며, 확인 횟수는 `n`에서 `sqrt(n)`으로 줄어든다.

예를 들어 `n = 36`이면 `1`부터 `6`까지만 확인한다. `i = 1`에서 `1`과 `36`, `i = 2`에서 `2`와 `18`, `i = 3`에서 `3`과 `12`, `i = 4`는 나누어떨어지지 않아 건너뛰고, `i = 6`에서 `6`을 한 번만 더한다. 합은 `1 + 36 + 2 + 18 + 3 + 12 + 4 + 9 + 6 = 91`이다.

이 방식은 제곱수에서 짝이 자기 자신과 겹친다는 점만 주의하면 된다. `i * i == n`일 때는 짝을 더하지 않는다. `n`이 커질수록 이득이 커진다. `n = 100,000`이면 초심자 방식은 `100,000`번, 개선 방식은 `316`번만 확인한다.

## 최종 솔루션 코드

### Python

```python
def solution(n):
    # 1. 약수는 짝을 이룬다: i가 n의 약수이면 n // i도 n의 약수이다.
    # 2. 1부터 sqrt(n)까지만 확인하면 모든 약수 쌍을 찾을 수 있다.
    #    i * i == n인 경우(제곱수)는 i를 한 번만 더한다.
    # 3. n이 0이면 약수가 없으므로 0을 반환한다.
    if n == 0:
        return 0
    total = 0
    i = 1
    while i * i <= n:
        if n % i == 0:
            total += i
            if i * i != n:
                total += n // i
        i += 1
    return total
```

### Java

```java
class Solution {
    public int solution(int n) {
        // 1. 약수는 짝을 이룬다: i가 n의 약수이면 n / i도 n의 약수이다.
        // 2. 1부터 sqrt(n)까지만 확인하면 모든 약수 쌍을 찾을 수 있다.
        //    i * i == n인 경우(제곱수)는 i를 한 번만 더한다.
        // 3. n이 0이면 약수가 없으므로 0을 반환한다.
        if (n == 0) {
            return 0;
        }
        int total = 0;
        for (int i = 1; i * i <= n; i++) {
            if (n % i == 0) {
                total += i;
                if (i * i != n) {
                    total += n / i;
                }
            }
        }
        return total;
    }
}
```

`i * i <= n`이라는 조건은 `i <= sqrt(n)`과 같은 뜻이지만, 부동소수점 제곱근을 쓰지 않아 오차가 없다. `i`가 `sqrt(n)`을 넘는 순간 반복이 끝나므로, 확인 범위는 정확히 `1`부터 `sqrt(n)`까지이다.

## 성능 측정

로컬 실측 결과이다. 문제의 제한은 `n ≤ 3000`이지만 스케일 차이를 보기 위해 `n = 100,000`까지 측정했다.

- Python 피크 메모리: 96 bytes (tracemalloc 실측, `n = 100,000` 1회 실행)
- Java 메모리 증가: 0 bytes (Runtime 실측, `n = 100,000` 1회 실행)
- 시간복잡도: O(√n) — `1`부터 `sqrt(n)`까지만 확인
- 공간복잡도: O(1) — 변수 몇 개만 사용

`n = 100,000`에서 개선 방식은 초심자 방식보다 약 210배 빠르다. `n`이 커질수록 격차는 `sqrt(n)` 대 `n`의 비율만큼 벌어진다. 이 문제의 제한(`n ≤ 3000`) 안에서는 두 방식 모두 여유 있게 동작한다.

## 요약

- 핵심 아이디어: 약수는 짝을 이룬다 — `i`가 약수이면 `n // i`도 약수이므로 `sqrt(n)`까지만 확인한다.
- 제곱수에서는 짝이 자기 자신이므로 한 번만 더한다.
- `n = 0`은 약수가 없으므로 `0`을 반환한다.
- 시간복잡도는 O(√n), 공간복잡도는 O(1)이다.
