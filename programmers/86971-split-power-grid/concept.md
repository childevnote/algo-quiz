# 개념 정리

## 트리(Tree)와 간선 절단

트리는 사이클이 없는 연결 그래프다. 노드가 n개면 간선은 정확히 n-1개다. 트리에서 간선 하나를 제거하면 그래프는 반드시 정확히 두 개의 연결 요소로 나뉜다. 어느 간선을 끊든 예외가 없으며, 끊긴 간선의 한쪽 끝에서 도달 가능한 노드 집합이 곧 한쪽 그룹이 된다. 이 성질 덕분에 두 그룹을 모두 셀 필요 없이 한쪽 그룹의 크기만으로 차이(`|n - 2 × 한쪽 크기|`)를 구할 수 있다.

```python
# 간선 (a, b)를 끊었을 때 한쪽 그룹 크기만 알면 충분하다
diff = abs(n - 2 * one_side_size)
```

## 루트 고정과 부분 트리(서브트리)

트리에는 원래 루트가 없지만, 임의의 노드를 루트로 정하면 모든 간선은 "부모-자식" 관계로 바뀐다. 어떤 노드를 루트로 하는 부분 트리는 그 노드와 그 아래 모든 자손으로 이루어진다. 부분 트리의 크기는 재귀적으로 정의된다.

```python
# size[node] = 1 + sum(size[child] for child in children[node])
```

자식보다 부모를 나중에 처리해야 하므로, DFS 방문 순서를 역순으로 처리하면 모든 부분 트리 크기를 한 번의 패스로 구할 수 있다. 각 노드는 정확히 한 번씩 부모에게 크기를 전달하므로 전체 작업량은 간선 수에 비례한다.

## 반복 DFS와 재귀 DFS

재귀 DFS는 코드가 짧지만, 트리가 깊어지면 호출 스택이 깊어져 스택 오버플로가 날 수 있다. 명시적 스택을 쓰는 반복 DFS는 같은 탐색을 수행하면서도 트리의 깊이와 무관하게 안전하다. 방문 순서만 기록해 두고 나중에 역순으로 처리하는 패턴은 부분 트리 크기, 트리 높이, 트리 DP 등 여러 트리 문제에 공통으로 쓰인다.

```python
# 반복 DFS로 부모와 방문 순서 기록
parent = [0] * (n + 1)
order = []
stack = [1]
parent[1] = -1
while stack:
    node = stack.pop()
    order.append(node)
    for nxt in graph[node]:
        if nxt != parent[node] and parent[nxt] == 0:
            parent[nxt] = node
            stack.append(nxt)

# 역순으로 부분 트리 크기 누적
size = [1] * (n + 1)
for node in reversed(order):
    if parent[node] > 0:
        size[parent[node]] += size[node]
```

## 시간복잡도 관점: 시뮬레이션 vs 한 번의 탐색

간선을 하나씩 끊고 매번 그래프를 탐색하는 방식은 간선 수(n-1) × 탐색 비용(O(n))으로 O(n²)이 된다. 반면 루트를 고정해 부분 트리 크기를 한 번에 구하면 탐색 한 번, 역순 누적 한 번, 차이 계산 한 번으로 O(n)에 끝난다. "모든 경우를 직접 시뮬레이션하는" 대신 "모든 경우의 답을 한 번의 탐색에서 함께 구하는" 발상의 전환이 이 문제의 핵심이다.
