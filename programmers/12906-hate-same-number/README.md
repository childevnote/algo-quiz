# 같은 숫자는 싫어

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12906
- 레벨: Lv.1 · 카테고리: 스택/큐

## 문제 분석 및 핵심 로직

배열의 원소는 0~9 사이 숫자로, 연속으로 나타나는 같은 숫자는 하나만 남기고 나머지를 제거한다. 단, 원래 순서는 그대로 유지해야 한다. 핵심 제한은 배열 크기가 최대 100만이라는 점으로, 한 번의 순회로 끝나는 선형 해법이 필요하다.

핵심 아이디어는 **결과 리스트를 스택처럼 쓰는 것**이다. 원소를 왼쪽부터 하나씩 보면서, 결과 리스트의 마지막 값(스택의 top)과 현재 값이 다를 때만 추가한다. 같은 값이 연속으로 들어오면 자동으로 무시되고, 중간에 다른 숫자가 끼면 다시 추가된다.

## 개념별 심층 설명

### 초심자 방식 — 매번 처음부터 비교하기

원소마다 이미 결과에 넣은 모든 원소를 처음부터 비교해 중복을 제거하려 하면, 원소가 n개일 때 비교 횟수가 n²에 육박한다. n = 1,000,000이면 현실적으로 끝나지 않는다.

```python
# 일반 예시: 왜 느린지 확인하는 패턴 (이 문제 풀이 아님)
data = [3, 1, 4, 1, 5]
for x in data:
    for y in data:      # 매번 전체를 다시 순회
        pass
```

### 개선 방식 — 스택의 top 하나만 비교하기

연속된 중복만 제거하면 되므로, 비교 대상은 "지금까지의 마지막 값" 하나면 충분하다. 결과 리스트의 끝은 스택의 top과 같은 역할을 한다.

```python
# 일반 예시: 스택 top과만 비교해 연속 중복 제거
stack = []
for c in "aaabbc":
    if not stack or stack[-1] != c:
        stack.append(c)
print("".join(stack))  # abc
```

### 동작 원리

1. 빈 결과 리스트에서 시작한다.
2. 원소 x를 본다.
3. 리스트가 비었거나 마지막 원소가 x와 다르면 x를 추가한다.
4. 같으면(연속 중복) 건너뛴다.
5. 모든 원소를 한 번씩 보면 끝난다.

각 원소는 최대 한 번 추가되므로 시간복잡도는 O(n), 공간복잡도는 결과 리스트 크기만큼 O(n)이다.

## 최종 솔루션 코드

### Python

```python
def solution(arr):
    result = []
    for x in arr:
        # 1. 결과 리스트의 마지막 값과 현재 값이 다를 때만 추가 (연속 중복 제거)
        if not result or result[-1] != x:
            result.append(x)
    return result
```

### Java

```java
class Solution {
    public int[] solution(int[] arr) {
        List<Integer> list = new ArrayList<>();
        for (int x : arr) {
            // 1. 결과의 마지막 값과 현재 값이 다를 때만 추가 (연속 중복 제거)
            if (list.isEmpty() || list.get(list.size() - 1) != x) {
                list.add(x);
            }
        }
        return list.stream().mapToInt(i -> i).toArray();
    }
}
```

## 성능 측정

로컬 실측 (n = 100,000, 0~9 무작위 정수):

| 언어 | 예제 케이스 | n=100,000 | 피크 메모리(Python) | 시간복잡도 | 공간복잡도 |
|---|---|---|---|---|---|
| Python | 1.4µs | 4.9ms | 782KiB | O(n) | O(n) |
| Java | — | 27ms | — | O(n) | O(n) |

- 시간복잡도: 원소를 한 번씩만 순회 → O(n)
- 공간복잡도: 결과 리스트만큼 추가 저장 → O(n)
- Java의 stream 변환에서 박싱 오버헤드가 있지만 n=100만에서도 수십 ms 수준으로 제한 내 충분히 통과한다.

## 요약

- 막혔던 점: 없음. 가장 먼저 출제된 Lv.1 스택/큐 문제로, 결과 리스트를 스택처럼 쓰면 한 번의 순회로 끝난다는 패턴이 핵심이었다.
- 핵심 포인트: "연속 중복 제거 = 스택의 top과만 비교하면 된다" — 전체를 다시 볼 필요가 없다.
- 개선: 초심자 방식(O(n²), 매번 전체 비교)에서 개선 방식(O(n), top 한 번만 비교)으로 바꿨다.
