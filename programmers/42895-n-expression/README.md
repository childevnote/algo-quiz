# N으로 표현

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42895
- 레벨: Lv.3
- 카테고리: DP
- 풀이 날짜: 2026-11-05 (18:00 자동 풀이)

## 문제 핵심 요약

숫자 N 하나와 사칙연산만을 이용해 주어진 number를 만들 때, N을 사용하는 횟수의 최솟값을 구하는 문제다. 괄호를 자유롭게 쓸 수 있고, 나눗셈에서는 나머지를 버린다. N을 8번보다 많이 써야 하면 -1을 반환한다.

- 제한사항: N은 1 이상 9 이하, number는 1 이상 32,000 이하, 최솟값이 8보다 크면 -1 반환
- 입출력 예: `N=5, number=12 → 4` / `N=2, number=11 → 3`

## 문제 분석 및 핵심 로직

N을 k번 쓰는 방법은 두 가지로 나뉜다. 하나는 N을 k번 이어붙인 수(55, 555 같은 수)이고, 다른 하나는 k번을 j번과 k-j번으로 나눠 각각 만든 두 수에 사칙연산을 적용하는 것이다. 예를 들어 12는 `55/5 + 5/5`처럼 5를 4번 써서 만들 수 있는데, 이는 2번으로 만든 55와 1번으로 만든 5, 그리고 1번으로 만든 5를 나눗셈과 덧셈으로 조합한 결과다.

이 관찰이 곧 점화식이다. `dp[i]`를 "N을 i번 사용해서 만들 수 있는 수들의 집합"이라 두면, `dp[i]`는 이어붙인 수 `NN...N`에, 모든 분할 `j + (i-j) = i`에 대해 `dp[j]`와 `dp[i-j]`의 원소 쌍에 사칙연산을 적용한 결과를 합친 집합이 된다. i를 1부터 8까지 차례로 채우다가 number가 처음 등장하는 i가 곧 최솟값이다. 8까지 채웠는데도 number가 없으면 -1이다.

핵심은 "최솟값을 직접 구하려고 하지 않고, 횟수별로 만들 수 있는 수를 전부 모아두는 것"이다. 횟수가 늘어날수록 집합이 커지지만, N이 한 자리 수이고 횟수가 최대 8번이라 집합 크기는 충분히 다룰 만한 수준에 머문다.

## 개념별 심층 설명

### 횟수를 차원으로 삼는 동적 프로그래밍

보통 동적 프로그래밍은 입력 크기나 합 같은 값을 차원으로 삼는다. 이 문제에서는 "N을 몇 번 썼는가"가 차원이다. 횟수를 비용으로 보고, 각 비용으로 도달할 수 있는 모든 결과를 집합에 저장한다. 비용이 작은 쪽부터 채우면, 원하는 수가 처음 등장하는 비용이 곧 최소 비용이 된다.

초심자 방식은 보통 수식을 직접 만들려고 한다. 예를 들어 number에서 거꾸로 N을 빼거나 나누는 식으로 접근하는데, 나눗셈의 역연산이 유일하지 않고(몫이 같아도 나머지가 다르면 원래 수가 다르다), 뺄셈·나눗셈이 섞이면 역방향 탐색이 금방 복잡해진다. 개선 방식은 방향을 뒤집는 것이다. 작은 횟수로 만들 수 있는 수를 전부 모아두고, 그 수들을 조합해 한 단계 큰 횟수의 집합을 만드는 식으로 앞으로 나아간다. 역연산을 고민할 필요가 없어진다.

### 집합(Set)을 이용한 중복 제거

같은 수를 만드는 방법은 여러 가지다. 서로 다른 식이 같은 값을 만들 수 있다. 값을 리스트에 그대로 쌓으면 중복이 기하급수적으로 늘어나지만, 집합에 넣으면 같은 값은 하나로 합쳐진다. 중복을 제거하는 것이 이 풀이의 성능을 결정짓는 요소다. 집합에 들어가는 것은 "어떻게 만들었는가"가 아니라 "무엇을 만들 수 있는가"뿐이며, 이후 조합에서는 식의 내역이 필요 없기 때문에 정보를 버려도 답에 영향을 주지 않는다.

### 분할 조합과 사칙연산의 순서

i번을 j번과 i-j번으로 나누는 분할은 j=1부터 i-1까지 모두 시도해야 한다. 뺄셈과 나눗셈은 교환법칙이 성립하지 않으므로, 순서가 바뀐 쌍도 따로 계산해야 한다. j가 1부터 i-1까지 움직이면 `(dp[j], dp[i-j])`의 순서쌍이 양방향을 모두 커버하므로, 각 쌍마다 `a-b`와 `a/b`만 계산하면 충분하다. 0으로 나누기는 제외한다.

나눗셈은 주의할 점이 하나 있다. 뺄셈으로 음수가 만들어질 수 있고, 음수의 나눗셈은 "버림"과 "0 쪽으로 자르기"가 다른 결과를 낸다. 이 풀이에서는 Python의 `//`(버림, floor)를 기준으로 삼고, Java에서는 `Math.floorDiv`로 같은 의미를 맞췄다. 양수끼리의 나눗셈에서는 두 방식이 같으므로 예제에는 영향이 없고, 음수가 개입하는 경우에도 한 가지 규칙으로 통일하면 된다.

## 최종 솔루션 코드

### Python

```python
def solution(N, number):
    # 1. dp[i]: N을 i번 사용해서 만들 수 있는 수들의 집합
    dp = [set() for _ in range(9)]
    for i in range(1, 9):
        # 2. N을 i번 이어붙인 수 (예: N=5, i=3 -> 555)
        dp[i].add(int(str(N) * i))
        # 3. i번을 j번과 i-j번으로 나눠 사칙연산으로 조합
        for j in range(1, i):
            for a in dp[j]:
                for b in dp[i - j]:
                    dp[i].add(a + b)
                    dp[i].add(a - b)
                    dp[i].add(a * b)
                    if b != 0:
                        dp[i].add(a // b)
        # 4. number를 처음 만든 횟수가 최솟값
        if number in dp[i]:
            return i
    return -1
```

### Java

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

class Solution {
    public int solution(int N, int number) {
        // 1. dp[i]: N을 i번 사용해서 만들 수 있는 수들의 집합 (long: 중간 곱셈 오버플로 방지)
        List<Set<Long>> dp = new ArrayList<>();
        for (int i = 0; i < 9; i++) {
            dp.add(new HashSet<>());
        }
        for (int i = 1; i <= 8; i++) {
            // 2. N을 i번 이어붙인 수 (예: N=5, i=3 -> 555)
            long concat = 0;
            for (int k = 0; k < i; k++) {
                concat = concat * 10 + N;
            }
            dp.get(i).add(concat);
            // 3. i번을 j번과 i-j번으로 나눠 사칙연산으로 조합
            for (int j = 1; j < i; j++) {
                for (long a : dp.get(j)) {
                    for (long b : dp.get(i - j)) {
                        dp.get(i).add(a + b);
                        dp.get(i).add(a - b);
                        dp.get(i).add(a * b);
                        if (b != 0) {
                            dp.get(i).add(Math.floorDiv(a, b));
                        }
                    }
                }
            }
            // 4. number를 처음 만든 횟수가 최솟값
            if (dp.get(i).contains((long) number)) {
                return i;
            }
        }
        return -1;
    }
}
```

Java에서는 중간 곱셈이 int 범위를 넘을 수 있어 집합의 원소를 `long`으로 두었다. 예를 들어 이어붙인 수끼리 곱하면 int 범위를 쉽게 넘는다. 최종 비교만 `number`와 하므로, 중간값을 넓은 타입으로 두는 것이 안전하다.

## 학습 노트

- 막혔던 점: 18:00 자동 풀이로 진행되어 별도의 막힘 없이 풀이했다. 다만 엣지 케이스 검증에서 (8, 53)의 답을 -1로 예상했다가 풀이가 5를 반환했는데, 역추적 결과 `(8*8) - (88//8) = 64 - 11 = 53`으로 5번이 맞았다. 직관으로 "안 될 것 같다"고 단정하기 전에 풀이를 검증하는 습관이 필요하다.
- 핵심 포인트: 횟수를 DP 차원으로 삼고, 횟수별로 도달 가능한 수의 집합을 채워 나간다. number가 처음 등장하는 횟수가 곧 최솟값이다.
- 개선: 값을 리스트가 아니라 집합에 저장해 중복된 식을 하나로 합쳐, 조합 폭발을 막았다. Java에서는 중간 곱셈 오버플로를 막기 위해 long을 썼다.

- 공간 복잡도: O(S) — 횟수별 집합 8개를 유지한다.

## 요약

N을 쓰는 횟수를 차원으로 삼아, 각 횟수로 만들 수 있는 수의 집합을 이어붙인 수와 분할 조합으로 채워 나간다. number가 처음 등장하는 횟수가 최솟값이고, 8회까지 등장하지 않으면 -1이다. 집합으로 중복을 제거하는 것이 이 풀이의 성능을 지탱한다.
