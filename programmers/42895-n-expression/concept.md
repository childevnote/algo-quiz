# 개념 정리: 횟수를 차원으로 삼는 DP와 집합 기반 상태 저장

## 비용을 차원으로 삼는 동적 프로그래밍

동적 프로그래밍에서는 보통 "입력의 크기"나 "목표 합" 같은 값을 차원으로 삼는다. 하지만 "어떤 자원을 몇 번 썼는가"처럼 비용 자체를 차원으로 삼을 수도 있다. 각 비용마다 도달 가능한 결과들을 모아두고, 비용이 작은 쪽부터 차례로 채우면, 원하는 결과가 처음 등장하는 비용이 곧 최소 비용이 된다.

이 방식이 성립하려면 작은 비용의 결과가 큰 비용의 결과를 만드는 재료가 되어야 한다. 즉, 비용 k의 결과는 비용 k보다 작은 결과들의 조합으로 표현되어야 한다. 그래야 비용을 오름차순으로 채우는 것만으로 모든 결과를 빠짐없이 얻을 수 있다.

### 일반 예시: 동전 개수로 만들 수 있는 합

```python
def reachable_sums(coins, max_count):
    # 동전을 최대 max_count개까지 써서 만들 수 있는 합들의 집합 (개수별)
    dp = [set() for _ in range(max_count + 1)]
    dp[0].add(0)
    for i in range(1, max_count + 1):
        for c in coins:
            for s in dp[i - 1]:
                dp[i].add(s + c)
    return dp
```

이 코드에서 `dp[i]`는 동전을 정확히 i개 써서 만들 수 있는 합들의 집합이다. i개를 쓰는 방법은 "i-1개로 만든 합에 동전 하나를 더하는 것"이므로, 작은 i부터 채우면 된다. 어떤 합이 처음 등장하는 i가 그 합을 만드는 최소 동전 개수다.

## 집합으로 상태를 저장하는 이유

같은 결과에 도달하는 방법이 여러 가지일 때, 방법 자체를 모두 저장하면 상태가 폭발한다. 결과가 같다면 이후의 계산에서는 방법이 달라도 같은 취급을 받으므로, 결과만 집합에 저장하고 방법은 버리는 것이 합리적이다. 집합은 중복을 자동으로 합쳐 주기 때문에, 서로 다른 식이 같은 값을 만드는 경우를 하나로 줄여 준다.

단, 이 압축이 성립하려면 "결과만으로 이후 계산이 완전히 결정되어야" 한다. 예를 들어, 이후 단계에서 "지금까지 쓴 연산의 종류"가 추가로 필요하다면 결과만으로는 부족하다. 그런 경우에는 집합의 원소에 부가 정보를 함께 담아야 한다.

### 일반 예시: 중복 제거가 만드는 차이

```python
# 리스트에 쌓으면 중복이 그대로 남는다
results = []
for a in [1, 2, 3]:
    for b in [1, 2, 3]:
        results.append(a + b)   # 2, 3, 4, 3, 4, 5, 4, 5, 6 (9개)

# 집합에 넣으면 같은 값은 하나로 합쳐진다
results = set()
for a in [1, 2, 3]:
    for b in [1, 2, 3]:
        results.add(a + b)      # {2, 3, 4, 5, 6} (5개)
```

조합의 가지수가 곱으로 늘어나는 문제에서는 이 차이가 누적되어, 리스트 방식이 감당할 수 없는 크기로 불어나는 것을 집합 방식은 억제한다.

## 분할 조합: 큰 문제를 작은 문제의 조합으로

어떤 대상을 만드는 데 비용이 k가 든다면, 그 대상을 두 부분으로 나누었을 때 각 부분의 비용은 k보다 작다. 이 성질을 이용하면 비용 k의 결과 집합을, 비용이 k보다 작은 집합들의 쌍을 조합해 만들 수 있다. 모든 분할을 시도해야 빠짐없이 얻을 수 있다.

조합 연산이 교환법칙을 만족하지 않으면 순서가 바뀐 쌍도 따로 계산해야 한다. 예를 들어 뺄셈 `a - b`와 `b - a`는 다른 값이므로, 순서쌍 `(a, b)`와 `(b, a)`를 모두 고려해야 한다. 분할 인덱스를 한쪽 방향으로만 순회하면서 순서쌍을 모두 만드는 방법이 자주 쓰인다. 분할이 `(j, k-j)`와 `(k-j, j)`를 모두 거치므로, 각 쌍에서 한 방향의 연산만 계산해도 반대 방향은 다른 분할에서 처리된다.

### 일반 예시: 문자열 분할 조합

```python
def combine(parts):
    # parts[i]: 비용 i로 만들 수 있는 문자열들의 집합
    n = len(parts) - 1
    for k in range(1, n + 1):
        for j in range(1, k):
            for a in parts[j]:
                for b in parts[k - j]:
                    parts[k].add(a + b)
                    parts[k].add(b + a)  # 순서가 중요하면 양쪽 모두
    return parts
```

## 정수 나눗셈의 두 가지 규칙

정수 나눗셈에서 음수가 개입하면 "버림(floor)"과 "0 쪽으로 자르기(truncation)"가 다른 결과를 낸다. 예를 들어 `-7 / 2`는 버림이면 -4, 0 쪽으로 자르면 -3이다. 양수끼리의 나눗셈에서는 두 규칙이 같으므로 차이가 드러나지 않지만, 뺄셈 등으로 음수가 만들어질 수 있는 문제에서는 규칙을 하나로 정해 두 언어가 같은 답을 내도록 맞춰야 한다.

- Python의 `//`는 버림이다.
- Java의 `/`는 0 쪽으로 자르기이고, `Math.floorDiv`가 버림이다.
- C/C++의 `/`도 0 쪽으로 자르기이다.

문제를 풀 때는 어느 규칙을 쓸지 먼저 정하고, 두 언어로 풀이를 작성할 때는 그 규칙을 일치시키는 것이 중요하다.
