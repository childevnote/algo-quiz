# 사칙연산

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1843
- 레벨: Lv.4
- 카테고리: DP

## 문제 핵심 요약

숫자와 `+`, `-` 연산자가 번갈아 들어 있는 배열이 주어진다. 덧셈은 결합법칙이 성립하지만 뺄셈은 그렇지 않으므로, 연산 순서(괄호를 치는 위치)에 따라 계산 결과가 달라진다. 가능한 모든 연산 순서 중 가장 큰 결과값을 구한다.

핵심 제한사항: 숫자는 2개 이상 101개 이하, 각 숫자는 1 이상 1,000 이하. 배열 길이는 항상 홀수이며 첫 원소와 마지막 원소는 숫자이다.

입출력 예:

| arr | result |
| --- | --- |
| `["1", "-", "3", "+", "5", "-", "8"]` | 1 |
| `["5", "-", "3", "+", "1", "+", "2", "-", "4"]` | 3 |

예1은 `1 - (3 + (5 - 8)) = 1`일 때 최댓값 1이 되고, 예2는 `5 - (3 + ((1 + 2) - 4)) = 3`일 때 최댓값 3이 된다.

## 문제 분석 및 핵심 로직

이 문제는 구간을 어떻게 나누느냐가 곧 연산 순서를 정하는 문제이다. 식 전체를 한 번에 계산하는 대신, 구간 `[i, j]`에 대해 "이 구간을 어떤 순서로 계산했을 때 나올 수 있는 최댓값과 최솟값"을 구해 두면, 더 큰 구간은 작은 구간의 결과를 조합해서 만들 수 있다.

핵심은 두 가지이다.

첫째, **최댓값만으로는 부족하고 최솟값도 함께 구해야 한다.** 덧셈은 단조적이라 최대끼리, 최소끼리 더하면 되지만, 뺄셈은 뒤쪽 구간이 작을수록 전체가 커진다. 즉 `A - B`의 최댓값은 `A의 최댓값 - B의 최솟값`이다. 최솟값을 모르면 뺄셈 구간의 최댓값을 만들 수 없다. 반대로 최솟값은 `A의 최솟값 - B의 최댓값`으로 구한다.

둘째, **구간 길이가 짧은 것부터 채운다.** 길이 2인 구간부터 시작해 길이를 하나씩 늘려 가면, 길이 `L`인 구간을 계산할 때 그 안의 모든 짧은 구간 값은 이미 테이블에 들어 있다. 마지막 연산 위치 `k`를 기준으로 구간을 `[i, k]`와 `[k+1, j]`로 나누고, 연산자가 `+`인지 `-`인지에 따라 위 규칙으로 조합한다.

## 개념별 심층 설명

### 초심자 방식: 모든 괄호 경우를 직접 세어 보기

숫자가 `n`개면 괄호를 치는 경우의 수는 카탈란 수로 늘어난다. `n = 101`이면 경우의 수가 천문학적이라, 모든 순서를 재귀나 완전탐색으로 세는 방식은 시간 안에 끝나지 않는다. 예제처럼 숫자가 4개일 때는 5가지 경우만 세면 되지만, 입력이 커지면 그대로 쓸 수 없다.

### 개선 방식: 구간 DP — 겹치는 부분 문제 재사용

같은 구간 `[i, j]`는 더 큰 식을 계산할 때 여러 번 등장한다. 예를 들어 `1 - 3 + 5 - 8`에서 구간 `3 + 5`의 결과는 전체를 어떻게 나누든 동일하게 쓰인다. 그래서 구간별 최댓값·최솟값을 한 번만 계산해 테이블에 저장하고 재사용한다. 구간이 겹치는 구조라 DP가 맞고, 부분 문제의 답이 전체 문제의 답을 만드는 최적 부분 구조가 성립한다.

### 왜 최대와 최소를 같이 저장하는가

뺄셈이 단조성을 깨뜨리기 때문이다. `A - B`에서 `B`가 커지면 결과는 작아지고, `B`가 작아지면 결과는 커진다. 그래서 최댓값을 만들 때 뒤쪽 구간의 최솟값이 필요하고, 최솟값을 만들 때 뒤쪽 구간의 최댓값이 필요하다. 덧셈만 있는 문제였다면 최댓값 테이블 하나로 충분했을 것이다. 이 "반전"이 이 문제의 유일한 함정이다.

## 최종 솔루션 코드

### Python

```python
def solution(arr):
    # 1. 숫자와 연산자를 분리한다 (arr는 숫자, 연산자, 숫자, ... 형태)
    nums = [int(arr[i]) for i in range(0, len(arr), 2)]
    ops = [arr[i] for i in range(1, len(arr), 2)]
    n = len(nums)

    # 2. 구간 [i, j]의 최댓값/최솟값을 저장하는 DP 테이블
    NEG = float('-inf')
    POS = float('inf')
    mx = [[NEG] * n for _ in range(n)]
    mn = [[POS] * n for _ in range(n)]
    for i in range(n):
        mx[i][i] = mn[i][i] = nums[i]

    # 3. 길이가 짧은 구간부터 채운다
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            # 4. 마지막 연산 위치 k로 구간을 둘로 나눈다
            for k in range(i, j):
                if ops[k] == '+':
                    # 5a. 덧셈: 최대+최대, 최소+최소
                    mx[i][j] = max(mx[i][j], mx[i][k] + mx[k + 1][j])
                    mn[i][j] = min(mn[i][j], mn[i][k] + mn[k + 1][j])
                else:
                    # 5b. 뺄셈: 최대-최소, 최소-최대 (뺄셈은 뒤쪽이 작을수록 커진다)
                    mx[i][j] = max(mx[i][j], mx[i][k] - mn[k + 1][j])
                    mn[i][j] = min(mn[i][j], mn[i][k] - mx[k + 1][j])

    return mx[0][n - 1]
```

### Java

```java
import java.util.Arrays;

class Solution {
    public int solution(String[] arr) {
        int n = (arr.length + 1) / 2;
        int[] nums = new int[n];
        char[] ops = new char[n - 1];
        for (int i = 0; i < n; i++) nums[i] = Integer.parseInt(arr[2 * i]);
        for (int i = 0; i < n - 1; i++) ops[i] = arr[2 * i + 1].charAt(0);

        int[][] mx = new int[n][n];
        int[][] mn = new int[n][n];
        for (int i = 0; i < n; i++) {
            mx[i][i] = mn[i][i] = nums[i];
        }
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                mx[i][j] = Integer.MIN_VALUE;
                mn[i][j] = Integer.MAX_VALUE;
                for (int k = i; k < j; k++) {
                    if (ops[k] == '+') {
                        mx[i][j] = Math.max(mx[i][j], mx[i][k] + mx[k + 1][j]);
                        mn[i][j] = Math.min(mn[i][j], mn[i][k] + mn[k + 1][j]);
                    } else {
                        mx[i][j] = Math.max(mx[i][j], mx[i][k] - mn[k + 1][j]);
                        mn[i][j] = Math.min(mn[i][j], mn[i][k] - mx[k + 1][j]);
                    }
                }
            }
        }
        return mx[0][n - 1];
    }
}
```

## 성능 측정

- 시간복잡도: O(n³) — 구간 O(n²)개 × 분할 위치 O(n)개. n ≤ 101이라 최대 약 100만 번 연산이다.
- 공간복잡도: O(n²) — 최댓값·최솟값 테이블 2개.
- 로컬 실측 (숫자 101개, 최대 크기 무작위 입력):
  - Python: 예제 케이스 약 0.009ms, 최대 크기 0.081초, 피크 메모리 약 488KB
  - Java: 최대 크기 약 12.8ms
- 검증: 예제 2건 통과, 숫자 2~8개 무작위 입력 200건에 대해 모든 괄호 경우를 세는 전수 탐색 결과와 일치 확인.

참고: 이 문제는 숫자 개수가 최대 101개로 제한돼 있어 n=100,000 규모의 스케일 테스트는 적용되지 않는다. 위 측정은 제한 내 최대 입력 기준이다.

## 학습 노트

- 막혔던 점: 없음. 이 풀이는 18:00 자동 풀이로 진행됐으며, 사용자가 풀지 않은 문제를 대신 풀고 커밋한 것이다.
- 핵심 포인트: 뺄셈 때문에 최댓값만으로는 부족하다. 구간의 최댓값과 최솟값을 함께 저장해야 `A - B`의 최댓값을 `A의 최대 - B의 최소`로 만들 수 있다.
- 개선: 모든 괄호 경우를 세는 완전탐색(O(카탈란 수)) 대신 구간 DP(O(n³))로 바꿔, 최대 입력에서도 0.1초 이내에 끝난다.

## 요약

사칙연산은 구간 DP 문제이다. 구간별 최댓값과 최솟값을 함께 저장하고, 길이가 짧은 구간부터 채워 나가며 마지막 연산 위치로 나눠 조합한다. 덧셈은 최대끼리·최소끼리, 뺄셈은 최대에서 최소를 빼는 식으로 조합하면 전체 식의 최댓값을 얻을 수 있다.
