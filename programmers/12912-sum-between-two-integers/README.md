# 두 정수 사이의 합

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12912
- 레벨: Lv.1
- 카테고리: 연습문제

## 문제 핵심 요약

두 정수 `a`, `b`가 주어졌을 때, `a`와 `b` 사이에 속한 모든 정수의 합을 구한다. 두 수의 대소관계는 정해져 있지 않다.

- 제한사항: `a`와 `b`가 같은 경우 둘 중 아무 수나 리턴, `-10,000,000 ≤ a, b ≤ 10,000,000`
- 입출력 예: `(3, 5) → 12`, `(3, 3) → 3`, `(5, 3) → 12`

## 문제 분석 및 핵심 로직

`a`부터 `b`까지의 모든 정수를 하나씩 더하는 풀이가 먼저 떠오른다. 구간 길이가 최대 2천만 개까지 커질 수 있어 반복 횟수가 입력 크기에 비례한다. 그런데 이 구간은 공차가 1인 등차수열이므로, 항의 개수와 첫 항·끝 항만 알면 합을 한 번의 식으로 구할 수 있다.

작은 쪽을 `lo`, 큰 쪽을 `hi`라 두면 항의 개수는 `n = hi - lo + 1`이고, 합은 `n * (lo + hi) / 2`이다. `n * (lo + hi)`는 항상 짝수라서 정수 나눗셈이 안전하다. `n`이 홀수이면 `lo`와 `hi`의 홀짝이 같아 `lo + hi`가 짝수이고, `n`이 짝수이면 `n` 자체가 짝수이기 때문이다.

주의할 점은 합의 크기이다. 구간이 `-10,000,000`부터 `10,000,000`까지이면 합은 0이지만, 한쪽으로 치우친 구간(예: `0`부터 `10,000,000`까지)의 합은 약 5×10¹³으로 32비트 정수 범위(약 ±2.1×10⁹)를 크게 넘는다. Java에서는 `long`으로 계산해야 하고, Python은 임의 정밀도 정수라 별도 처리가 필요 없다.

## 개념별 심층 설명

### 초심자 방식: 구간을 하나씩 더하기

`lo`부터 `hi`까지 반복문으로 누적하거나 `sum(range(lo, hi + 1))`로 합산한다. 직관적이고 틀릴 여지가 적지만, 시간복잡도는 O(n)으로 구간 길이에 비례한다. 구간이 10만 개일 때는 1.69 ms, 최대 구간(2천만 개)일 때는 339.8 ms가 걸린다(Python 실측). 제한 내에서는 동작하지만, 입력이 커질수록 선형으로 느려진다.

### 개선 방식: 등차수열의 합 공식

첫 항과 끝 항을 짝지어 더하면 모든 쌍의 합이 같아진다. `1`부터 `100`까지의 합을 예로 들면 `1 + 100 = 101`, `2 + 99 = 101`, ... 과 같이 50개의 쌍이 모두 101이 되므로 합은 `101 × 50 = 5050`이다. 일반적으로 `n`개의 항을 가진 등차수열의 합은 `n × (첫 항 + 끝 항) / 2`이다.

이 방식은 구간 길이에 관계없이 상수 시간에 답을 낸다. 같은 최대 구간 실측은 Python 기준 1회 약 0.24 µs로, 반복 합산 방식보다 100만 배 이상 빠르다. 항의 개수가 1개(`a == b`)인 경우에도 공식이 그대로 성립해 별도 분기가 필요 없다.

## 최종 솔루션 코드

### Python

```python
def solution(a, b):
    # 1. a와 b의 대소관계가 정해져 있지 않으므로 작은 쪽을 lo, 큰 쪽을 hi로 둔다.
    # 2. lo부터 hi까지의 합은 등차수열의 합: 항의 개수 n = hi - lo + 1,
    #    합 = n * (lo + hi) / 2. n * (lo + hi)는 항상 짝수이므로 정수 나눗셈이 안전하다.
    lo, hi = (a, b) if a <= b else (b, a)
    n = hi - lo + 1
    return n * (lo + hi) // 2
```

### Java

```java
class Solution {
    public long solution(int a, int b) {
        // 1. a와 b의 대소관계가 정해져 있지 않으므로 작은 쪽을 lo, 큰 쪽을 hi로 둔다.
        // 2. lo부터 hi까지의 합은 등차수열의 합: 항의 개수 n = hi - lo + 1,
        //    합 = n * (lo + hi) / 2. n * (lo + hi)는 항상 짝수이므로 정수 나눗셈이 안전하다.
        // 3. a, b가 ±10,000,000까지 가능하므로 합은 int 범위를 넘을 수 있어 long으로 계산한다.
        long lo = Math.min(a, b);
        long hi = Math.max(a, b);
        long n = hi - lo + 1;
        return n * (lo + hi) / 2;
    }
}
```

Java에서 `long`으로 변환하는 이유는 합의 범위가 `int`를 넘기 때문이다. `a = 0, b = 10,000,000`인 경우 합은 약 5×10¹³으로, `int` 연산으로 계산하면 오버플로가 난다. `Math.min`/`Math.max`에 `int`를 넣고 `long`으로 받는 시점에서 이미 64비트 연산이 되므로 이후 곱셈도 안전하다.

- 시간복잡도: O(1) — 등차수열 합 공식을 한 번 계산
- 공간복잡도: O(1) — 변수 몇 개만 사용

## 요약

- 핵심 아이디어: `lo`부터 `hi`까지의 합은 등차수열의 합 `n * (lo + hi) / 2`로 한 번에 구할 수 있다.
- `n * (lo + hi)`는 항상 짝수이므로 정수 나눗셈이 안전하다.
- 합의 크기가 `int` 범위를 넘을 수 있으므로 Java에서는 `long`으로 계산한다.
- 시간복잡도는 O(1), 공간복잡도는 O(1)이다.
