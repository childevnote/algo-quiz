## 문제 핵심 요약

숫자 문자열에서 정확히 k개의 자리수를 제거하되, 남은 자리들의 상대 순서는 그대로 유지하면서 만들 수 있는 가장 큰 수를 구한다.

- 핵심 제한사항: 숫자 길이는 2자리 이상 1,000,000자리 이하, k는 1 이상 자릿수 미만.
- 입출력 예: `"1924", k=2 → "94"`, `"1231234", k=3 → "3234"`, `"4177252841", k=4 → "775841"`.

## 문제 분석 및 핵심 로직

자릿수가 같은 수끼리는 앞자리부터 비교해서 먼저 달라지는 자리가 큰 쪽이 전체로도 크다. 따라서 "어느 자리를 지울 것인가"는 "앞자리를 얼마나 크게 만들 것인가"로 귀결된다.

앞자리를 크게 만드는 방법은 하나다. 왼쪽에서 오른쪽으로 숫자를 훑으면서, 현재 숫자보다 작은 앞자리 숫자는 제거 기회 안에서 지운다. 작은 앞자리를 남겨두는 선택은 그 자리가 그대로 비교의 기준이 되어 전체 수를 작게 만들기 때문에, 그 선택이 포함된 답은 항상 더 큰 답으로 교체할 수 있다. 이것이 탐욕 선택이 최적임을 보장하는 이유다.

제거 기회가 끝까지 남았다는 것은 숫자가 끝까지 내림차순이었다는 뜻이다. 이 경우에는 뒤에서 자르는 것이 손해가 가장 작다. 뒤쪽 자리는 앞자리 비교에 영향을 주지 않기 때문이다.

## 개념별 심층 설명

### 1. 초심자 방식: 모든 조합을 따져보기

k개를 골라 제거하는 모든 경우를 열거하면 조합 수가 폭발한다. 길이가 n일 때 경우의 수는 이항 계수 수준으로 커지므로, n이 수십만까지 커지는 이 문제에서는 아예 성립하지 않는다.

### 2. 개선 방식: 단조 감소 스택

스택에 숫자를 쌓되, 스택이 항상 내림차순을 유지하도록 관리한다.

- 동작 원리: 현재 숫자 `d`가 들어올 때, 스택 상단이 `d`보다 작으면 그 상단은 `d`보다 앞자리에서 더 작은 값을 차지하고 있는 셈이다. 제거 기회가 남아 있다면 상단을 제거하고 `d`를 더 앞자리로 끌어오는 편이 전체 수를 키운다. 상단이 `d`보다 크거나 같아질 때까지, 또는 제거 기회가 떨어질 때까지 반복한다.
- 왜 안 되는 방식이 있는지: 앞에서부터 "가장 큰 숫자 하나를 고르고, 나머지를 재귀적으로" 푸는 방식도 논리적으로는 맞지만, 매번 남은 구간에서 최댓값을 찾는 비용이 들고 구현이 복잡해진다. 스택은 한 번의 순회로 같은 판단을 수행한다.
- 엣지 케이스: `"1000", k=1`처럼 제거 기회가 남는 경우, 뒤에서 자르면 `"100"`이 된다. 앞의 `1`을 지우는 선택(`"000"`)보다 크다. `"987654321"`처럼 이미 내림차순이면 제거 자체가 뒤에서만 일어나고, 앞자리는 그대로 유지된다.

## 최종 솔루션 코드

### Python

```python
def solution(number, k):
    # 1. 단조 감소 스택: 현재 숫자보다 작은 스택 상단은 제거 기회 안에서 제거한다.
    stack = []
    for digit in number:
        while k > 0 and stack and stack[-1] < digit:
            stack.pop()
            k -= 1
        stack.append(digit)
    # 2. 제거 기회가 남았으면 뒤에서 자른다.
    if k > 0:
        stack = stack[:-k]
    # 3. 남은 스택을 그대로 이어붙인다.
    return "".join(stack)
```

### Java

```java
class Solution {
    public String solution(String number, int k) {
        // 1. 단조 감소 스택: char 배열을 스택으로 쓰고, 현재 숫자보다 작은 상단은 제거한다.
        char[] stack = new char[number.length()];
        int top = 0;
        for (int i = 0; i < number.length(); i++) {
            char digit = number.charAt(i);
            while (k > 0 && top > 0 && stack[top - 1] < digit) {
                top--;
                k--;
            }
            stack[top++] = digit;
        }
        // 2. 제거 기회가 남았으면 뒤에서 자른다.
        top -= k;
        // 3. 남은 구간을 문자열로 만든다.
        return new String(stack, 0, top);
    }
}
```

## 학습 노트

- 막혔던 점: 해당 없음. 18:00 자동 풀이로 직접 풀었으며, 예제 3건과 엣지 케이스(`"1000"`, `"10"`, 내림차순, 동일 숫자 연속)가 모두 통과했다.
- 핵심 포인트: 앞자리가 클수록 전체 수가 크다는 자릿수 비교 원리, 그리고 그 원리를 한 번의 순회로 구현하는 단조 감소 스택.
- 개선: 조합 열거가 아니라 스택 한 번 순회로 선형 시간에 해결했다.

## 성능 측정

로컬 실측 결과다.

- 예제 케이스 3건: 1,000회 반복 기준 1세트당 약 0.004ms (Python).
- n=100,000 무작위 숫자, k=50,000: Python 0.0420초, 피크 메모리 약 484KiB (tracemalloc 기준), Java 0.0147초, 결과 길이 50,000.
- 시간 복잡도: O(n). 각 숫자는 스택에 최대 한 번 들어가고 한 번 나가기 때문이다.
- 공간 복잡도: O(n). 스택이 답의 길이를 차지한다.

## 요약

앞자리를 크게 만드는 탐욕 선택을 단조 감소 스택으로 구현하면, 한 번의 순회로 가장 큰 수를 만들 수 있다. 제거 기회가 남으면 뒤에서 자르는 것이 손해가 가장 작다.
