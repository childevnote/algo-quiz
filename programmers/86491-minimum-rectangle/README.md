## 문제 분석 및 핵심 로직

모든 명함을 수납할 수 있는 가장 작은 지갑의 크기를 구하는 문제다. 각 명함은 90도 회전이 가능하다.

**핵심 조건:**

1. **회전 가능:** 명함을 눕히거나 세울 수 있다. 가로/세로가 고정된 것이 아니다.
2. **지갑은 직사각형:** 모든 명함을 동시에 수납해야 하므로, 지갑의 가로는 모든 명함의 가로 중 최댓값 이상, 세로는 모든 명함의 세로 중 최댓값 이상이어야 한다.
3. **최소 면적:** 가로 최댓값 × 세로 최댓값이 답이다.

## 회전하지 않고 구하면 생기는 문제

각 명함을 주어진 방향 그대로 둔다고 생각해 보자. 예제 1의 2번 명함 [30, 70]은 세로가 70이므로, 지갑의 세로는 최소 70이 되어야 한다. 다른 명함들의 가로 최댓값은 80이므로 지갑 크기는 80 × 70 = 5600이 된다.

하지만 2번 명함을 눕히면 [70, 30]이 되어 세로 최댓값이 50으로 줄어든다. 지갑 크기는 80 × 50 = 4000이다. 회전을 고려하지 않으면 불필요하게 큰 지갑이 나온다.

## 모든 명함을 한 방향으로 정렬하는 아이디어

핵심은 "가로는 가로끼리, 세로는 세로끼리 비교해야 한다"는 점이다. 각 명함마다 긴 쪽을 가로, 짧은 쪽을 세로로 통일하면, 회전의 모든 경우를 따지지 않아도 된다.

왜 이게 맞는가? 지갑의 가로 W는 모든 명함의 가로(회전 후) 중 최댓값 이상이어야 하고, 세로 H도 마찬가지다. 각 명함을 긴 쪽이 가로가 되도록 놓으면, 가로들의 최댓값과 세로들의 최댓값이 각각 최소가 된다. 긴 쪽을 세로로 세우는 선택은 세로 최댓값만 키울 뿐 이득이 없다.

```python
# [30, 70] → 긴 쪽(70)을 가로로
w, h = max(30, 70), min(30, 70)  # w=70, h=30
```

따라서 풀이는 한 번의 순회로 끝난다. 각 명함을 정규화(긴 쪽 → 가로)한 뒤 가로 최댓값과 세로 최댓값을 구하고 곱한다.

## 최종 솔루션 코드

```python
def solution(sizes):
    max_w = 0
    max_h = 0
    for w, h in sizes:
        # 1. 각 명함을 회전시켜 긴 쪽을 가로로 눕히기
        w, h = max(w, h), min(w, h)
        # 2. 지금까지 본 명함 중 가장 긴 가로/세로 갱신
        max_w = max(max_w, w)
        max_h = max(max_h, h)
    # 3. 가장 작은 지갑의 크기
    return max_w * max_h
```

```java
class Solution {
    public int solution(int[][] sizes) {
        int maxW = 0;
        int maxH = 0;
        for (int[] s : sizes) {
            // 1. 각 명함을 회전시켜 긴 쪽을 가로로 눕히기
            int w = Math.max(s[0], s[1]);
            int h = Math.min(s[0], s[1]);
            // 2. 지금까지 본 명함 중 가장 긴 가로/세로 갱신
            maxW = Math.max(maxW, w);
            maxH = Math.max(maxH, h);
        }
        // 3. 가장 작은 지갑의 크기
        return maxW * maxH;
    }
}
```

## 요약

1. 회전 가능한 직사각형 문제는 각 도형을 "긴 쪽 → 가로"로 정규화하면 회전의 경우의 수를 따질 필요가 없다.
2. 지갑 크기는 정규화된 가로들의 최댓값 × 세로들의 최댓값이다.
3. 추가 메모리가 필요 없는 O(n) 한 번 순회로 해결된다.
