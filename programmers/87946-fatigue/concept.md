# 개념 정리 — 피로도 (백트래킹 완전탐색)

이 문제에 필요한 일반 개념만 정리한다.

## 순열 기반 완전탐색

n개의 대상을 나열하는 모든 순서(순열)는 n!가지다. n이 8이면 40,320가지로, 컴퓨터가 전부 시도해 볼 수 있는 수준이다. "순서에 따라 결과가 달라지는" 문제에서 특정 휴리스틱(탐욕 정렬 등)이 정답을 보장하지 못하면, n! 전수탐색이 가장 확실한 방법이 된다. n이 커지면 지수 폭발이 일어나므로 보통 n ≤ 8~10인 문제에만 적용한다.

```python
from itertools import permutations

def all_orders(items):
    for order in permutations(range(len(items))):
        # order는 가능한 순서 중 하나
        yield order
```

## 백트래킹

재귀적으로 선택을 쌓아 나가다가, 더 이상 진행할 수 없거나 답을 찾으면 한 단계 되돌아가 다른 선택을 시도하는 탐색 기법이다. 핵심은 "상태 복원"이다. 분기로 내려갈 때 변경한 상태(방문 표시, 남은 자원 등)를 복귀 시 원래대로 돌려놓아야 다른 분기가 깨끗한 상태에서 시작한다.

```python
def backtrack(state, chosen):
    for option in candidates(state):
        apply(state, option)       # 선택 적용
        backtrack(state, chosen + [option])  # 다음 단계로
        undo(state, option)        # 상태 원복 ← 백트래킹의 핵심
```

## 가지치기 (pruning)

전체 경우의 수를 다 도는 완전탐색에서도, 답이 될 수 없는 분기는 일찍 잘라낼 수 있다. 예를 들어 "현재 피로도로 입장할 수 없는 던전은 건너뛴다"는 분기 자체를 만들지 않으므로 실제 탐색 노드는 n!보다 적어진다. 또 "남은 던전을 전부 탐험해도 현재 최댓값을 넘지 못하면 중단" 같은 최적화도 가능하다. 이 문제에서는 입장 조건 자체가 자연스러운 가지치기 역할을 한다.

## 탐욕 선택과 완전탐색의 경계

"지금 가능한 것 중 가장 좋아 보이는 것을 고른다"는 탐욕 선택은 선택이 이후 단계에 미치는 영향이 단조적일 때만 안전하다. 이 문제처럼 입장 조건(최소 필요 피로도)과 실제 비용(소모 피로도)이 따로 노는 경우, 지금의 최선 선택이 나중에 발목을 잡을 수 있어 탐욕이 깨진다. 순서에 따라 결과가 바뀌고 n이 작으면 탐욕을 버리고 완전탐색으로 가는 것이 정석이다.
