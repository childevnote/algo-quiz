# 올바른 괄호

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/12909
- 레벨: Lv.2 · 카테고리: 스택/큐
- 풀이 날짜: 2026-10-11

## 문제 분석 및 핵심 로직

`(`와 `)`로만 이루어진 문자열이 올바르게 짝지어졌는지 판정하는 문제다.
올바른 괄호의 조건은 두 가지다. 첫째, 문자열을 왼쪽부터 읽으면서 닫는 괄호 `)`가
여는 괄호 `(`보다 먼저 나타나는 지점이 없어야 한다(접두 조건). 둘째, 전체를 다 읽었을 때
여는 괄호와 닫는 괄호의 개수가 같아야 한다(잔여 조건).

이를 하나의 카운터로 처리할 수 있다. `(`를 만나면 1을 더하고, `)`를 만나면 1을 뺀다.
카운터는 "아직 닫히지 않은 열린 괄호의 수"를 의미한다. 순회 중 카운터가 음수가 되면
닫을 수 있는 열린 괄호보다 닫는 괄호가 먼저 나온 것이므로 즉시 `False`를 반환한다.
순회를 마치고 카운터가 0이면 두 개수가 일치하므로 `True`다.

물리적인 스택을 쓰지 않아도 되는 이유: 열린 괄호의 종류가 `(` 한 가지뿐이라
"무엇이 열려 있는가"를 기억할 필요가 없고, "몇 개가 열려 있는가"만 알면 충분하다.
괄호 종류가 여러 개라면 스택이 필요해진다.

## 개념별 심층 설명

### 초심자 방식: 스택에 직접 쌓기

```python
stack = []
for c in s:
    if c == '(':
        stack.append(c)
    else:
        if not stack:
            return False
        stack.pop()
return not stack
```

동작 원리는 카운터 방식과 동일하다. `(`가 나올 때마다 push하고, `)`가 나올 때 pop한다.
pop할 때 스택이 비어 있으면 짝 없는 닫는 괄호이므로 실패, 끝까지 돌았는데 스택이 남아 있으면
짝 없는 여는 괄호이므로 실패다. 직관적이지만 최대 n개의 원소를 저장하므로 공간 복잡도가 O(n)이다.

### 개선 방식: 카운터로 치환

위에서 본 풀이처럼 스택에 저장되는 원소가 전부 `(`라면, 스택의 내용물은 사실상 크기만 중요하다.
push는 +1, pop은 -1, empty 검사는 0 이하 검사로 바꿀 수 있다. 공간 복잡도가 O(1)로 줄어든다.

### 동작 원리 (균형 카운터)

- `balance`: 현재까지 닫히지 않은 `(`의 개수 (불변식: 0 이상을 유지하다가 음수가 되는 순간 실패)
- 접두 조건을 순회 중에 검사하는 것이 포인트다. 접두 조건 없이 개수만 비교하면
  `")()("` 같은 입력(개수는 맞지만 순서가 틀림)을 잘못 통과시킨다.

### 왜 안 되는가: 순수 개수 비교

`count('(') == count(')')`만 검사하면 `")()("`에서 2 == 2이므로 True가 나와 버린다.
괄호 문제는 순서의 문제이므로 접두 조건이 반드시 필요하다.

## 최종 솔루션 코드

핵심 로직 번호: ① 열린 괄호 카운트 증가 ② 닫는 괄호 카운트 감소 ③ 음수 즉시 실패 ④ 최종 0 검사

### Python

```python
def solution(s):
    balance = 0
    for c in s:
        if c == '(':      # ①
            balance += 1
        else:             # ②
            balance -= 1
            if balance < 0:  # ③
                return False
    return balance == 0  # ④
```

### Java

```java
class Solution {
    boolean solution(String s) {
        int balance = 0;
        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) == '(') {  // ①
                balance++;
            } else {                    // ②
                if (--balance < 0) {     // ③
                    return false;
                }
            }
        }
        return balance == 0;  // ④
    }
}
```

## 성능 측정

- 시간 복잡도: O(n) — 문자열을 한 번만 순회
- 공간 복잡도: O(1) — 카운터 변수 하나
- 로컬 실측 (n=100,000, 모두 열린 괄호 5만 + 닫는 괄호 5만):
  - Python: 약 0.0064초
  - Java: 약 0.0076초
- 빠른 실패 케이스(n=100,000 랜덤 문자열): Python 약 0.0001초 — 음수가 되는 지점에서 즉시 종료되므로 평균적으로 훨씬 빠르다.

## 요약

괄호 한 종류뿐이라면 스택이 아니라 카운터 하나로 충분하다.
접두 조건(순회 중 음수 검사)과 잔여 조건(최종 0 검사)을 분리해 생각하면
단일 순회 O(n), 추가 메모리 O(1)로 풀린다.
