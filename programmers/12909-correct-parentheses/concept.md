# 개념 정리: 스택과 카운터로의 치환

이 문제는 스택/큐 카테고리로 분류되지만, 실전 풀이는 스택 없이 카운터 하나로 처리한다.
여기에 등장하는 개념만 정리한다.

## 스택 (LIFO)

나중에 들어온 것이 먼저 나가는 구조. 괄호 매칭이 대표 예시다.

```python
stack = []
stack.append('A')  # push
stack.append('B')
top = stack.pop()  # pop -> 'B' (마지막에 넣은 것이 먼저 나옴)
```

## 괄호 검사의 접두 조건

문자열 전체에서 열린 괄호와 닫는 괄호의 개수가 같아도 순서가 틀리면 올바르지 않다.
따라서 왼쪽부터 읽어 나가며 어느 접두에서도 "닫는 괄호 > 여는 괄호"가 되지 않아야 한다.
이 조건을 검사하려면 문자열을 한 번 순회하면서 누적 개수를 추적해야 한다.

## 스택의 카운터 치환

스택에 저장되는 원소의 종류가 한 가지뿐이라면, 스택의 "내용물"은 사실상
원소의 개수(스택의 깊이)로 완전히 설명된다. 이때

- push → 카운터 +1
- pop → 카운터 -1
- 비어 있는지 검사 → 카운터가 0인지 검사

로 바꿀 수 있고, 공간 복잡도가 O(n)에서 O(1)로 줄어든다.
괄호 종류가 여러 개(예: `()`, `[]`, `{}`)라면 어떤 종류가 열려 있는지를 구분해야 하므로
이 치환이 성립하지 않고 진짜 스택이 필요하다.
