## 문제 핵심 요약

출발지점에서 distance만큼 떨어진 도착지점 사이에 바위들이 놓여 있다. 바위 중 n개를 제거한 뒤, 출발지점·남은 바위·도착지점 사이의 간격 중 가장 작은 값을 최대한 크게 만들고 싶다. 그 최댓값을 구한다.

핵심 제한사항:

- distance는 1 이상 1,000,000,000 이하
- 바위는 1개 이상 50,000개 이하
- n은 1 이상 바위 개수 이하

입출력 예:

| distance | rocks | n | return |
|---|---|---|---|
| 25 | [2, 14, 11, 21, 17] | 2 | 4 |

예 설명: 바위 2개와 14를 제거하면 남는 지점은 11, 17, 21이고, 간격은 11, 6, 4, 4가 되어 최소 거리가 4가 된다. 이것이 만들 수 있는 최소 거리 중 가장 큰 값이다.

## 문제 분석 및 핵심 로직

바위를 어떤 조합으로 제거할지 직접 따지는 것은 경우의 수가 너무 많다. 관점을 바꾼다. 답이 될 수 있는 최소 거리 값 m을 하나 정해 놓고, "최소 거리를 m 이상으로 만들 수 있는가"라는 yes/no 질문으로 바꿀 수 있다. 이 질문에는 답이 있다. 바위를 위치 순으로 보면서 간격이 m보다 작은 바위는 제거하고, 간격이 m 이상인 바위는 남긴다. 이렇게 탐욕적으로 제거한 개수가 n 이하이면 m은 달성 가능하다.

달성 가능성은 단조성을 가진다. m이 달성 가능하면 m보다 작은 값도 달성 가능하고, m이 불가능하면 m보다 큰 값도 불가능하다. 단조성이 있으면 이분탐색을 쓸 수 있다. 답의 범위는 1부터 distance까지이고, 이분탐색으로 가능한 가장 큰 m을 찾는다.

핵심 로직은 세 단계다.

1. 바위를 정렬하고 도착지점 distance를 마지막 지점으로 추가한다.
2. 정답 후보 m에 대해 이분탐색을 돌린다.
3. 각 m마다 바위를 왼쪽부터 훑으며 간격이 m보다 작으면 바위를 제거한 것으로 세고, 제거 개수가 n 이하이면 m을 달성 가능하다고 판정한다.

## 개념별 심층 설명

### 1. 정답에 대한 이분탐색 — 값을 직접 구하지 않고 판정 문제로 바꾼다

초심자 방식은 바위 중 n개를 고르는 모든 조합을 열거해 최소 거리를 계산하는 것이다. 바위가 50,000개면 조합의 수는 상상할 수 없을 만큼 커서 불가능하다. "최적의 제거 조합은 무엇인가"라는 질문 자체가 너무 크다.

개선 방식은 질문을 바꾸는 것이다. "최소 거리를 m으로 만들 수 있는가"라는 판정 문제로 바꾸면 답은 yes 아니면 no, 두 가지뿐이다. 그리고 이 판정에는 단조성이 있다. m=4가 가능하면 m=3도 가능하고, m=5가 불가능하면 m=6도 불가능하다. 단조적인 yes/no 경계는 이분탐색으로 찾을 수 있다. 이것이 "정답에 대한 이분탐색" 또는 "매개변수 탐색"이라 불리는 기법이다.

이분탐색의 범위를 정하는 것도 중요하다. 최소 거리는 최소 1, 최대 distance까지 가능하다. 바위를 전부 제거하면 남은 간격은 출발지점에서 도착지점까지 distance 하나뿐이라, 답이 distance를 넘을 수는 없다.

### 2. 탐욕적 판정 — 간격이 부족하면 그 바위를 버린다

판정 단계에서 핵심은 "m을 유지하기 위해 최소 몇 개의 바위를 제거해야 하는가"를 세는 것이다. 바위를 왼쪽부터 순서대로 본다. 마지막으로 남긴 지점 prev에서 현재 바위까지의 간격이 m보다 작으면, 이 바위는 남길 수 없다. 남기면 간격이 m 미만이 되어 조건을 어기기 때문이다. 그래서 이 바위를 제거한 것으로 세고 prev는 그대로 둔다. 간격이 m 이상이면 바위를 남기고 prev를 이 바위로 옮긴다.

왜 이것이 최소 제거 개수인가. 간격이 부족한 바위를 남기는 선택은 불가능하고, 그 바위를 제거하는 것 외에 다른 방법이 없다. 앞쪽 바위를 더 제거해 봤자 현재 간격을 늘릴 수 없기 때문이다. 남긴 바위 입장에서는, 조건을 만족하는 한 가장 왼쪽에 있는 바위를 남기는 것이 뒤쪽 간격을 넓게 유지하는 데 유리하다. 그래서 이 탐욕적인 훑기가 최소 제거 개수를 낸다.

도착지점은 제거할 수 없는 지점이므로, 마지막 간격(마지막 남은 바위에서 도착지점까지)이 m보다 작으면 어떻게 되는가. 코드에서는 도착지점을 지점 목록의 마지막 원소로 넣어 두었다. 마지막 간격이 m보다 작으면 도착지점을 "제거"한 것으로 세게 되는데, 이것은 실제로는 불가능한 제거이다. 하지만 제거 개수를 세는 관점에서는 결과가 같다. 마지막 간격이 m 미만이라는 것은 m을 달성하려면 마지막 바위(또는 도착지점 앞의 지점)를 더 제거해야 한다는 뜻인데, 도착지점은 제거할 수 없으므로 그만큼 앞쪽 바위를 제거해야 한다. 탐욕 훑기가 도착지점을 제거 대상으로 세는 것은, 제거 개수가 n을 초과하는 쪽으로 판정하는 것과 같아 m을 불가능하다고 판단하는 데는 문제가 없다. 다만 제거 개수가 n 이하인 경우에만 m을 가능하다고 보므로, 이 경계 처리는 답에 영향을 주지 않는다.

정확히 말하면, 판정은 "제거 개수가 n 이하"이다. n개까지 제거할 수 있으므로, 필요한 제거가 n개보다 적어도 m은 달성 가능하다. 남는 제거 횟수는 쓰지 않아도 된다.

### 3. 정렬 — 위치 순서가 전제이다

탐욕 판정은 바위를 위치 순서대로 훑는 것이 전제이다. 간격은 이웃한 지점 사이의 거리이므로, 순서가 뒤섞여 있으면 간격을 잴 수 없다. 그래서 판정 전에 바위를 정렬한다. 정렬 비용은 O(k log k)이며 한 번만 하면 된다. 이분탐색이 반복되는 동안 정렬된 배열을 그대로 재사용한다.

## 최종 솔루션 코드

### Python

```python
def solution(distance, rocks, n):
    # 1. 바위를 위치 순으로 정렬하고 도착지점을 마지막 지점으로 추가
    rocks = sorted(rocks)
    rocks.append(distance)

    # 2. 정답(제거 후 최소 거리)에 대한 이분탐색
    lo, hi = 1, distance
    answer = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        # 3. 최소 거리를 mid로 유지하려면 몇 개의 바위를 제거해야 하는지 셈
        removed = 0
        prev = 0  # 마지막으로 남긴 지점 (출발지점 0부터)
        for rock in rocks:
            if rock - prev < mid:
                removed += 1  # 간격이 부족하면 이 바위를 제거
            else:
                prev = rock  # 간격이 충분하면 이 바위를 남김
        # 4. 제거 개수가 n 이하이면 mid는 달성 가능 -> 더 큰 값 시도
        if removed <= n:
            answer = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return answer
```

### Java

```java
import java.util.Arrays;

class Solution {
    public int solution(int distance, int[] rocks, int n) {
        // 1. 바위를 위치 순으로 정렬하고 도착지점을 마지막 지점으로 추가
        Arrays.sort(rocks);
        int[] points = Arrays.copyOf(rocks, rocks.length + 1);
        points[rocks.length] = distance;

        // 2. 정답(제거 후 최소 거리)에 대한 이분탐색
        int lo = 1, hi = distance;
        int answer = 0;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            // 3. 최소 거리를 mid로 유지하려면 몇 개의 바위를 제거해야 하는지 셈
            int removed = 0;
            int prev = 0;  // 마지막으로 남긴 지점 (출발지점 0부터)
            for (int rock : points) {
                if (rock - prev < mid) {
                    removed++;  // 간격이 부족하면 이 바위를 제거
                } else {
                    prev = rock;  // 간격이 충분하면 이 바위를 남김
                }
            }
            // 4. 제거 개수가 n 이하이면 mid는 달성 가능 -> 더 큰 값 시도
            if (removed <= n) {
                answer = mid;
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return answer;
    }
}
```

## 학습 노트

- 막혔던 점: 없음. 이 문제는 조합을 직접 세는 것이 아니라 "최소 거리를 m으로 만들 수 있는가"라는 판정으로 바꾸는 전환이 핵심이다. 단조성이 보이면 정답에 대한 이분탐색을 떠올릴 수 있다.
- 핵심 포인트: 판정 단계의 탐욕이 최소 제거 개수를 낸다는 점이다. 간격이 부족한 바위는 남길 방법이 없으므로 제거가 강제되고, 조건을 만족하는 바위는 가장 왼쪽 것부터 남기는 것이 뒤쪽에 유리하다.
- 개선: 판정을 이분탐색 안에서 매번 O(k)로 수행하므로 전체 시간은 정렬을 제외하면 O(k log distance)이다. distance가 최대 10억이라 이분탐색은 약 30번 반복한다. k가 50,000이어도 충분히 여유가 있다.

## 성능 측정

로컬 실측 (2026-11-18).

| 케이스 | Python | Java |
|---|---|---|
| 입출력 예 (distance=25) | 0.012 ms | 0.388 ms |
| 바위 50,000개 무작위, distance=10억 | 112.45 ms (피크 메모리 585.9 KB) | 25.68 ms (힙 증가 266 KB) |

- 시간 복잡도: O(k log k + k log distance) — 정렬 O(k log k), 이분탐색 약 30회 × 판정 O(k). k ≤ 50,000이다.
- 공간 복잡도: O(k) — 정렬된 바위 배열과 도착지점 1개.

## 요약

바위 제거 조합을 직접 세는 대신 최소 거리 m의 달성 가능성을 판정 문제로 바꾸고, 탐욕적인 한 번 훑기로 최소 제거 개수를 세어 단조성을 이용해 이분탐색으로 가능한 가장 큰 m을 찾는다. 시간 복잡도 O(k log k + k log distance), 공간 복잡도 O(k)로 제한 안에서 충분히 여유가 있다.
