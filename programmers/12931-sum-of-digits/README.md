# 자릿수 더하기

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12931
- 레벨: Lv.1
- 카테고리: 연습문제

## 문제 핵심 요약

자연수 `N`이 주어지면 `N`의 각 자릿수의 합을 반환한다.

- 제한사항: `N`은 100,000,000 이하의 자연수
- 입출력 예: `123 → 6` (1 + 2 + 3), `987 → 24` (9 + 8 + 7)

## 문제 분석 및 핵심 로직

십진수에서 한 숫자의 일의 자리는 그 수를 10으로 나눈 나머지이다. `123 % 10`은 `3`, `123 // 10`은 `12`이다. 몫 `12`에 같은 일을 반복하면 `12 % 10 = 2`, `12 // 10 = 1`이 되고, 다시 `1 % 10 = 1`, `1 // 10 = 0`이 된다. 나머지를 차례로 더하면 `3 + 2 + 1 = 6`, 즉 각 자릿수의 합이 된다.

자릿수를 떼어내는 일은 결국 "10으로 나눈 나머지를 취하고, 몫으로 다음 자리로 넘어가는" 반복이다. `n`이 0이 되면 더 이상 떼어낼 자릿수가 없으므로 반복이 끝난다. `N`이 최대 100,000,000(9자리)이므로 반복은 최대 9번이다.

## 개념별 심층 설명

### 초심자 방식: 문자열로 바꿔서 한 글자씩 더하기

`str(n)`으로 숫자를 문자열로 바꾸면 각 자릿수가 문자 하나가 된다. `"123"`을 한 글자씩 순회하며 `int()`로 되돌려 더하면 답이 나온다. 직관적이고 코드도 짧다.

```python
def solution(n):
    return sum(int(c) for c in str(n))
```

이 방식의 비용은 문자열 변환에 있다. 숫자를 문자열로 바꾸는 일 자체가 내부적으로는 위의 나눗셈 반복과 비슷한 일을 하지만, 여기에 문자 객체 생성과 `int()` 변환이 더해진다. 자릿수가 적으면 차이는 미미하지만, 불필요한 중간 객체를 만드는 셈이다.

### 개선 방식: 나머지와 몫으로 직접 떼어내기

숫자를 문자열로 바꾸지 않고, `% 10`과 `// 10`만으로 자릿수를 떼어낸다. 중간 객체가 생기지 않고, 정수 연산만으로 끝나므로 같은 일을 더 적은 비용으로 한다.

예를 들어 `n = 987`이면 `987 % 10 = 7`을 더하고 `n = 98`이 되고, `98 % 10 = 8`을 더하고 `n = 9`가 되며, `9 % 10 = 9`를 더하고 `n = 0`이 되어 끝난다. 합은 `7 + 8 + 9 = 24`이다.

두 방식의 시간복잡도는 자릿수에 비례한다는 점에서 같지만, 상수 차이가 있다. 로컬 실측에서 무작위 100,000개 케이스 기준으로 문자열 방식은 0.1315초, 나머지와 몫 방식은 0.0588초로 약 2.2배 차이가 났다.

## 최종 솔루션 코드

### Python

```python
def solution(n):
    # 1. 10으로 나눈 나머지가 일의 자리 숫자이다.
    # 2. 10으로 나눈 몫으로 자리수를 한 칸씩 줄여 나간다.
    # 3. n이 0이 되면 모든 자릿수를 더한 것이다.
    total = 0
    while n > 0:
        total += n % 10
        n //= 10
    return total
```

### Java

```java
class Solution {
    public int solution(int n) {
        // 1. 10으로 나눈 나머지가 일의 자리 숫자이다.
        // 2. 10으로 나눈 몫으로 자리수를 한 칸씩 줄여 나간다.
        // 3. n이 0이 되면 모든 자릿수를 더한 것이다.
        int total = 0;
        while (n > 0) {
            total += n % 10;
            n /= 10;
        }
        return total;
    }
}
```

`n % 10`은 일의 자리, `n / 10`은 일의 자리를 떼어낸 나머지 수이다. 정수 나눗셈이므로 소수 부분은 버려진다. 반복 조건 `n > 0`은 "떼어낼 자릿수가 남아 있다"는 뜻과 같다.

## 성능 측정

로컬 실측 결과이다. 제한은 `n ≤ 100,000,000`이지만 스케일 차이를 보기 위해 무작위 100,000개 케이스로 측정했다.

| 케이스 | Python | Java |
| --- | --- | --- |
| 예제 `123 → 6`, `987 → 24` | 통과 | 통과 |
| 무작위 100,000개 (합계) | 0.0588 s | 0.0056 s |
| 무작위 100,000개 (1회당) | 0.588 µs | 0.056 µs |
| 문자열 방식 100,000개 (비교용) | 0.1315 s | — |

- Python 피크 메모리: 0.1 KiB (tracemalloc 실측, 무작위 100,000개 케이스 실행)
- Java 메모리: 힙 할당 없음 — 정수 변수 두 개만 사용
- 시간복잡도: O(d) — d는 자릿수 (최대 9, `n ≤ 100,000,000`)
- 공간복잡도: O(1) — 변수 몇 개만 사용

`n`이 100,000,000 이하이므로 자릿수는 최대 9개이고, 반복 횟수는 자릿수를 넘지 않는다. 입력 범위가 커져 자릿수가 늘어나도 반복 횟수는 자릿수에 비례해 늘 뿐이다.

## 요약

- 핵심 아이디어: `n % 10`으로 일의 자리를 떼어 더하고, `n // 10`으로 다음 자리로 넘어간다.
- 문자열로 바꾸는 방식도 동작하지만, 정수 연산만으로 하면 중간 객체가 없어 약 2.2배 빠르다.
- `n`이 0이 되면 반복이 끝나며, 시간복잡도는 O(자릿수), 공간복잡도는 O(1)이다.
