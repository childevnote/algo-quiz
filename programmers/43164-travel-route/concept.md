# 오일러 경로와 Hierholzer 알고리즘

## 오일러 경로란

그래프의 모든 간선을 정확히 한 번씩만 사용해 그리는 경로를 오일러 경로(Eulerian path)라고 한다. 시작점과 끝점이 같은 경우를 오일러 회로(Eulerian circuit)라고 한다. 쾨니히스베르크의 다리 문제에서 유래한 개념으로, "모든 다리를 한 번씩만 건너 출발점으로 돌아올 수 있는가"라는 질문이 그 시작이다.

오일러 경로가 존재하려면 그래프가 연결되어 있고, 홀수 차수(간선 개수)를 가진 정점이 0개(회로) 또는 2개(경로)여야 한다. 방향 그래프에서는 각 정점의 나가는 간선 수와 들어오는 간선 수의 차이가 시작점 +1, 끝점 -1, 나머지 0이어야 한다.

## Hierholzer 알고리즘

오일러 경로를 간선 수에 비례하는 시간에 찾는 알고리즘이다. 핵심 발상은 "막힌 곳에서 확정한다"는 것이다.

1. 시작 정점에서 간선을 따라 이동한다. 사용한 간선은 그래프에서 제거한다.
2. 더 이상 나갈 간선이 없으면 현재 정점을 경로에 확정한다.
3. 확정된 정점에서 되돌아오며, 아직 간선이 남은 정점이 있으면 그곳에서 다시 2번을 반복한다.
4. 확정된 정점들을 역순으로 이어 붙이면 전체 경로가 된다.

일반적인 예시로, 정점 A, B, C가 있고 간선이 A→B, B→C, C→A, A→C인 경우를 보자. A에서 시작해 B, C를 거쳐 A로 돌아오면 C→A 간선을 이미 썼으므로 A에서는 더 나갈 곳이 없다. A를 확정하고 되돌아오면 C에서 남은 A→C 간선을 발견해 C→A 경로를 이어 붙인다. 확정 순서를 뒤집으면 A→B→C→A→C가 된다.

```python
# Hierholzer 알고리즘의 뼈대 (일반적인 형태)
def eulerian_path(graph, start):
    route = []
    stack = [start]
    while stack:
        while graph[stack[-1]]:
            stack.append(graph[stack[-1]].pop())
        route.append(stack.pop())
    return route[::-1]
```

## 왜 백트래킹보다 빠른가

단순 DFS 백트래킹은 다음 정점을 고를 때마다 "이 선택이 끝까지 이어지는가"를 확신할 수 없어, 막히면 되돌아와 다른 선택을 다시 시도한다. 잘못된 선택이 많을수록 되돌아가는 횟수가 늘어난다.

Hierholzer 알고리즘은 되돌아가는 대신 막힌 정점을 확정한다. 간선을 따라 끝까지 간 뒤 확정하는 방식이라, 각 간선은 정확히 한 번씩만 처리된다. 되돌아오는 과정에서도 남은 간선이 있는 정점을 만나면 그 자리에서 부분 경로를 이어 붙이므로, 탐색을 처음부터 다시 할 필요가 없다.

## 사전식 순서가 필요할 때의 정렬

가능한 오일러 경로가 여러 개일 때 사전식 순서가 가장 앞서는 경로를 구하려면, 각 정점의 인접 목록을 미리 정렬해 두면 된다. 뒤에서 꺼내는 연산이 빠르므로 역순으로 정렬해 두고 뒤에서 꺼내면, 항상 가장 작은 다음 정점을 고르게 된다. 이렇게 하면 탐색 중에 매번 최소값을 찾을 필요가 없어진다.

## 시간·공간 복잡도

- 시간 복잡도: O(E log E). E는 간선 수이다. 인접 목록 정렬이 지배적이고, 탐색 자체는 간선마다 한 번씩 이동하므로 O(E)이다.
- 공간 복잡도: O(E). 인접 목록, 스택, 결과 경로가 모두 간선 수에 비례한다.
