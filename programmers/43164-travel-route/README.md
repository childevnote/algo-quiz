# 여행경로

- 문제: [여행경로](https://school.programmers.co.kr/learn/courses/30/lessons/43164)
- 레벨: Lv.3
- 카테고리: DFS/BFS
- 날짜: 2026-11-11

## 문제 핵심 요약

항공권 목록 `tickets`가 주어진다. 각 항공권은 `[출발 공항, 도착 공항]` 쌍이며, 모든 항공권을 정확히 한 번씩 사용해 "ICN"에서 출발하는 여행 경로를 만든다. 가능한 경로가 여러 개면 알파벳 순서가 가장 앞서는 경로를 반환한다.

핵심 제한사항:

- 모든 공항은 알파벳 대문자 3글자이다.
- 공항 수는 3개 이상 10,000개 이하이다.
- 주어진 항공권은 모두 사용해야 한다.
- 모든 도시를 방문할 수 없는 경우는 주어지지 않는다.

입출력 예:

| tickets | return |
| --- | --- |
| [["ICN", "JFK"], ["HND", "IAD"], ["JFK", "HND"]] | ["ICN", "JFK", "HND", "IAD"] |
| [["ICN", "SFO"], ["ICN", "ATL"], ["SFO", "ATL"], ["ATL", "ICN"], ["ATL", "SFO"]] | ["ICN", "ATL", "ICN", "SFO", "ATL", "SFO"] |

## 문제 분석 및 핵심 로직

이 문제는 공항을 정점, 항공권을 간선으로 하는 방향 그래프에서 모든 간선을 정확히 한 번씩 사용하는 경로, 즉 오일러 경로(Eulerian path)를 찾는 문제이다. 시작점이 "ICN"으로 고정되고, 가능한 경로가 여러 개면 사전식 순서가 가장 앞서는 것을 골라야 한다는 조건이 붙는다.

핵심 로직은 다음과 같다.

1. 출발 공항별로 도착 공항 목록을 만든다. 같은 출발 공항에서 나가는 항공권이 여러 장일 수 있으므로 목록은 중복을 허용한다.
2. 각 목록을 알파벳 역순으로 정렬한다. 뒤에서 꺼내는 연산(`pop` / `removeLast`)이 O(1)이므로, 역순 정렬을 해 두면 가장 작은 도착 공항을 항상 뒤에서 꺼낼 수 있다.
3. "ICN"에서 출발해 스택으로 깊이 우선 탐색을 하되, 간선을 따라 이동하면서 사용한 항공권은 목록에서 제거한다. 현재 공항에서 나갈 간선이 더 이상 없으면 그 공항을 경로에 확정한다. 이것이 Hierholzer 알고리즘이다.
4. 확정된 공항들은 이동 순서의 역순으로 쌓이므로, 마지막에 뒤집으면 "ICN"에서 시작하는 전체 경로가 된다.

## 개념별 심층 설명

### 1. 왜 단순 DFS 백트래킹이 아니라 Hierholzer인가

초심자 방식은 현재 공항에서 알파벳 순서대로 다음 공항을 골라 재귀 탐색을 하고, 막히면 되돌아와 다음 후보를 시도하는 백트래킹이다. 이 방식도 정답을 찾지만, 잘못된 선택을 했을 때 되돌아가는 비용이 크고, 간선 수가 많아지면 탐색량이 폭발적으로 늘어난다.

Hierholzer 알고리즘은 되돌아가는 대신 "막힌 곳에서 확정한다"는 발상을 쓴다. 간선을 따라 끝까지 가다가 더 이상 나갈 간선이 없으면, 그 공항은 경로의 끝에 와야 하는 공항임이 확실하므로 그 자리에서 확정한다. 되돌아오면서 확정된 공항들을 이어 붙이면 모든 간선을 한 번씩 쓴 전체 경로가 된다. 백트래킹처럼 후보를 되돌리며 다시 시도하지 않으므로 간선 수에 비례하는 시간에 끝난다.

### 2. 확정 순서를 뒤집어야 하는 이유

예제 2번으로 과정을 따라가 보자. "ICN"에서 알파벳 순서대로 "ATL"을 고르고, "ATL"에서 "ICN"으로 간 뒤, "ICN"에서 남은 "SFO"로 가고, "SFO"에서 "ATL"로 가고, "ATL"에서 남은 "SFO"로 가면 더 이상 나갈 간선이 없다. 여기서 "SFO"를 먼저 확정하고, 되돌아오면서 "ATL", "SFO", "ICN", "ATL", "ICN" 순으로 확정한다. 확정 순서는 ["SFO", "ATL", "SFO", "ICN", "ATL", "ICN"]인데, 이것은 이동 순서의 역순이다. 뒤집으면 ["ICN", "ATL", "ICN", "SFO", "ATL", "SFO"]로 정답이 된다. 막힌 끝에서부터 확정하기 때문에 역순이 되는 것이고, 뒤집는 한 번의 연산으로 해결된다.

### 3. 알파벳 순서를 정렬로 미리 처리하는 이유

가능한 경로가 여러 개면 알파벳 순서가 앞서는 경로를 골라야 한다. 탐색 중에 매번 "남은 도착 공항 중 가장 작은 것"을 찾으면 매번 선형 탐색이 필요하다. 대신 각 출발 공항의 도착 목록을 미리 정렬해 두면, 가장 작은 도착 공항은 항상 목록의 끝에 있게 된다. 스택에서 꺼내는 연산은 O(1)이므로 정렬 비용 한 번으로 탐색 전체가 빨라진다. 역순 정렬인 이유는 뒤에서 꺼내는 연산이 빠르기 때문이다. 오름차순으로 정렬해 앞에서 꺼내면 리스트의 앞부분을 지우는 연산이 O(N)이 되어 간선 수만큼 반복될 때 전체가 느려진다.

### 4. 간선을 "사용하면 제거"하는 이유

모든 항공권을 정확히 한 번씩 사용해야 하므로, 사용한 항공권은 다시 쓰면 안 된다. 인접 목록에서 간선을 꺼내는 순간 그 항공권은 소진된 것으로 처리된다. 별도의 방문 표시 배열을 두지 않아도 목록 자체가 남은 항공권의 상태가 되므로, 코드가 단순해지고 메모리도 아낄 수 있다. 단, 같은 출발·도착 쌍의 항공권이 여러 장이면 목록에 중복으로 들어가므로, 한 장씩만 제거되는 점이 중요하다.

## 최종 솔루션 코드

### Python

```python
from collections import defaultdict


def solution(tickets):
    graph = defaultdict(list)
    # 1. 출발 공항별로 도착 공항 목록을 만든다.
    for src, dst in tickets:
        graph[src].append(dst)
    # 2. 알파벳 역순으로 정렬해 두면 pop()으로 가장 작은 도착 공항을 꺼낼 수 있다.
    for dsts in graph.values():
        dsts.sort(reverse=True)

    route = []
    stack = ["ICN"]
    # 3. Hierholzer 알고리즘: 더 이상 갈 간선이 없을 때만 경로에 확정한다.
    while stack:
        while graph[stack[-1]]:
            stack.append(graph[stack[-1]].pop())
        route.append(stack.pop())
    # 4. 확정 순서가 역순이므로 뒤집으면 ICN에서 시작하는 전체 경로가 된다.
    return route[::-1]
```

### Java

```java
import java.util.*;

class Solution {
    public String[] solution(String[][] tickets) {
        Map<String, List<String>> graph = new HashMap<>();
        // 1. 출발 공항별로 도착 공항 목록을 만든다.
        for (String[] ticket : tickets) {
            graph.computeIfAbsent(ticket[0], k -> new ArrayList<>()).add(ticket[1]);
        }
        // 2. 알파벳 역순으로 정렬해 두면 removeLast()로 가장 작은 도착 공항을 꺼낼 수 있다.
        for (List<String> dsts : graph.values()) {
            dsts.sort(Collections.reverseOrder());
        }

        List<String> route = new ArrayList<>();
        Deque<String> stack = new ArrayDeque<>();
        stack.push("ICN");
        // 3. Hierholzer 알고리즘: 더 이상 갈 간선이 없을 때만 경로에 확정한다.
        while (!stack.isEmpty()) {
            List<String> dsts = graph.getOrDefault(stack.peek(), List.of());
            while (!dsts.isEmpty()) {
                stack.push(dsts.remove(dsts.size() - 1));
                dsts = graph.getOrDefault(stack.peek(), List.of());
            }
            route.add(stack.pop());
        }
        // 4. 확정 순서가 역순이므로 뒤집으면 ICN에서 시작하는 전체 경로가 된다.
        Collections.reverse(route);
        return route.toArray(new String[0]);
    }
}
```

로컬 실측 결과 (2026-11-11):

| 스케일 테스트 (티켓 100,001장) | 약 285 ms | 약 50 ms |
| 스케일 테스트 피크 메모리 | 약 12.8 MB | 약 16.8 MB |

스케일 테스트는 문제 제한(공항 수 ≤ 10,000개)을 크게 넘는 합성 데이터이다. "ICN"에서 시작해 서로 다른 공항 코드를 차례로 잇는 100,000개의 간선에 마지막 공항에서 "ICN"으로 돌아오는 간선 1개를 더해, 유효한 오일러 경로가 존재하는 티켓 100,001장을 만들었다. 각 간선마다 나가는 공항이 하나뿐이라 정렬 비용이 거의 들지 않는 구조이므로, 분기가 많은 입력에서는 정렬 비용이 더해질 수 있다.

- 시간 복잡도: O(E log E). E는 티켓 수이다. 인접 목록 정렬이 지배적이며, Hierholzer 탐색 자체는 간선마다 한 번씩만 이동하므로 O(E)이다.
- 공간 복잡도: O(E). 인접 목록, 스택, 결과 경로가 모두 티켓 수에 비례한다.

## 요약

- 모든 간선을 한 번씩 사용하는 경로는 오일러 경로이며, Hierholzer 알고리즘으로 간선 수에 비례하는 시간에 구한다.
- 현재 공항에서 나갈 간선이 없을 때 그 공항을 확정하고, 확정 순서를 뒤집으면 전체 경로가 된다.
- 알파벳 순서는 인접 목록을 역순 정렬해 미리 처리하고, 사용한 간선은 목록에서 제거해 다시 쓰지 않는다.
- 학습 노트: 이 문제는 DFS 백트래킹으로 풀면 되돌아가는 비용이 커지지만, 막힌 곳에서 확정하는 Hierholzer 방식을 쓰면 간선을 한 번씩만 훑어 답을 얻을 수 있다는 점이 핵심이다. 확정 순서가 역순이 된다는 점을 놓치면 경로가 거꾸로 나오므로 뒤집는 단계를 빼먹지 않는다.
