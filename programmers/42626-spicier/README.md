# 더 맵게

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42626
- 레벨: Lv.2 · 카테고리: 힙

## 문제 핵심 요약

scoville 배열의 모든 원소를 K 이상으로 만들어야 한다. 섞는 방법은 정해져 있다: 현재 가장 작은 원소 a와 두 번째로 작은 원소 b를 꺼내 `a + 2 * b`를 다시 넣는다. 이 과정을 최소 몇 번 반복하면 되는지 묻는다.

핵심 제한사항은 두 가지다. 배열 길이는 최대 1,000,000, K는 최대 1,000,000,000. 그리고 아무리 섞어도 K에 도달할 수 없으면 -1을 반환한다. 즉 (1) 매번 가장 작은 두 개를 효율적으로 뽑아야 하고, (2) 남은 음식이 1개뿐인데 아직 K 미만이면 멈춰야 한다.

## 문제 분석 및 핵심 로직

이 문제는 "매번 전체 중 가장 작은 두 개를 뽑아 합치고 다시 넣는" 과정을 반복한다. 반복 횟수는 최악의 경우 n에 가까울 수 있다.

핵심은 **최소 힙**이다. 가장 작은 원소를 꺼내는 연산과 새 원소를 넣는 연산을 모두 로그 시간에 처리해야 전체가 버틴다. 힙에 전제를 깔면 풀이는 그대로 번역된다: 가장 작은 값이 K 이상이 될 때까지 (가장 작은 두 개 꺼내기 → 섞어서 넣기)를 반복한다.

종료 조건을 정리하면 세 가지다.

1. 힙의 최솟값이 K 이상 → 성공, 반복 횟수 반환
2. 힙에 원소가 1개뿐인데 최솟값이 K 미만 → 더 섞을 수 없으므로 -1
3. 힙이 비는 경우는 사실상 2번에 포함된다 (길이가 2 이상으로 시작하므로)

## 초심자 방식 vs 개선 방식

### 초심자 방식: 매번 정렬하기

가장 직관적인 접근은 리스트를 정렬한 뒤 앞의 두 개를 꺼내 섞고 다시 정렬하는 것이다. 코드는 짧지만 섞을 때마다 정렬을 다시 하므로 한 번의 반복에 O(n log n)이 든다. 섞는 횟수가 n에 가까워지면 전체 복잡도는 O(n² log n)에 이르고, n이 1,000,000인 제한에서는 시간 초과가 확정적이다.

### 개선 방식: 최소 힙 한 번 깔아두기

배열을 처음에 한 번 힙화(heapify)해 두면 그 이후의 최소값 꺼내기와 삽입이 각각 O(log n)이다. 전체 과정은 heapify O(n) + 반복 m회에 O(m log n). 즉 O(n log n) 수준으로 안정적으로 끝난다. 정렬을 반복하는 방식과의 차이는 이 한 줄의 자료구조 선택에 있다.

### 놓치기 쉬운 종료 조건

- `K = 0`인 경우: 스코빌 지수는 0 이상이므로 아무것도 섞지 않고 0을 반환해야 한다. `while 최소값 < K` 조건이 처음부터 거짓이라 자연스럽게 0이 나온다.
- 다 섞었는데 K에 못 미치는 경우: 힙 크기가 1이 되면 `len < 2` 체크에서 -1을 반환한다. 이 체크를 반복문 안의 최솟값 체크보다 먼저 하지 않으면, 크기가 0이 된 힙의 `[0]`에 접근해 인덱스 에러가 난다 (Python).

## 최종 솔루션 코드

### Python

```python
import heapq

def solution(scoville, K):
    heapq.heapify(scoville)  # 1. 전체를 최소 힙으로
    answer = 0
    while scoville[0] < K:  # 2. 가장 안 매운 게 K 미만이면 계속 섞음
        if len(scoville) < 2:  # 3. 섞을 수 없으면 -1
            return -1
        first = heapq.heappop(scoville)  # 4. 가장 안 매운 두 개
        second = heapq.heappop(scoville)
        heapq.heappush(scoville, first + 2 * second)  # 5. 섞은 음식 투입
        answer += 1
    return answer
```

### Java

```java
import java.util.PriorityQueue;

class Solution {
    public int solution(int[] scoville, int K) {
        // 1. 전체를 최소 힙(PriorityQueue)으로
        PriorityQueue<Long> pq = new PriorityQueue<>();
        for (int s : scoville) pq.offer((long) s);

        int answer = 0;
        // 2. 가장 안 매운 게 K 미만이면 계속 섞음
        while (!pq.isEmpty() && pq.peek() < K) {
            // 3. 섞을 수 없으면 -1
            if (pq.size() < 2) return -1;
            // 4. 가장 안 매운 두 개를 꺼내 5. 섞은 음식 투입
            long first = pq.poll();
            long second = pq.poll();
            pq.offer(first + 2 * second);
            answer++;
        }
        return answer;
    }
}
```

Java에서 `long`을 쓴 이유는 섞는 과정이 반복되면 값이 지수적으로 커져 `int` 범위를 넘을 수 있기 때문이다. 루프는 힙 크기가 매 반복마다 1씩 줄어들므로 오버플로우가 있어도 무한 루프에는 빠지지 않지만, 비교값이 틀어질 여지를 없애는 편이 안전하다.

## 성능 측정

로컬 실측 (n = 100,000, 원소 0 ~ 1,000,000 무작위):

| 조건 | Python | Java |
|---|---|---|
| K 도달 불가 (섞을 수 있을 때까지 전부 섞음) | 0.64s | 0.13s |
| K = 100,000 (도달 가능, 약 6,000회 섞음) | 0.016s | — |
| 피크 메모리 (K 도달 불가 케이스, tracemalloc) | 1.86MB | — |

예제 케이스 `[1, 2, 3, 9, 10, 12], K=7` → 2, 엣지 케이스(전부 K 이상 → 0, `[1, 1], K=100` → -1, `K=0` → 0, `[0, 0], K=1` → -1) 모두 통과.

- 시간 복잡도: O(n log n) — heapify O(n), 섞기 m회 × (pop 2회 + push 1회) O(m log n), m ≤ n
- 공간 복잡도: O(n) — 힙 하나

## 학습 노트

- 막혔던 점: 없었다. 문제는 힙이 떠오르는 정형 문제였다. 다만 Java에서 섞은 값이 `int`를 넘을 수 있다는 점을 뒤늦게 점검했다.
- 핵심 포인트: "매번 가장 작은 두 개를 뽑아 합치고 다시 넣기"는 최소 힙의 정석 패턴이다. 정렬 반복과의 차이는 한 번의 반복 비용이 O(n log n)이냐 O(log n)이냐다.
- 개선: 섞는 과정이 끝나지 않는 케이스(-1)를 `len < 2` 한 줄로 처리했다. 힙이 빌 때까지 루프를 돌리면 pop 순서상 마지막 남은 1개가 K 미만일 때 멈출 방법이 없어 이 가드가 필수다.

## 요약

최소 힙에 전체를 넣고 최솟값이 K 이상이 될 때까지 두 개씩 꺼내 섞는 것이 전부다. 힙 크기 2 미만에서 종료 체크를 빼먹지 않으면 -1 케이스도 자연스럽게 처리된다.
