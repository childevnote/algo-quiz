# 개념 노트: 큐와 시뮬레이션

## 큐 (FIFO)

먼저 들어간 원소가 먼저 나오는 자료구조다. 줄 서기와 같은 순서다. 지원하는 연산은 뒤쪽에 넣기(enqueue), 앞쪽에서 꺼내기(dequeue), 맨 앞 확인(peek)이며 모두 O(1)이다.

Python의 `collections.deque`와 Java의 `ArrayDeque`가 대표적이다. 리스트의 맨 앞에서 꺼내는 연산은 O(n)이 걸리지만, deque는 양쪽 끝 연산이 모두 O(1)이라 대기열 구현에 적합하다.

일반적인 쓰임은 "순서대로 처리해야 하는 작업 목록"이다. 예를 들어 프린터 대기열에서는 인쇄 요청이 들어온 순서대로 처리되며, 먼저 들어온 요청이 먼저 빠져나간다.

## 시뮬레이션

문제에서 주어진 규칙을 시간이나 단계에 따라 그대로 따라가며 상태를 갱신하는 풀이 방식이다. 별도의 수식이나 역산 없이 "규칙대로 한 걸음씩" 진행한다.

시뮬레이션의 관건은 상태 표현을 최소화하는 것이다. 전체 상황을 다 들고 있을 필요는 없고, 다음 단계를 판단하는 데 필요한 정보만 유지하면 된다. 예를 들어 은행 창구의 대기열을 시뮬레이션할 때 각 손님의 전체 이력이 아니라 "대기 중인 손님 수"와 "창구가 비는 시각"만 알면 된다.

## 누적 합 유지하기

반복적으로 전체 합을 다시 계산하는 대신, 값이 바뀔 때만 합을 가감해서 최신 상태를 유지하는 기법이다. 원소가 추가되면 더하고, 제거되면 뺀다.

예를 들어 슬라이딩 윈도우의 합을 구할 때, 매번 윈도우 안의 원소를 전부 더하면 O(윈도우 크기)가 걸리지만, 윈도우가 한 칸 이동할 때마다 "나간 원소는 빼고 들어온 원소는 더하면" O(1)에 갱신된다. 합을 조회하는 연산이 빈번할수록 효과가 크다.
