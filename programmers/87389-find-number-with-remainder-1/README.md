# 나머지가 1이 되는 수 찾기

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/87389
- 레벨: Lv.1
- 카테고리: 월간 코드 챌린지 시즌3

## 문제 핵심 요약

자연수 `n`이 주어졌을 때, `n`을 나눈 나머지가 1이 되는 가장 작은 자연수 `x`를 구한다. 답은 항상 존재한다.

- 제한사항: 3 ≤ `n` ≤ 1,000,000
- 입출력 예: `n = 10` → `3`, `n = 12` → `11`

## 문제 분석 및 핵심 로직

조건 `n % x == 1`을 그대로 읽으면 `x`를 2부터 하나씩 대입해 보는 풀이가 먼저 떠오른다. 그런데 이 조건을 식으로 다시 쓰면 더 짧은 길이 보인다.

`n`을 `x`로 나눈 나머지가 1이라는 것은 `n - 1`이 `x`로 나누어떨어진다는 뜻이다. 단, 나머지가 1이려면 나누는 수 `x`가 1보다 커야 한다(`x = 1`이면 나머지는 항상 0이다). 따라서 문제는 "1보다 큰 `n - 1`의 가장 작은 약수를 구하라"로 바뀐다.

- `n = 10`이면 `n - 1 = 9`의 가장 작은 약수는 3이다.
- `n = 12`이면 `n - 1 = 11`은 소수라서 약수가 없으므로 답은 11 자체이다.

약수를 찾을 때는 제곱근까지만 검사하면 된다. `n - 1`의 약수 `d`가 있다면 짝이 되는 약수 `(n - 1) / d`도 존재하고, 둘 중 하나는 반드시 `sqrt(n - 1)` 이하이기 때문이다. 제곱근까지 약수가 하나도 없으면 그 수는 소수이고, 답은 `n - 1` 자체이다.

## 개념별 심층 설명

### 초심자 방식: x를 2부터 하나씩 대입

`n % x == 1`인 가장 작은 `x`를 찾기 위해 `x = 2, 3, 4, ...` 순서로 나머지를 계산한다. 답이 `n - 1`인 경우(즉 `n - 1`이 소수인 경우)에는 `n`에 가까운 횟수만큼 반복해야 하므로 시간복잡도는 O(n)이다. `n`이 최대 1,000,000일 때 최악 케이스(`n = 999984`, `n - 1 = 999983`은 소수) 실측은 Python 기준 약 876 ms이다. 제한 내에서는 동작하지만, 불필요하게 긴 반복이다.

### 개선 방식: n - 1의 약수 찾기

조건을 `n - 1`의 약수 문제로 바꾸면 검사 범위가 `sqrt(n - 1)`까지로 줄어든다. `n`이 최대 1,000,000일 때 반복 횟수는 최대 1,000회 수준이다. 같은 최악 케이스 실측은 Python 기준 약 1.08 ms로, 초심자 방식보다 800배 이상 빠르다.

동작 원리는 약수의 대칭성에 있다. 어떤 수 `m`의 약수 `d`에 대해 `m / d`도 약수이고, `d`와 `m / d` 중 작은 쪽은 항상 `sqrt(m)` 이하이다. 따라서 `sqrt(m)`까지 약수를 찾지 못했다면 `m`은 소수임이 확정된다.

## 최종 솔루션 코드

### Python

```python
def solution(n):
    # 1. n % x == 1 이면 n - 1은 x의 배수이다. (단, 나머지가 1이려면 x > 1)
    # 2. 따라서 답은 n - 1의 1보다 큰 가장 작은 약수이다.
    # 3. 약수는 sqrt(n - 1)까지만 검사하면 된다. 약수가 없으면 n - 1 자체가 소수이므로 답은 n - 1이다.
    m = n - 1
    x = 2
    while x * x <= m:
        if m % x == 0:
            return x
        x += 1
    return m
```

### Java

```java
class Solution {
    public int solution(int n) {
        // 1. n % x == 1 이면 n - 1은 x의 배수이다. (단, 나머지가 1이려면 x > 1)
        // 2. 따라서 답은 n - 1의 1보다 큰 가장 작은 약수이다.
        // 3. 약수는 sqrt(n - 1)까지만 검사하면 된다. 약수가 없으면 n - 1 자체가 소수이므로 답은 n - 1이다.
        int m = n - 1;
        for (int x = 2; (long) x * x <= m; x++) {
            if (m % x == 0) {
                return x;
            }
        }
        return m;
    }
}
```

Java에서 `(long) x * x`로 형변환하는 이유는 `x * x`가 `int` 범위를 넘을 가능성을 원천적으로 차단하기 위해서이다. 이 문제에서는 `x`가 최대 1,000까지만 커지므로 실제로 오버플로가 나지 않지만, 습관적으로 안전한 형태를 썼다.

## 성능 측정

로컬 실측 결과이다.

| 케이스 | Python | Java |
| --- | --- | --- |
| 예제 n = 10 → 3 | 3.0 µs | 1.9 µs |
| 예제 n = 12 → 11 | 2.0 µs | 1.8 µs |
| 무작위 1,000건 (n ≤ 100,000) | 14.45 ms (합계) | 0.70 ms (합계) |
| 최악 케이스 n = 999,984 → 999,983 | 1.08 ms | 0.01 ms 미만 |
| n = 1,000,000 → 3 | 0.002 ms | — |

- 무작위 1,000건 실행 시 Python 피크 메모리: 0.1 KiB (tracemalloc 실측)
- 시간복잡도: O(√n) — 약수 검사를 `sqrt(n - 1)`까지만 수행
- 공간복잡도: O(1) — 변수 몇 개만 사용

## 요약

- 핵심 아이디어: `n % x == 1`은 `x`가 `n - 1`의 약수라는 것과 동치이다.
- 답은 `n - 1`의 1보다 큰 가장 작은 약수이며, 없으면 `n - 1` 자체이다.
- 약수 검사는 제곱근까지만 하면 되므로 시간복잡도는 O(√n), 공간복잡도는 O(1)이다.
