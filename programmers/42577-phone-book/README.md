# [Lv.2 · 해시] 전화번호 목록

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42577

## 문제 핵심 요약

전화번호 목록이 주어졌을 때, **한 번호가 다른 번호의 접두어인 경우가 있는지** 판정한다. 그런 경우가 있으면 `false`, 없으면 `true`를 반환한다. 목록 크기는 최대 100만, 번호 길이는 최대 20.

핵심 제한: 번호들은 서로 중복되지 않는다. 단, A가 B의 접두어이면서 B가 C의 접두어인 연쇄(예: `"12"`, `"123"`, `"1235"`)도 존재한다.

입출력 예:

| phone_book | return |
|---|---|
| ["119", "97674223", "1195524421"] | false |
| ["123", "456", "789"] | true |
| ["12", "123", "1235", "567", "88"] | false |

## 문제 분석 및 핵심 로직

접두어 관계에 있는 쌍을 어떻게 찾을 것인가. 두 가지 방향이 있다.

**초심자 방식 — 모든 쌍을 직접 비교**: 번호가 n개면 약 n²/2쌍을 검사한다. 각 쌍에 대해 "짧은 쪽이 긴 쪽의 앞부분과 일치하는가"를 본다. n=100만이면 5×10¹¹ 쌍, 비교 한 번에 최대 20문자 — 연산량이 수백조에 이른다. 시간 제한을 넘을 것이 분명하다. O(n²)이다.

**초심자 방식 2 — 접두어 해시 셋**: 각 번호의 모든 접두어를 해시 셋에 저장한다. 예를 들어 "119"는 "1", "11", "119"를 셋에 넣는다. 그 뒤 각 번호가 셋에 자기 자신이 아닌 접두어로 들어있는지 확인한다. 시간은 전체 문자 길이 합 O(ΣL), 접두어 셋이 최대 2천만 개의 짧은 문자열을 담을 수 있어 메모리 부담이 있다. 번호 길이 합이 2천만이면 수백 MB를 넘을 수도 있다.

**개선 방식 — 정렬 후 인접 비교**: 문자열을 사전식으로 정렬하면, 접두어 관계에 있는 두 번호는 정렬 결과에서 반드시 인접하게 붙는다. "12", "123", "1235"는 정렬 후 "12"–"123"–"1235"가 되어 각각 앞 번호가 뒷 번호의 접두어임이 드러난다. 따라서 **인접한 쌍 n−1개만 검사**하면 충분하다. 정렬이 O(n log n), 인접 비교가 O(n), 추가 메모리는 정렬이 필요로 하는 만큼뿐이다.

왜 인접 비교로 충분한가: A가 B의 접두어라면, 정렬된 순서에서 A와 B 사이에 끼는 어떤 문자열 C도 A–B 쌍과 동일한 접두어 관계를 깨뜨릴 수 없다. C가 A와 B 사이에 위치한다면, C는 A의 접두어가거나 A가 C의 접두어인 관계 중 하나를 갖게 되며, 어쨌든 A는 자신의 "뒤에 오는 이웃" 중 하나와 접두어 관계에 있게 된다. 따라서 한 번호가 누군가의 접두어라면, 그 번호 바로 다음에 오는 번호와의 검사에서 반드시 발견된다.

## 최종 솔루션 코드

**Python** — `solution.py`

```python
def solution(phone_book):
    phone_book.sort()
    for i in range(len(phone_book) - 1):
        # ① 정렬: 접두어 관계의 쌍은 인접해 나타난다
        # ② 앞 번호가 뒷 번호의 접두어면 즉시 false
        if phone_book[i + 1].startswith(phone_book[i]):
            return False
    return True
```

**Java** — `Solution.java`

```java
import java.util.Arrays;

public class Solution {
    public boolean solution(String[] phone_book) {
        Arrays.sort(phone_book);  // ① 사전식 정렬
        for (int i = 0; i < phone_book.length - 1; i++) {
            // ② 인접 쌍 검사: 앞 번호가 뒷 번호의 접두어면 false
            if (phone_book[i + 1].startsWith(phone_book[i])) return false;
        }
        return true;
    }
}
```

## 성능 측정

로컬 실측 (VM, JDK 21, CPython):

| 케이스 | Python | Java |
|---|---|---|
| 예제 3건 | < 0.001초 | < 0.001초 |
| 무작위 n=100,000 (번호 길이 20, 중복 없음) | 0.332초 | 0.254초 |
| n=100,000 추가 메모리 | ≈ 0.4MB (정렬 제외 순증가분) | ≈ 24MB (JVM 전체 사용량) |

- 시간 복잡도: **O(n log n)** — 정렬이 지배한다. 인접 비교는 O(n × 접두어 비교 비용), 비교 비용은 최대 20문자이므로 상수로 간주한다.
- 공간 복잡도: **O(n)** — 정렬이 입력 배열을 제자리에서 처리하고, 추가 자료구조는 사용하지 않는다.

## 요약

접두어 판정은 "모든 접두어를 해시 셋에 넣는다"가 정석처럼 알려져 있지만, **사전식 정렬 한 번이면 인접 비교 n−1회로 충분하다**는 성질을 이용하는 편이 메모리가 가볍고 코드도 짧다. n=100만(제한 최대)에서도 정렬은 수 초 안에 끝나며, 접두어 셋 방식이 최대 2천만 개의 문자열을 담아야 하는 데 비해 이 방식은 추가 메모리를 거의 쓰지 않는다. 정렬 후 인접한 원소만 보면 된다는 통찰은, "순서가 보장하는 인접성"을 이용하는 전형적인 패턴이다.
