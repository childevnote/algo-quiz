# 조이스틱

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42860
- 레벨: Lv.2 · 카테고리: 탐욕법
- 풀이 날짜: 2026-10-26

## 문제 핵심 요약

처음에는 모든 자리가 `A`인 이름이 있다. 조이스틱 상하로는 현재 자리의 알파벳을 바꾸고, 좌우로는 커서를 이동한다. 커서는 양쪽 끝에서 반대쪽 끝으로 이어진다. 목표 이름을 만드는 조이스틱 조작 횟수의 최솟값을 구한다.

핵심 제한사항: 이름은 알파벳 대문자로만 이루어지며 길이는 1 이상 20 이하이다.

입출력 예:

| name | return |
| --- | --- |
| "JEROEN" | 56 |
| "JAN" | 23 |

## 문제 분석 및 핵심 로직

이 문제는 상하 조작 횟수와 좌우 이동 횟수를 따로 구해 더하는 구조이다. 두 부분은 서로 영향을 주지 않는다. 상하 조작은 자리마다 독립적이고, 좌우 이동은 어떤 자리가 이미 `A`인지에만 달려 있기 때문이다.

### 상하 조작: 자리마다 위아래 중 짧은 쪽

알파벳은 `A`에서 `Z`까지 원형으로 이어진다. `A`에서 아래로 한 번 가면 `Z`가 된다. 목표 문자가 `A`에서 위쪽으로 `d`만큼 떨어져 있다면, 아래쪽으로는 `26 - d`만큼 떨어져 있다. 따라서 자리마다 `min(d, 26 - d)`를 더하면 된다. 예를 들어 `J`는 위로 9번, 아래로는 17번이므로 9번을 택하고, `Z`는 위로 25번, 아래로 1번이므로 1번을 택한다.

### 좌우 이동: `A`가 연속된 구간을 건너뛰는 것이 관건

초심자 방식은 커서를 오른쪽으로 끝까지 한 칸씩 이동하는 것이다. 이동 횟수는 `n - 1`회이다. 이 방식은 모든 자리가 `A`가 아닐 때는 최적이다. 그러나 목표 이름에 `A`가 연속된 구간이 있으면 이야기가 달라진다. 이미 `A`인 자리는 바꿀 필요가 없으므로, 그 구간을 굳이 지나갈 이유가 없다.

예를 들어 `JAZ`를 보자. 오른쪽으로만 가면 이동이 2회이지만, 왼쪽으로 1회 이동하면 커서가 마지막 자리로 넘어가므로 이동이 1회로 줄어든다. `J`를 만든 뒤 왼쪽으로 1회, `Z`를 아래로 1회 조작하면 총 11회가 되어 최소가 된다.

개선 방식은 각 위치 `i`마다 그 뒤에 이어지는 `A` 구간을 확인하는 것이다. `i` 다음 자리부터 `A`가 아닌 자리가 나오는 위치를 `nxt`라 하자. 그러면 두 가지 우회 경로를 계산할 수 있다.

- `i`까지 갔다가 되돌아와 반대쪽에서 `nxt`로 진입: `i * 2 + (n - nxt)`
- 왼쪽으로 먼저 돌아 반대쪽에서 진입한 뒤 `i` 방향으로 오는 경로: `(n - nxt) * 2 + i`

두 값과 기본값 `n - 1` 중 가장 작은 값을 좌우 이동 횟수로 택한다. `A` 구간이 길수록 우회로 얻는 이득이 커지고, 구간이 없으면 기본값이 그대로 유지된다.

### 왜 상하와 좌우를 분리해도 되는가

상하 조작은 커서가 해당 자리에 있을 때만 일어나고, 좌우 이동은 어떤 순서로 자리를 방문하든 각 자리를 최소 한 번씩 방문하기만 하면 된다. 바꿀 필요가 없는 `A` 자리는 방문 자체를 생략할 수 있으므로, 좌우 이동 문제는 "바꿀 자리들을 모두 방문하는 최단 경로"로 축소된다. 위의 두 우회 공식은 그 경로의 후보를 전부 따져 보는 셈이다.

## 개념별 심층 설명

### 원형 거리

선형 거리와 원형 거리는 다르다. 알파벳처럼 양끝이 이어진 구조에서는 두 지점 사이의 거리가 위쪽 거리와 아래쪽 거리 중 짧은 쪽이다. `A`와 `Z`의 선형 거리는 25이지만 원형 거리는 1이다. 이 문제의 상하 조작이 바로 원형 거리이다. 자세한 내용은 `concept.md`의 원형 거리 항목을 참고한다.

### 연속 구간 건너뛰기

배열을 순회할 때 바꿀 필요가 없는 구간이 있으면, 그 구간을 통과하는 대신 방향을 바꿔 반대쪽에서 접근하는 편이 짧을 수 있다. 이때 되돌아가는 비용은 이미 이동한 거리의 두 배가 된다. 한 번 되돌아가면 다시 원래 방향으로 돌아올 필요가 없으므로, 되돌아가는 지점은 `A` 구간 바로 앞이 최적이다. 이 판단이 위의 두 공식으로 이어진다.

## 최종 솔루션 코드

### Python

```python
def solution(name):
    # 1. 상하 조작: 각 자리마다 A에서 목표 문자까지 위/아래 중 짧은 쪽
    answer = 0
    for ch in name:
        up = ord(ch) - ord('A')
        answer += min(up, 26 - up)

    # 2. 좌우 이동: 기본은 오른쪽으로 끝까지 가는 n-1회.
    #    연속된 'A' 구간을 만나면, 되돌아가거나 왼쪽으로 먼저 돌아
    #    그 구간을 건너뛰는 편이 짧아질 수 있어 두 방향 모두 계산한다.
    n = len(name)
    move = n - 1
    for i in range(n):
        nxt = i + 1
        while nxt < n and name[nxt] == 'A':
            nxt += 1
        # i까지 갔다가 되돌아와 반대쪽에서 nxt로 진입 / 왼쪽으로 먼저 돌아 반대쪽에서 진입
        move = min(move, i * 2 + n - nxt, (n - nxt) * 2 + i)
    return answer + move
```

### Java

```java
class Solution {
    public int solution(String name) {
        // 1. 상하 조작: 각 자리마다 A에서 목표 문자까지 위/아래 중 짧은 쪽
        int answer = 0;
        for (int i = 0; i < name.length(); i++) {
            int up = name.charAt(i) - 'A';
            answer += Math.min(up, 26 - up);
        }

        // 2. 좌우 이동: 기본은 오른쪽으로 끝까지 가는 n-1회.
        //    연속된 'A' 구간을 만나면 되돌아가거나 왼쪽으로 먼저 돌아
        //    그 구간을 건너뛰는 편이 짧아질 수 있어 두 방향 모두 계산한다.
        int n = name.length();
        int move = n - 1;
        for (int i = 0; i < n; i++) {
            int nxt = i + 1;
            while (nxt < n && name.charAt(nxt) == 'A') {
                nxt++;
            }
            move = Math.min(move, i * 2 + n - nxt);
            move = Math.min(move, (n - nxt) * 2 + i);
        }
        return answer + move;
    }
}
```

## 학습 노트

- 막혔던 점: 이 실행은 자동 풀이로, 사용자가 18시까지 풀지 않아 대신 풀었다. 풀이 자체에서 막힌 지점은 없었다. 다만 좌우 이동에서 "오른쪽으로만 가는 것이 최선"이라는 직관을 버리고 `A` 구간 우회를 따로 계산해야 한다는 점이 이 문제의 함정이다.
- 핵심 포인트: 상하 조작과 좌우 이동을 분리하고, 좌우 이동은 `A` 연속 구간을 건너뛰는 두 가지 우회 경로와 기본 경로 중 최솟값을 택한다.
- 개선: 처음 떠오르는 오른쪽 일방향 이동(`n - 1`회)에서, `A` 구간마다 되돌아가기·먼저 돌아가기 두 후보를 비교하는 방식으로 개선했다. 길이가 2~3인 모든 `A/B/Z/J` 조합에 대해 너비 우선 탐색 결과와 대조해 풀이를 검증했다.

## 성능 측정

로컬 실측 결과이다. 이름 길이는 최대 20이므로, `n = 100,000`짜리 입력은 존재하지 않는다. 대신 최대 길이 20짜리 이름으로 100,000회 반복 실행해 측정했다.

- 예제 케이스 실행시간 (Python): "JEROEN" 약 16μs, "JAN" 약 6μs, "JAZ" 약 4μs
- 20자 이름 100,000회 반복 (Python): 총 0.885초, 호출당 약 8.85μs, 결과 144
- 20자 이름 100,000회 반복 (Java): 총 51.7ms, 호출당 약 0.52μs, 결과 144
- 시간 복잡도: O(n²) — 각 위치마다 뒤의 `A` 구간을 스캔하므로 최악의 경우 제곱 시간이 걸리지만, n ≤ 20이라 무시할 수 있는 수준이다. `A` 구간 스캔을 한 번의 순회로 합치면 O(n)까지 줄일 수 있다.
- 공간 복잡도: O(1) — 입력 외에 추가 배열을 사용하지 않는다.

## 요약

상하 조작은 자리마다 원형 거리의 최솟값을 더하고, 좌우 이동은 `A` 연속 구간을 우회하는 경로까지 비교해 최솟값을 택한다. 두 부분을 더하면 조이스틱 조작 횟수의 최솟값이 된다.
