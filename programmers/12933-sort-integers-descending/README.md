# 정수 내림차순으로 배치하기

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12933
- 레벨: Lv.1
- 카테고리: 연습문제

## 문제 핵심 요약

자연수 `n`의 각 자릿수를 큰 것부터 작은 순으로 정렬해 새로운 정수를 반환한다.

- 제한사항: `n`은 1 이상 8,000,000,000 이하의 자연수
- 입출력 예: `118372 → 873211`

## 문제 분석 및 핵심 로직

숫자의 자릿수를 다루려면 숫자를 그대로 두는 것보다 문자열로 바꾸는 편이 낫다. `118372`를 문자열 `"118372"`로 바꾸면 각 자릿수가 문자 하나가 되고, 문자끼리는 사전 순으로 비교할 수 있다. 문자 `'0'`부터 `'9'`까지는 코드값이 숫자 크기 순서와 같으므로, 문자를 정렬하면 곧 숫자 자릿수를 정렬하는 것과 같다.

내림차순으로 정렬한 뒤 다시 이어 붙이면 `873211`이 된다. 이어 붙인 결과를 `int`로 되돌리면 답이다. `n`이 `100`이면 정렬 결과는 `"100"` 그대로이고, `int("100")`은 `100`이므로 앞자리 0이 사라지는 문제는 생기지 않는다. 내림차순 정렬에서는 0이 맨 뒤로 가기 때문이다.

주의할 점은 `n`의 범위이다. 8,000,000,000은 32비트 정수 범위(최대 약 21억)를 넘으므로, Java에서는 파라미터와 반환값을 `int`가 아니라 `long`으로 받아야 한다. Python은 정수 크기에 제한이 없어 신경 쓸 필요가 없다.

## 개념별 심층 설명

### 초심자 방식: 자릿수를 직접 비교하며 자리 바꾸기

자릿수를 하나씩 꺼내어 배열에 담고, 두 개씩 비교해 큰 것을 앞으로 보내는 식으로 직접 정렬할 수 있다. 예를 들어 `[1, 1, 8, 3, 7, 2]`에서 이웃한 두 수를 비교해 순서가 틀렸으면 바꾸는 일을 반복하면 결국 `[8, 7, 3, 2, 1, 1]`이 된다. 동작 원리는 이해하기 쉽지만, 자릿수가 `d`개일 때 비교 횟수가 `d`의 제곱에 비례해 늘어나고 코드도 길어진다.

### 개선 방식: 내장 정렬에 맡기기

자릿수를 문자열로 바꾼 뒤 언어의 내장 정렬(`sorted`, `Arrays.sort`)에 맡기면 정렬 로직을 직접 짤 필요가 없다. 정렬 알고리즘은 이미 검증된 효율적인 구현이며, 자릿수 비교 횟수는 `d log d` 수준이다. 이 문제의 자릿수는 최대 10개라 두 방식의 속도 차이는 실용적으로 의미가 없지만, 코드가 짧아지고 실수할 여지가 줄어든다는 점이 크다.

정렬할 대상이 문자라는 점도 짚고 넘어갈 만하다. 문자 `'8'`과 `'3'`을 비교하면 코드값 56과 51을 비교하게 되는데, `'0'`부터 `'9'`까지의 코드값은 숫자 순서와 일치하므로 문자 정렬 결과가 곧 숫자 자릿수 정렬 결과와 같다. 이 성질 덕분에 문자를 숫자로 되돌리는 변환 없이 정렬만으로 답을 만들 수 있다.

### 자릿수가 0부터 9까지만 있다는 점을 활용한 방식

자릿수의 종류가 0부터 9까지 열 가지뿐이므로, 각 숫자가 몇 번 등장하는지 세는 것만으로 정렬할 수도 있다. `118372`에서는 1이 두 번, 2·3·7·8이 한 번씩 등장한다. 9부터 0까지 등장 횟수만큼 숫자를 이어 붙이면 `873211`이 된다. 비교 자체가 없어 시간복잡도는 자릿수에 비례한다. 다만 Python에서는 문자열을 한 글자씩 세는 반복이 Python 레벨에서 돌아, 내장 정렬(C로 구현됨)보다 실측상 느렸다. 무작위 100,000개 케이스 기준으로 정렬 방식 0.1443초, 개수 세기 방식 0.3538초였다. 개념적으로는 우아하지만 이 문제에서는 내장 정렬이 더 실용적이다.

## 최종 솔루션 코드

### Python

```python
def solution(n):
    # 1. n을 문자열로 바꿔 각 자릿수를 문자로 만든다.
    # 2. 자릿수 문자를 내림차순으로 정렬한다.
    # 3. 이어 붙인 뒤 정수로 되돌린다.
    return int("".join(sorted(str(n), reverse=True)))
```

### Java

```java
import java.util.Arrays;

class Solution {
    public long solution(long n) {
        // 1. n을 문자열로 바꿔 각 자릿수를 문자로 만든다.
        // 2. 자릿수 문자를 오름차순으로 정렬한다.
        // 3. 뒤에서부터 이어 붙이면 내림차순이 된다.
        // n은 최대 8,000,000,000이므로 long으로 받는다.
        char[] digits = String.valueOf(n).toCharArray();
        Arrays.sort(digits);
        StringBuilder sb = new StringBuilder(digits.length);
        for (int i = digits.length - 1; i >= 0; i--) {
            sb.append(digits[i]);
        }
        return Long.parseLong(sb.toString());
    }
}
```

`str(n)`과 `String.valueOf(n)`은 숫자를 자릿수 문자열로 바꾼다. Python의 `sorted(..., reverse=True)`는 내림차순 정렬을 바로 해 주지만, Java의 `Arrays.sort`는 문자 배열을 오름차순으로만 정렬하므로 뒤에서부터 이어 붙여 내림차순을 만든다. `Long.parseLong`은 이어 붙인 문자열을 `long` 값으로 되돌린다. `n`이 32비트 범위를 넘으므로 Java에서는 `long`을 써야 한다.

## 성능 측정

로컬 실측 결과이다. 제한은 `n ≤ 8,000,000,000`이지만 스케일 차이를 보기 위해 무작위 100,000개 케이스(1 이상 8,000,000,000 이하)로 측정했다.

| 케이스 | Python | Java |
| --- | --- | --- |
| 예제 `118372 → 873211` | 통과 | 통과 |
| 무작위 100,000개 (합계) | 0.1443 s | 0.095 s |
| 무작위 100,000개 (1회당) | 1.443 µs | 0.95 µs |
| 예제 100,000회 (1회당) | 0.916 µs | 0.456 µs |
| 개수 세기 방식 100,000개 (비교용) | 0.3538 s | — |

- Python 피크 메모리: 0.2 KiB (tracemalloc 실측, 무작위 100,000개 케이스 실행)
- Java 메모리: 힙 증가분 약 1.7 MiB (무작위 100,000개 케이스 실행 중, 임시 문자열·배열 할당)
- 시간복잡도: O(d log d) — d는 자릿수 (최대 10, `n ≤ 8,000,000,000`)
- 공간복잡도: O(d) — 자릿수 문자열·배열이 자릿수만큼 필요

`n`이 8,000,000,000 이하이므로 자릿수는 최대 10개이고, 정렬 비용은 자릿수에 달려 있다. 입력 범위가 커져 자릿수가 늘어나도 비용은 자릿수의 로그 수준으로만 늘어난다.

## 요약

- 핵심 아이디어: 숫자를 문자열로 바꿔 자릿수를 내림차순으로 정렬한 뒤 다시 정수로 되돌린다.
- 문자 `'0'`~`'9'`의 코드값은 숫자 순서와 같아, 문자 정렬이 곧 자릿수 정렬이 된다.
- 자릿수 종류가 열 가지뿐이라 개수 세기로 정렬할 수도 있지만, Python 실측에서는 내장 정렬이 더 빨랐다.
- Java에서는 `n`이 32비트 범위를 넘으므로 파라미터와 반환값을 `long`으로 받아야 한다.
- 시간복잡도는 O(d log d), 공간복잡도는 O(d)이다. (d는 자릿수)
