# 정수 제곱근 판별

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12934
- 레벨: Lv.1
- 카테고리: 연습문제

## 문제 핵심 요약

양의 정수 `n`이 어떤 양의 정수 `x`의 제곱이면 `(x+1)`의 제곱을, 제곱수가 아니면 `-1`을 반환한다.

- 제한사항: `n`은 1 이상 50,000,000,000,000 이하의 양의 정수
- 입출력 예: `121 → 144`, `3 → -1`

## 문제 분석 및 핵심 로직

이 문제의 본질은 "n의 제곱근이 정수인가"를 묻는 것이다. `121`은 `11`의 제곱이므로 답은 `(11+1)`의 제곱인 `144`이고, `3`은 어떤 정수의 제곱도 아니므로 `-1`이다.

제곱근을 구하는 방법은 여러 가지이지만, 핵심은 정확성이다. `n`의 최대값은 5×10¹³으로, 제곱근은 약 707만까지 커진다. 이 범위에서는 부동소수점으로 제곱근을 구하면 반올림 때문에 결과가 1만큼 어긋날 수 있다. 예를 들어 완전제곱수의 제곱근이 `7071067`이어야 하는데 부동소수점 연산 결과가 `7071066.9999999`로 나오면, 정수 변환 시 `7071066`이 되어 잘못된 답을 낸다. 그래서 부동소수점 결과를 그대로 믿지 않고, 구한 후보 `x`에 대해 `x * x == n`을 곱셈으로 직접 확인하는 과정이 반드시 필요하다.

Python에서는 `math.isqrt`를 쓰면 이 걱정을 원천적으로 피할 수 있다. `isqrt`는 부동소수점을 거치지 않고 정확한 정수 제곱근(내림값)을 반환한다. `isqrt(n)`의 제곱이 `n`과 같으면 `n`은 완전제곱수이고, 다르면 완전제곱수가 아니다. Java에는 정수 제곱근 내장 함수가 없으므로 `Math.sqrt`로 근사값을 구한 뒤, 후보 `x`를 `±1` 범위에서 보정해 `x * x == n`을 만족하는 정확한 값을 찾는다. `Math.sqrt`의 오차는 아무리 커도 1을 넘지 않으므로, `while` 루프로 한두 번만 조정하면 정확한 제곱근에 도달한다.

주의할 점은 `n`의 범위이다. 50,000,000,000,000은 32비트 정수 범위(최대 약 21억)를 한참 넘으므로, Java에서는 파라미터와 반환값을 `int`가 아니라 `long`으로 받아야 한다. Python은 정수 크기에 제한이 없어 신경 쓸 필요가 없다.

## 개념별 심층 설명

### 초심자 방식: 1부터 차례로 제곱해 보기

`1`의 제곱, `2`의 제곱, `3`의 제곱…을 차례로 계산해 `n`과 같은 값이 나오는지 확인하는 방법이다. 동작 원리는 가장 직관적이지만, `n`이 5×10¹³이면 제곱근이 약 707만까지 커지므로 최악의 경우 707만 번의 곱셈을 해야 한다. `n`이 완전제곱수가 아닐 때는 끝까지 다 확인해야 하므로 항상 최악의 경우에 가깝다. 입력이 하나뿐인 문제라 707만 번도 컴퓨터에게는 큰 부담은 아니지만, 제곱근을 구한다는 목적에 비해 너무 많은 일을 한다.

### 개선 방식 1: 이분탐색으로 제곱근 찾기

제곱근이 될 수 있는 범위는 `1`부터 `n`까지이고, `x`가 커질수록 `x * x`도 커진다는 단조성을 이용하면 이분탐색을 쓸 수 있다. 범위를 절반씩 줄여 나가면 약 46번의 비교만으로 제곱근을 찾을 수 있다. `1`부터 차례로 확인하는 방식보다 훨씬 빠르고, 부동소수점을 쓰지 않으므로 오차 걱정도 없다. 다만 범위 경계를 다루는 코드가 필요하고, 이 문제는 사실 제곱근을 직접 계산하는 방법이 있어 이분탐색까지 갈 필요가 없다.

### 개선 방식 2: 정수 제곱근을 직접 계산하기

Python의 `math.isqrt`는 정수 제곱근을 정확한 정수 연산으로 구한다. 내부적으로 뉴턴법 같은 정수 반복 계산을 C로 구현해 두었으므로, 호출 한 번으로 정확한 `floor(√n)`을 얻는다. 부동소수점을 전혀 쓰지 않으니 오차 보정이 필요 없고, 코드도 `isqrt(n)` 한 줄이다. Java에는 동등한 내장 함수가 없어 `Math.sqrt`로 근사값을 구한 뒤 `±1` 보정을 붙인다. 근사값의 오차가 1을 넘지 않는다는 성질 덕분에 보정은 한두 번의 곱셈 비교로 끝난다.

### 부동소수점 제곱근의 오차와 보정

`double`은 53비트 가수(약 15~16자리 십진수)까지만 정확히 표현한다. `n` 자체는 5×10¹³(약 14자리)까지 정확히 표현되지만, 제곱근 연산은 반올림을 거치므로 결과가 정수여야 할 지점에서 `7071066.9999999`처럼 나올 수 있다. 정수 변환은 소수점 아래를 버리므로 `7071066`이 되어, `7071066 * 7071066`은 `n`보다 작아진다. 이를 막으려면 근사값을 그대로 쓰지 않고 `(x+1) * (x+1) <= n`이면 `x`를 올리고, `x * x > n`이면 `x`를 내리는 식으로 조정해 정확한 내림 제곱근을 만든 뒤, `x * x == n`으로 판정한다. 이 보정 루프는 최대 한두 번만 돌고, 곱셈 결과도 `long` 범위(약 9.2×10¹⁸)를 넘지 않으므로 오버플로 걱정도 없다.

## 최종 솔루션 코드

### Python

```python
import math

def solution(n):
    # 1. n의 정수 제곱근 x를 구한다. (isqrt는 부동소수점 오차 없이 정확한 정수 제곱근을 반환한다)
    # 2. x의 제곱이 n과 같으면 완전제곱수이므로 (x+1)의 제곱을 반환한다.
    # 3. 다르면 -1을 반환한다.
    x = math.isqrt(n)
    return (x + 1) ** 2 if x * x == n else -1
```

### Java

```java
class Solution {
    public long solution(long n) {
        // 1. 부동소수점으로 근사 제곱근을 구한다.
        // 2. 근사값이 실제 제곱근보다 크거나 작을 수 있으므로 ±1 범위로 보정한다.
        // 3. 보정된 x의 제곱이 n과 같으면 (x+1)의 제곱을, 다르면 -1을 반환한다.
        // n은 최대 50,000,000,000,000이므로 long으로 받는다.
        long x = (long) Math.sqrt(n);
        while ((x + 1) * (x + 1) <= n) x++;
        while (x * x > n) x--;
        if (x * x == n) {
            return (x + 1) * (x + 1);
        }
        return -1;
    }
}
```

Python의 `math.isqrt(n)`은 정확한 정수 제곱근을 반환하므로, `x * x == n` 비교 한 번으로 완전제곱수 여부를 판정할 수 있다. Java는 `Math.sqrt(n)`이 `double` 근사값이라 `(long)` 변환 시 1만큼 어긋날 수 있으므로, 두 개의 `while` 루프로 `x`를 정확한 내림 제곱근으로 보정한 뒤 같은 판정을 한다. 두 방식 모두 판정이 끝나면 `(x + 1)`의 제곱을 반환하고, 완전제곱수가 아니면 `-1`을 반환한다.

## 성능 측정

로컬 실측 결과이다. 제한은 `n ≤ 50,000,000,000,000`이고, 입력이 하나의 수라 스케일 차이를 보기 위해 무작위 100,000개 케이스(1 이상 50,000,000,000,000 이하)로 측정했다. 정확성은 이분탐색으로 짠 독립 검증 코드와 1,200개 케이스(무작위 1,000개 + 완전제곱수 200개)를 대조해 확인했다.

| 케이스 | Python | Java |
| --- | --- | --- |
| 예제 `121 → 144`, `3 → -1` | 통과 | 통과 |
| 엣지 `1 → 4`, `4 → 9`, `2 → -1` | 통과 | 통과 |
| 최대 범위 `49999988518489 → 50000002660624` (7071067² → 7071068²) | 통과 | 통과 |
| 무작위 100,000개 (합계) | 0.0228 s | 0.0028 s |
| 무작위 100,000개 (1회당) | 0.228 µs | 0.028 µs |
| 예제 100,000회 (1회당) | 0.204 µs | 0.074 µs |

- Python 피크 메모리: 0.1 KiB (tracemalloc 실측, 무작위 100,000개 케이스 실행)
- Java 메모리: 힙 증가분 0.0 KiB (무작위 100,000개 케이스 실행 중, 추가 할당 없음)
- 시간복잡도: O(1) — 정수 제곱근 계산 한 번과 곱셈 몇 번으로 끝나며, 입력 크기에 따라 반복이 늘어나지 않는다 (비교용 이분탐색은 O(log n))
- 공간복잡도: O(1) — 변수 몇 개만 사용한다

입력은 하나의 수뿐이라 계산량은 `n`의 자릿수에 사실상 무관하다. `isqrt`와 `Math.sqrt` 모두 상수 시간에 가까운 연산이고, Java의 보정 루프도 한두 번이면 끝나므로 전체 실행 시간은 마이크로초 단위이다.

## 요약

- 핵심 아이디어: `n`의 정수 제곱근 `x`를 구해 `x * x == n`인지 확인한다. 맞으면 `(x+1)`의 제곱, 틀리면 `-1`을 반환한다.
- Python은 `math.isqrt`로 부동소수점을 거치지 않고 정확한 정수 제곱근을 구한다.
- Java는 `Math.sqrt` 근사값에 `±1` 보정을 붙여 정확한 제곱근을 만든 뒤 곱셈으로 검증한다.
- 부동소수점 제곱근은 반올림으로 1만큼 어긋날 수 있어, 검증 없는 사용은 완전제곱수 경계에서 틀릴 수 있다.
- `n`이 32비트 범위를 넘으므로 Java에서는 `long`을 써야 한다.
- 시간복잡도는 O(1), 공간복잡도는 O(1)이다.
