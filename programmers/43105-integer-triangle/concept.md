# 동적 프로그래밍 — 아래에서 위로 채우기

이 문제는 "작은 부분 문제의 답을 이용해 큰 문제의 답을 만든다"는 동적 프로그래밍의 기본 형태를 보여준다. 핵심은 부분 문제의 정의와, 그 답들을 어떤 순서로 채울 것인가이다.

## 부분 문제와 점화식

동적 프로그래밍은 문제를 겹치는 부분 문제들로 나누고, 각 부분 문제의 답을 한 번만 계산해 저장해 두는 방법이다. 부분 문제를 정의할 때는 "이 답만 알면 윗 단계의 답을 구할 수 있는가"를 기준으로 삼는다.

예를 들어 피보나치 수열에서는 `f(n) = f(n-1) + f(n-2)`라는 점화식이 있고, `f(0)`과 `f(1)`이 자명하다. n이 커지면 같은 값을 반복 계산하게 되므로, 작은 n부터 차례로 채워 두면 각 값을 한 번씩만 계산한다.

```python
def fib(n):
    dp = [0] * (n + 1)
    dp[0], dp[1] = 0, 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
```

이 문제의 부분 문제는 "어떤 칸에서 바닥까지의 최대합"이다. 바닥에 가까운 행부터 채우면, 위 행을 계산할 때 필요한 아래 행의 값은 이미 확정돼 있다. 의존 관계가 한 방향으로만 흐르므로, 한 방향으로 한 번씩 훑는 것만으로 모든 부분 문제의 답이 완성된다.

## 메모이제이션(Top-down)과 타뷸레이션(Bottom-up)

동적 프로그래밍에는 두 가지 구현 방향이 있다.

- 메모이제이션은 재귀 함수로 큰 문제에서 시작해 필요한 부분 문제만 계산하고, 결과를 딕셔너리나 배열에 저장해 재사용한다. 필요한 부분만 계산한다는 장점이 있지만, 재귀 호출 깊이가 커질 수 있고 호출 오버헤드가 있다.
- 타뷸레이션은 작은 부분 문제부터 반복문으로 차례로 채워 나간다. 의존 관계의 순서를 미리 파악해야 하지만, 재귀가 없어 스택 부담이 없고 코드가 단순해진다.

아래는 같은 "1, 2, 3을 더해 n을 만드는 방법의 수"를 두 방식으로 푼 예다.

```python
# 메모이제이션 (Top-down)
def count_ways_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n == 0:
        return 1
    if n < 0:
        return 0
    if n in memo:
        return memo[n]
    memo[n] = (count_ways_memo(n - 1, memo)
               + count_ways_memo(n - 2, memo)
               + count_ways_memo(n - 3, memo))
    return memo[n]

# 타뷸레이션 (Bottom-up)
def count_ways_tab(n):
    dp = [0] * (n + 1)
    dp[0] = 1
    for i in range(1, n + 1):
        dp[i] = sum(dp[i - k] for k in (1, 2, 3) if i - k >= 0)
    return dp[n]
```

이 문제에서는 타뷸레이션이 자연스럽다. 아래 행이 전부 확정된 뒤에야 위 행을 계산할 수 있다는 순서가 명확하고, 모든 행을 빠짐없이 채워야 하므로 메모이제이션의 "필요한 부분만"이라는 장점도 없다.

## 1차원 배열로 공간 줄이기

타뷸레이션에서는 현재 단계의 계산에 바로 이전 단계의 값만 필요한 경우가 많다. 그럴 때는 전체 테이블을 유지할 필요가 없고, 필요한 만큼의 배열 하나로 충분하다.

피보나치 수열이 대표적인 예다. `f(n)`을 구하는 데는 `f(n-1)`과 `f(n-2)` 두 값만 필요하므로, 배열 대신 변수 두 개로 충분하다.

```python
def fib_optimized(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

이 문제에서도 같은 원리가 적용된다. 각 행을 계산할 때 바로 아래 행의 값만 필요하므로, 2차원 테이블 대신 마지막 행 길이만큼의 1차원 배열 하나로 충분하다. 다만 덮어쓰기 순서는 조심해야 한다. 왼쪽부터 채우면 계산에 필요한 오른쪽 값(아래 행의 j+1번째)이 아직 덮어쓰기 전 상태로 남아 있어 안전하다. 반대로 오른쪽부터 채우면 이미 갱신된 값을 읽게 되어 틀린 답이 나온다. 덮어쓰기를 할 때는 "읽어야 할 값이 아직 남아 있는가"를 항상 확인한다.
