## 문제 분석 및 핵심 로직

디스크는 한 번에 하나의 작업만 처리한다. 각 작업은 요청 시각과 소요 시간을 가지고, 모든 작업의 반환 시간(요청 시각부터 종료 시각까지)의 평균의 정수 부분을 구하는 문제다.

디스크가 비어 있고 대기 중인 작업이 있을 때, 컨트롤러는 소요 시간이 가장 짧은 작업을 먼저 꺼낸다. 동점인 경우 요청 시각이 빠른 작업, 그다음은 작업 번호가 작은 작업이 우선이다. 따라서 매번 "지금 대기 중인 작업 중 가장 짧은 것"을 골라야 하고, 이 선택이 반복된다.

핵심은 두 가지다.

1. **대기 중인 작업을 소요 시간 순으로 꺼내는 구조가 필요하다.** 매번 전체를 스캔하면 느리다. 최소 힙을 쓰면 가장 짧은 작업을 O(log n)에 꺼낼 수 있다.
2. **시간을 작업 단위로 전진시키는 시뮬레이션이다.** 디스크가 비어 있는데 대기 큐도 비어 있으면, 다음 작업이 요청되는 시각까지 시간을 점프시켜야 한다. 반대로 디스크가 일하는 동안 들어온 요청은 모두 대기 큐에 쌓아 둔다.

### 초심자 방식 vs 개선 방식

처음 떠올리기 쉬운 방식은 요청 시각 순으로 작업을 정렬한 뒤, 들어온 순서대로(FIFO) 처리하는 것이다. 하지만 이 문제는 소요 시간이 짧은 작업을 먼저 처리하도록 명시하고 있다. 예제에서 1ms에 들어온 9ms짜리 작업이 3ms에 들어온 5ms짜리 작업보다 늦게 처리되는 이유가 여기에 있다. FIFO로 풀면 답이 달라진다.

또 하나 흔한 실수는 "현재 시각에 요청된 작업만" 대기 큐에 넣는 것이다. 디스크가 바쁠 때 들어온 요청은 대기 큐에 쌓이고, 디스크가 비는 순간 그때까지 들어온 모든 요청이 후보가 된다. 그래서 작업 하나를 마칠 때마다 "현재 시각 이하에 요청된 작업"을 전부 힙에 넣는 과정이 필요하다.

### 동작 원리

1. 작업을 요청 시각 순으로 정렬한다. 작업 번호는 원래 인덱스다.
2. 최소 힙을 준비한다. 힙의 키는 (소요 시간, 요청 시각, 작업 번호) 순이다. 파이썬 튜플 비교와 자바 Comparator가 이 순서를 그대로 구현한다.
3. 힙이 비어 있으면 다음 작업의 요청 시각으로 시간을 점프한다. 디스크가 노는 시간을 건너뛰는 과정이다.
4. 현재 시각까지 요청된 작업을 모두 힙에 넣는다.
5. 힙에서 가장 우선순위가 높은 작업을 꺼내 실행한다. 종료 시각을 현재 시각에 소요 시간을 더해 구하고, 반환 시간(종료 시각 − 요청 시각)을 누적한다.
6. 모든 작업이 끝나면 누적 반환 시간을 작업 수로 나눈 정수 부분을 반환한다.

작업이 최대 500개라서 복잡도를 따질 일은 아니지만, 이 방식은 정렬 O(n log n)에 힙 삽입·추출이 작업마다 O(log n)이므로 전체 O(n log n)이다.

## 최종 솔루션 코드

### Python

```python
import heapq


def solution(jobs):
    # 1. 요청 시각 순으로 정렬 (작업 번호는 원래 인덱스)
    indexed = [(s, l, i) for i, (s, l) in enumerate(jobs)]
    indexed.sort()
    n = len(jobs)

    heap = []  # 2. 대기 큐: (소요시간, 요청시각, 작업번호) 순 최소 힙
    idx = 0
    time = 0
    total = 0

    # 3. 모든 작업이 끝날 때까지 시뮬레이션
    while idx < n or heap:
        # 대기 큐가 비어 있으면 다음 작업 요청 시각으로 점프
        if not heap:
            time = max(time, indexed[idx][0])
        # 현재 시각까지 요청된 작업을 모두 대기 큐에 삽입
        while idx < n and indexed[idx][0] <= time:
            s, l, i = indexed[idx]
            heapq.heappush(heap, (l, s, i))
            idx += 1
        # 우선순위 가장 높은 작업(소요시간 최단) 실행
        l, s, i = heapq.heappop(heap)
        time += l
        total += time - s  # 반환 시간 = 종료 시각 - 요청 시각

    return total // n
```

### Java

```java
import java.util.*;

class Solution {
    public int solution(int[][] jobs) {
        // 1. 요청 시각 순으로 정렬 (작업 번호는 원래 인덱스)
        int n = jobs.length;
        int[][] indexed = new int[n][3];
        for (int i = 0; i < n; i++) {
            indexed[i][0] = jobs[i][0]; // 요청 시각
            indexed[i][1] = jobs[i][1]; // 소요 시간
            indexed[i][2] = i;          // 작업 번호
        }
        Arrays.sort(indexed, Comparator.comparingInt(a -> a[0]));

        // 2. 대기 큐: (소요시간, 요청시각, 작업번호) 순 최소 힙
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> {
            if (a[1] != b[1]) return a[1] - b[1];
            if (a[0] != b[0]) return a[0] - b[0];
            return a[2] - b[2];
        });

        int idx = 0;
        int time = 0;
        int total = 0;

        // 3. 모든 작업이 끝날 때까지 시뮬레이션
        while (idx < n || !heap.isEmpty()) {
            // 대기 큐가 비어 있으면 다음 작업 요청 시각으로 점프
            if (heap.isEmpty()) {
                time = Math.max(time, indexed[idx][0]);
            }
            // 현재 시각까지 요청된 작업을 모두 대기 큐에 삽입
            while (idx < n && indexed[idx][0] <= time) {
                heap.offer(indexed[idx]);
                idx++;
            }
            // 우선순위 가장 높은 작업(소요시간 최단) 실행
            int[] job = heap.poll();
            time += job[1];
            total += time - job[0]; // 반환 시간 = 종료 시각 - 요청 시각
        }

        return total / n;
    }
}
```

## 학습 노트

- 막혔던 점: 18:00 자동 풀이로 진행되어 별도의 막힘 없이 풀이했다. 주의할 점은 FIFO로 처리하면 틀린다는 것으로, 소요 시간이 짧은 작업을 먼저 꺼내는 규칙을 힙에 그대로 옮기는 것이 핵심이었다.
- 핵심 포인트: 대기 중인 작업 중 소요 시간이 가장 짧은 것을 고르는 SJF 스케줄링이며, 최소 힙에 (소요 시간, 요청 시각, 작업 번호)를 키로 넣으면 우선순위가 그대로 구현된다.
- 개선: 시간을 1단위씩 전진시키지 않고 다음 요청 시각으로 점프시켜 빈 시간을 건너뛰었고, 작업마다 전체를 스캔하지 않고 힙으로 O(log n)에 선택했다.

## 요약

- 디스크가 빌 때마다 대기 중인 작업 중 소요 시간이 가장 짧은 것을 고르는 SJF 스케줄링 문제다.
- 최소 힙에 (소요 시간, 요청 시각, 작업 번호)를 키로 넣어 우선순위를 그대로 구현한다.
- 디스크가 비어 있고 대기 큐도 비어 있으면 다음 요청 시각으로 시간을 점프시키고, 작업 하나를 마칠 때마다 그 시각까지 들어온 요청을 모두 힙에 넣는다.
- FIFO로 처리하면 틀리므로, "지금 대기 중인 것 중 가장 짧은 것"이라는 선택 규칙을 정확히 구현하는 것이 핵심이다.
