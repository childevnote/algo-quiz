# 개념 정리: 디스크 컨트롤러

## 1. 최소 힙 (Min-Heap)

힙은 가장 작거나(최소 힙) 가장 큰(최대 힙) 원소를 항상 루트에 두는 이진 트리 기반 자료구조다. 삽입과 삭제가 모두 O(log n)이며, "지금까지 본 것 중 가장 작은 것"을 반복해서 꺼내야 할 때 쓴다.

- 최소 힙에서는 부모가 자식보다 항상 작거나 같다. 루트를 꺼내면 다음으로 작은 원소가 루트로 올라온다.
- 정렬된 리스트와 달리 힙은 전체를 정렬하지 않는다. 가장 작은 원소만 필요할 때 정렬보다 저렴하다. 전체 정렬은 O(n log n)이지만 힙에서 원소 하나를 꺼내는 것은 O(log n)이다.
- 파이썬에서는 `heapq` 모듈이 리스트를 최소 힙으로 다룬다. `heapq.heappush(heap, x)`로 삽입하고 `heapq.heappop(heap)`으로 가장 작은 원소를 꺼낸다. 튜플을 넣으면 첫 번째 원소부터 순서대로 비교한다.
- 자바에서는 `PriorityQueue`가 최소 힙이다. `offer`로 삽입하고 `poll`로 가장 작은 원소를 꺼낸다. 비교 기준은 `Comparator`로 지정한다.

```python
import heapq

heap = []
heapq.heappush(heap, (3, "c"))
heapq.heappush(heap, (1, "a"))
heapq.heappush(heap, (2, "b"))
print(heapq.heappop(heap))  # (1, "a") — 가장 작은 원소가 먼저 나온다
print(heapq.heappop(heap))  # (2, "b")
```

```java
import java.util.*;

PriorityQueue<Integer> heap = new PriorityQueue<>();
heap.offer(3);
heap.offer(1);
heap.offer(2);
System.out.println(heap.poll());  // 1
System.out.println(heap.poll());  // 2
```

### 복합 키로 우선순위 정하기

비교 기준이 여러 개일 때는 우선순위가 높은 기준부터 순서대로 비교한다. 예를 들어 (소요 시간, 요청 시각, 번호) 순으로 우선순위를 정한다면, 소요 시간이 다르면 소요 시간만으로 결정하고, 같을 때만 다음 기준을 본다. 파이썬 튜플은 이 비교를 기본으로 수행하고, 자바에서는 Comparator에 조건을 차례로 적는다.

## 2. SJF 스케줄링 (Shortest Job First)

SJF는 대기 중인 작업 중 소요 시간이 가장 짧은 작업을 먼저 실행하는 스케줄링 방식이다. 평균 반환 시간(대기 시간 + 소요 시간)을 줄이는 데 효과적이다.

- 짧은 작업을 먼저 처리하면 짧은 작업의 반환 시간이 크게 줄고, 긴 작업이 조금 늦어지는 손해보다 전체 평균이 개선된다.
- 단점도 있다. 긴 작업이 계속 뒤로 밀리면 기아(starvation)가 발생할 수 있다. 이 문제는 작업 수가 고정되고 모든 작업이 결국 처리되므로 기아를 걱정하지 않아도 된다.
- 선점형 SJF(SRTF)는 실행 중인 작업보다 더 짧은 작업이 들어오면 실행을 중단하고 교체하지만, 이 문제의 디스크는 한 번 시작한 작업을 끝까지 수행하므로 비선점형 SJF다.

## 3. 이벤트 기반 시뮬레이션과 시간 점프

시간이 흐르는 과정을 1단위씩 전진시키는 대신, 의미 있는 사건(작업 요청, 작업 완료)이 일어나는 시점으로만 시간을 점프시키는 방식이다.

- 디스크가 일하고 있는 동안에는 다음 사건이 "작업 완료" 시점이다. 작업 하나가 끝나면 그 시각까지 들어온 요청을 모두 처리 대상에 올린다.
- 디스크가 비어 있는데 대기 중인 작업이 없으면, 다음 요청이 들어오는 시각까지 시간이 비게 된다. 이때는 1씩 전진하지 않고 다음 요청 시각으로 바로 점프한다. 이 점프가 없으면 빈 시간을 한 단위씩 세는 낭비가 생기고, 요청 시각이 큰 경우 루프가 오래 돈다.
- 시뮬레이션의 상태는 보통 (현재 시각, 대기 큐, 아직 도착하지 않은 작업 목록) 세 가지로 유지한다.
